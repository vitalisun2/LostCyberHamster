## Правила работы с репозиторием

### Правила работы с ветками
1. main – стабильная ветка, содержит релизные версии.

2. develop – основная рабочая ветка для разработки новых фич и исправления багов.
Тестировщик проверяет сборки из этой ветки.

3. Для каждой задачи создаётся отдельная ветка:
- feature/#номер_задачи – для новых фич.
- bugfix/#номер_задачи – для исправления багов.

4. Разработчик в ветке задачи выполняет работу, проверяет работоспособность и создаёт Pull Request (PR) в develop.

5. При мёрже PR в develop выполняется squash (объединение всех коммитов ветки задачи в один).

6. После каждого мёржа в develop автоматически создаётся тестовый APK, который отправляется в Telegram-канал для оперативного тестирования.

### Установка хуков
В папке `.githooks` определен набор хуков, помогающих вести разработку, например, чтобы ограничить прямой push в main или автоматически обновить документацию. Для у становки достаточно указать в терминале:

```sh
git config core.hooksPath .githooks
```
