## Правила работы с репозиторием

### Правила работы с ветками
1. main – стабильная ветка, содержит релизные версии.

2. Для каждой задачи создаётся отдельная ветка вида `task/<slug>`.

3. Каждая задача должна выполняться в отдельном git worktree. Это позволяет безопасно вести несколько параллельных потоков работы и запускать несколько агентов без конфликтов по рабочему каталогу.

4. Разработчик или агент работает только внутри своей task-ветки и своего worktree, проверяет результат и пушит именно эту ветку.

5. Независимые задачи можно вести параллельно в нескольких worktree, если они не изменяют один и тот же набор файлов или Unity-ассетов.

6. После завершения и проверки задачи её ветка мержится обратно в `main` последовательно, по одной задаче за раз.

### Установка хуков
В папке `.githooks` определен набор хуков, помогающих вести разработку, например, чтобы ограничить прямой push в main или автоматически обновить документацию. Для у становки достаточно указать в терминале:

```sh
git config core.hooksPath .githooks
```
