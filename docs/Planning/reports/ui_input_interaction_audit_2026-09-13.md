## Доказанная причина

Старый `UiInputCarryoverBlock` ставил глобальный блок на 1000 мс, но снимал его лениво только при приходе следующего события. Поэтому первый `PointerUp`, `Click`, `KeyUp` или submit/cancel на новом экране мог стать событием, которое лишь снимало старый блок и само не доходило до назначения. Одновременно навигация могла начать заменять дерево UI в стеке обработки исходного события, особенно когда подготовка экрана завершалась синхронно из кэша. Это объясняет оба наблюдавшихся эффекта: тап «проваливался» в следующее дерево либо первый настоящий ввод нового экрана пропадал.

Причина подтверждена старым execution path и runtime-пробой: блок оставался активным после своего временного окна до следующего подходящего события. Исправление проверено отдельным UnityTest: переход не начинается внутри текущего dispatch, блок активен на границе события и освобождается сразу после завершения перехода.

## Исправление

- Ввод-инициированная навигация отделена от программной: `RequestScreenFromInput` проходит через одну общую границу события.
- `RunAfterCurrentEventAsync` сначала захватывает `UiInputBlock`, затем делает `Task.Yield`, выполняет переход и гарантированно освобождает блок через `using`.
- Документ UI больше не «потребляет» следующий пользовательский event для ленивого снятия таймера; он блокирует события только пока существует реальный владелец перехода.
- Переходы из результатов уровня и загрузка сцен используют ту же ограниченную временем жизни операции границу.

## Как проверялось

Тест отправляет настоящие pooled pointer down/up/move и wheel events через живую UI Toolkit panel. Для каждой операции он проверяет hit target, click/change, отсутствие синхронной смены дерева внутри исходного dispatch, освобождение `UiInputBlock`, ожидаемый screen/modal route, отсутствие неожиданных сцен и доставку первого harmless input на новом дереве с первой попытки.

Рекламные, IAP, аккаунтные, cloud-choice и сценосменяющие кнопки не запускают реальные внешние последствия: тест доказывает их hit target и прохождение pointer pair, после чего безопасно останавливает событие. Их серверный/магазинный результат остаётся областью отдельного sandbox/device-теста.
