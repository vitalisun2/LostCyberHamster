## Android-приёмка

Скопировать APK на телефон и установить его. Использовать отдельный тестовый профиль: очистка данных для чистого запуска удаляет локальный прогресс. Для обычного обновления существующий профиль сохранить. Зафиксировать build ID, модель телефона, Android, исходный баланс и время каждого сценария. Для принудительного завершения использовать Android → Настройки → Приложения → LostCyberHamster → Остановить. Диагностику читать штатным способом.

1. Чистая установка; до первого старта включить авиарежим. Открыть меню, обучение, доступный уровень, настройки, персонажа. Зафиксировать отсутствие сетевой блокировки.
2. Завершить уровень, получить награду, обменять ресурсы. Принудительно завершить процесс; повторный запуск должен восстановить баланс, награды и прогресс.
3. Подключить Wi-Fi без доступа в интернет. Повторить запуск и забег; меню остаётся доступным, сетевые функции показывают ожидание.
4. Во время забега отключить сеть, закончить уровень, перейти в меню. Затем вернуть сеть: тот же аккаунт и очереди восстанавливаются без перезапуска.
5. Проверить известный аккаунт после истечения сессии. Отдельно закрыть браузер входа через Back; дождаться завершения ожидания и повторить вход.
6. Изменить обе версии профиля на двух устройствах. Проверить обе карточки, ресурсы, прогресс, уровень героя и дату игрового сохранения. Выбрать «Позже», перезапустить, продолжить игру и открыть выбор через настройки.
7. Оборвать ответ после cloud write; сделать новое локальное изменение. После связи подтверждается отправленный снимок, новое изменение остаётся ожидающим.
8. Реклама: double tap, отказ SDK, потеря сети после Show, возврат из фона, поздний и повторный callback. Проверить одну награду, доступность остальных действий и revive исходного runId.
9. Уйти из магазина во время рекламы. Подтверждённая награда должна пережить закрытый экран и перезапуск после записи receipt.
10. Сохранить несколько улучшений недельного результата офлайн. После связи проверить FIFO и 50 XP за каждое доказанное улучшение. При смене недели старый результат завершается в исходном периоде.
11. На первом полностью офлайн-запуске получить результат. После запуска онлайн он остаётся `LocalOnly` и сохраняется между запусками.
12. Проверить полночь, несколько пропущенных дней, часовую зону и возврат к использованной дате. Проверить защищённые задания и отдельное право на общую награду.
13. На тестовых данных проверить старый формат, повреждённый primary, валидный backup и более новую схему. Рабочую копию сохранить до сценария.
14. Проверить длительную автономную работу: очереди, ограничение логов, повторы и отсутствие сетевых блокировок.

Сценарии 1–5, 8–12 и 14 доступны обычной ручной проверке. Для 6 нужны два тестовых устройства или две независимые установки с одним аккаунтом. Сценарии 7 и 13 требуют контролируемого сбоя ответа/хранилища и резервной копии тестового профиля; одного авиарежима для доказательства lost ACK недостаточно.

Перед выпуском открыть Unity Dashboard → Gaming Services → Leaderboards отдельно для `development` и `production`. Сверить все 12 ID из `ugs/leaderboards`: `keepBest`, descending, недельный reset `0 0 * * 1`, понедельник 00:00 UTC. Для результатов проверки записывать: сценарий, PASS/FAIL, фактический баланс/награду после перезапуска и время для поиска в логах.

## Границы надёжности

- Недельная клиентская очередь допускает потерю бонусных XP, если принятие операции уже нельзя доказать после lost ACK или смены недели.
- Рекламный SDK не восстанавливает доказательство просмотра после гибели процесса до записи completion. Одно сохранённое намерение награду не даёт.
- Primary/backup работает в пределах гарантий текущего PlayerPrefs-хранилища. Постоянная ошибка устройства требует успешной повторной записи.
- Локальное время защищает от повторного использования даты. Ранее не посещённая дата, в том числе прошлая, считается новым периодом по принятому правилу.
- **Дополнительный риск SDK:** при одновременной самой первой cloud-записи два устройства могут прочитать отсутствующий ключ. `SaveItem(..., null)` игнорирует write conflict для ключа, успевшего появиться. Известные версии защищены write lock. Строгая защита первого создания требует серверного арбитража или отдельного протокола хранения; дополнительное чтение лишь сужает окно гонки.

## Совместная работа

Cloud-карточки, их UXML/USS и локализация интегрируются владельцем параллельной UI-задачи. Offline QA APK использует согласованный стабильный срез Cloud + HUD. Остальные этапы UI имеют собственную приёмку. Чужие незавершённые изменения сохраняются отдельно от offline scope.
