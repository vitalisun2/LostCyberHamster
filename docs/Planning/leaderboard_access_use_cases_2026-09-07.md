# Лидерборд: доступ, сценарии и реализация

Дата: 7 сентября 2026. Статус: изменения внесены; финальный C# gate пройден. Пользователь продолжает ручную приёмку.

Цель: игрок видит доступную таблицу, понимает состояние своего результата и получает действие, которое устраняет конкретную причину отказа.

Анализ и реализация разделены между основным агентом и тремя субагентами: аккаунты/сохранения, контракт лидерборда, пользовательские сценарии. Ниже разделены исходный сбой, утверждённое поведение и выполненные проверки.

## Пользовательский договор

1. Таблицу можно смотреть гостем. Игра автоматически устанавливает гостевую сетевую сессию; регистрация и привязка внешнего аккаунта для просмотра не требуются.
2. Гость с подтверждённым владельцем локального профиля может участвовать в рейтинге. Привязка аккаунта нужна для восстановления доступа и переноса профиля между устройствами.
3. Общая таблица, личная позиция и отправка результата имеют отдельные состояния. Проблема локального сохранения приостанавливает участие, сохраняя просмотр таблицы.
4. При восстановлении связи открытый экран обновляется сам. «Повторить» повторяет подходящую операцию и показывает её состояние.
5. Старый прогресс принимается явным выбором игрока. Действие объясняет, какой прогресс и к какому игровому профилю будет привязан.
6. Меню заранее загружает рейтинги открытых частей дня. Экран сразу показывает кеш; фоновое чтение обновляет результаты. При прежних данных строки и прокрутка сохраняются.

Технически SDK требует сетевую авторизацию игрока, но поддерживает анонимный вход без данных от пользователя. В официальном примере Leaderboards этот вход используется для чтения таблицы и отправки очков. Связь с внешним аккаунтом — отдельный механизм восстановления identity. Источники: [Unity Leaderboards SDK sample](https://docs.unity.com/ja-jp/leaderboards/unity-sdk-sample), [Unity anonymous sign-in](https://docs.unity.com/en-us/authentication/use-anon-sign-in).

## Исходный сбой до изменений

### Историческое воспроизведение

Воспроизведение до исправления: Bootstrap → меню → лидерборд New York / Morning → «Повторить». Кнопка вызвана через зарегистрированный `ClickEvent`; физическое попадание мыши этим способом отдельно не проверялось. После повторного события экран сохранял «НЕ УДАЛОСЬ ЗАГРУЗИТЬ РЕЙТИНГ».

| Проверка | Факт |
|---|---|
| Unity / сеть | Play Mode активен; UGS готов; DEV offline выключен |
| Аккаунт | Гость авторизован; внешней привязки нет |
| Сохранение | `OwnerPlayerId = ""`, `LegacyOwnerUnassigned = true` |
| Облако | Конфликта нет; initial reconciliation не завершён |
| Доступ лидерборда | `CanRun() = false`; owner не совпадает с PlayerId |
| Повтор загрузки | `Leaderboard connection is unavailable.` до обращения к Leaderboards API |
| Независимое чтение API ранее в задаче | NY Morning отвечает успешно; текущая неделя пуста |

Причина: экран использовал строгий `WeeklyLeaderboardCoordinator.GetResultsAsync`, который требовал подтверждённого владельца и согласования облака. `TryBindAuthenticatedOwner` сохранял legacy без владельца. Экран сводил отказ к общей ошибке. Текущие владельцы этих механизмов: [weekly coordinator](../../LostCyberHamster/Assets/Scripts/Leaderboard/WeeklyLeaderboardCoordinator.cs), [GameDataManager](../../LostCyberHamster/Assets/Scripts/GameManagement/Persistence/GameDataManager.cs), [экран](../../LostCyberHamster/Assets/Scripts/UI/Screens/LeaderboardScreenController.cs).

Пустая серверная неделя — корректный результат запроса. В исходном сбое запрос до сервера не доходил; смена недели его не объясняла.

### Исходные связи, подтверждённые кодом

- Полный запрос [GameNetworkFacade](../../LostCyberHamster/Assets/Scripts/Online/GameNetworkFacade.cs) ожидал top и self; отказ self терял успешный top. Этот строгий контракт сохранён для DEV; экран получил отдельный сервис чтения.
- Общий и личный [кеш](../../LostCyberHamster/Assets/Scripts/Leaderboard/LeaderboardResultsSnapshot.cs) хранился в журнале владельца. Чтение недели и сохранение ответа также зависели от профильной транзакции.
- [CloudSyncService](../../LostCyberHamster/Assets/Scripts/CloudSave/CloudSyncService.cs) согласовывал облако только для Linked; принятия legacy гостем ещё не было.
- Пустая строка owner выбирала ветку «чужой аккаунт» и отклонялась `BindOwner` даже с `allowLegacyAdoption`. Это был статический вывод; внешняя привязка в исходном расследовании не запускалась.
- Успешная гостевая сессия могла сосуществовать с непринятым локальным прогрессом. Экран не различал эти состояния и не слушал восстановление сетевых зависимостей.
- [ExperienceProgressTestRunner](../../LostCyberHamster/Assets/Scripts/DevTools/ExperienceProgressTesting/ExperienceProgressTestRunner.cs) принимает `CurrentPlayer == null` за рекорд 0. Сетевой отказ его строгого чтения остаётся ошибкой.
- Установленный SDK 2.3.4 проверяет project ID, Player ID и access token: [LeaderboardsApiClientInternal](../../LostCyberHamster/Library/PackageCache/com.unity.services.leaderboards@4afe9822e038/Runtime/com.unity.services.leaderboards.internal/LeaderboardsApiClientInternal.cs#L166). Внешняя привязка и состояние локального сохранения в контракт чтения SDK не входят.

## Сценарии и сообщения

Таблица и блок «Ваш результат» отображаются независимо. Матрица фиксирует утверждённый смысл сообщений и действий; строки интерфейса локализованы на RU/EN.

| Ситуация | Общая таблица | Личный блок и действие |
|---|---|---|
| Онлайн, обычный гость | Загружается автоматически | Серверное место/очки либо «У вас пока нет результата за эту неделю» |
| Онлайн, привязанный аккаунт | То же поведение | Привязка сама по себе оформление рейтинга не меняет |
| Новая неделя без участников | «На этой неделе пока нет результатов» | Предложить пройти уровень выбранной части дня; это успешная загрузка |
| Личного результата нет, другие участники есть | Строки участников видны | «У вас пока нет результата за эту неделю»; действие «Играть» |
| Legacy без владельца | Таблица видна после гостевой авторизации | «Выберите игровой профиль для участия в рейтинге. Прогресс на устройстве сохранён»; «Выбрать профиль» |
| Аккаунт и владелец сохранения различаются | Таблица видна при действующей сессии | «Открыт другой игровой профиль. Выберите профиль для отправки результатов»; «Выбрать профиль»; чужое место не помечается «Вы» |
| Первичная синхронизация Linked | Таблица видна | При совпадении owner можно показать уже подтверждённое серверное место; «Синхронизируем прогресс. Новые результаты появятся после завершения» |
| Конфликт сохранений одного owner | Таблица и подтверждённое место видны | «Выберите прогресс для продолжения отправки результатов»; «Выбрать прогресс», затем существующий выбор устройство/облако/позже |
| Первый вход ещё выполняется | Кеш сразу, если есть; иначе «Подключаемся к рейтингу…» | Фоновое завершение загрузки без обязательной регистрации |
| Истекла сессия | Кеш с датой; в фоне восстановление тех же credentials | При невосстановимом входе известного связанного аккаунта — «Войдите снова, чтобы подключить игровой профиль»; явный маршрут входа |
| Связь недоступна, кеш есть | «Сохранённый рейтинг от {дата}» | «Не удалось обновить. Повторить»; после восстановления исчезает статус устаревания |
| Связь недоступна, кеша нет | «Не удалось подключиться к рейтингу. Проверьте интернет и повторите» | «Повторить»; DEV-симуляция дополнительно объясняется в DEV |
| Top получен, self завершился ошибкой | Полученный top остаётся | «Не удалось обновить ваш результат»; повтор только личного чтения |
| Результат ожидает отправки | Серверная таблица остаётся | «Результат сохранён на устройстве и ожидает отправки» только для durable Pending текущего owner и периода |
| Результат LocalOnly | Таблица доступна | «Этот результат сохранён только на устройстве. Для нового результата подключитесь к рейтингу и пройдите уровень ещё раз» |
| Результат Expired | Текущая неделя | «Неделя завершилась до отправки результата. Сыграйте ещё раз для участия в новой неделе» |
| Забег не улучшил рекорд | Действующий лучший результат | «Ваш рекорд этой недели остаётся {очки}»; отсутствие изменения очков объяснено |
| Ответ на отправку потерян, подтверждение не получено | Подтверждённые серверные строки | Для Pending: «Проверяем отправку результата»; для terminal Unconfirmed: «Не удалось подтвердить обновление рекорда»; бонус XP обещается только при подтверждении |
| 429 / 5xx / ошибка сервиса | Сохраняется подходящий кеш | Короткое сообщение о временной недоступности; повтор по backoff; кнопка исключает параллельные дубли |
| Не настроена таблица / доступ запрещён | Явная недоступность выбранной таблицы | «Этот рейтинг сейчас недоступен»; техническая причина в диагностике; без обещания исправить входом |

Один активный призыв к действию на каждый блок. «Повторить» используется для повторяемых сетевых отказов; выбор профиля и прогресса запускают соответствующий flow. Выход из flow оставляет таблицу доступной.

Неделя берётся с сервера; границы показываются в понятном локальном времени. Для кеша отображается время последнего чтения. Если срок сброса из кеша уже прошёл, указать «Рейтинг прошлой недели»; если актуальный период неизвестен — «Сохранённый рейтинг». Серверное время нового периода нельзя выводить из часов устройства как доказанный факт.

Текущий каталог доступных локаций и частей дня сохраняется. Расширение просмотра на закрытые игровые локации — отдельное продуктовое изменение.

## Принятие старого прогресса

Экран выбора должен объяснить отличие игрового гостевого профиля от внешней привязки.

**Гость, legacy без владельца.** «Использовать прогресс с этого устройства для текущего гостевого профиля?» Краткое описание: уровни и накопления сохраняются; следующие подходящие результаты могут отправляться в рейтинг. Действия: «Использовать этот прогресс», «Войти в существующий аккаунт», «Позже». Вход в существующий аккаунт отдельно предупреждает о возможной загрузке другого прогресса.

**Linked, legacy без владельца.** Прочитать облачную ветку до решения. При двух сохранениях показать сравнение и выбор. При пустом облаке показать принятие единственного локального прогресса; заголовок «Найдены два сохранения» здесь неверен.

**Реальный owner A, сессия B.** Обычное принятие legacy недоступно: это другой владелец. Использовать существующий механизм переключения/восстановления профиля с предварительным описанием последствий.

**Повторный вход известного Linked owner.** `ReauthenticateLinkedOwnerAsync` проверяет кандидата в отдельном SDK-профиле и принимает только прежний PlayerId. Локальный gameplay сохраняется; неудачная попытка возвращает исходный SDK-профиль и понятное состояние повтора.

Привязка подтверждается атомарно для пары ProfileId + PlayerId после проверки актуальной сессии и допустимости смены. При сбое записи решение остаётся незавершённым, игровой прогресс сохраняется. Повтор и перезапуск завершают ту же операцию.

Владение сохранением нормализуется в одном месте чтения/восстановления: отсутствие owner имеет единое представление. Реальные непустые идентификаторы и флаг legacy сохраняют смысл. Проверить также восстановление после rollback, backup и повторного чтения. Журналы без владельца, записанные под пустым ключом или `profile:<id>`, переносятся только при доказанном соответствии текущему профилю; неоднозначные записи требуют отдельного решения.

Старые LocalOnly-забеги сохраняют статус. После принятия профиля серверная неделя загружается для будущих забегов. Исторические очки и XP автоматически задним числом не публикуются: для них нет прежнего подтверждённого контекста.

Экран победы и личный блок используют одинаковое объяснение. Для новых LocalOnly-записей сохранять причину: не определён владелец либо неизвестен период. Для старых записей с неизвестной причиной использовать общий точный текст «Результат сохранён только на устройстве».

## Контракты реализации

### Чтение

[LeaderboardReadService](../../LostCyberHamster/Assets/Scripts/Leaderboard/LeaderboardReadService.cs) читает рейтинг через существующие `GameNetworkFacade` и `LeaderboardService`. SDK остаётся за фасадом.

- Чтение top: доступ сети, готовый UGS, действующая авторизация. Локальный owner и облачное согласование не участвуют в разрешении этого чтения.
- Чтение «Вашего результата»: отдельный outcome. Пометка «Вы» требует совпадения identity с подтверждённым владельцем активного профиля. При совпадении чтение серверного места безопасно во время синхронизации или конфликта; отправка остаётся приостановленной.
- Отсутствие записи, временная ошибка, истёкшая сессия и неподходящий профиль различаются типизированным состоянием. `null` означает только доказанное отсутствие записи там, где этот контракт нужен существующему потребителю.
- Для top и self — независимые результаты и повторы. Ошибка вторичного запроса сохраняет уже полученный top.
- Строгое чтение личного рекорда для DEV остаётся отдельным контрактом: отсутствие записи допустимо, сетевой отказ не превращается в 0.

### Кеш и период

Общий [кеш просмотра](../../LostCyberHamster/Assets/Scripts/Leaderboard/LeaderboardReadCache.cs) хранится отдельно от журнала gameplay/отправки. Для каждой среды и настроенной таблицы сохраняется последний успешный снимок: VersionId, FetchedAtUtc, NextResetUtc и строки. Личная запись имеет собственный OwnerPlayerId; пометка «Вы» проверяется при каждом показе. Кеш читается независимо от владельца прогресса. Старый профильный кеш служит fallback при совпадении подтверждённого владельца. Очереди и receipts остаются в прежнем формате.

Стабильность недели: версия до чтения и после чтения относится к одной таблице; при reset повторить загрузку текущего периода. Sequence для ответов периода, данных таблицы и жизненного цикла экрана разделены. Ушедший экран не принимает поздний результат. Смена identity сразу снимает персональную пометку, даже если общие строки остаются.

Ошибка сохранения кеша не отменяет показ уже полученного ответа. Профильный weekly journal продолжает хранить runId, owner, исходный период, FIFO, receipts и награды.

### Предзагрузка в меню и обновление экрана

- [MenuEntryPoint](../../LostCyberHamster/Assets/Scripts/Entry%20Points/MenuEntryPoint.cs) запускает предзагрузку открытых локаций и частей дня. Уход из меню приостанавливает фоновую очередь.
- Открытие рейтинга и смена вкладки сразу показывают имеющийся снимок. Сеть проверяет выбранную таблицу в фоне; кеш остаётся видимым вместе со статусом обновления.
- Одновременные запросы одной таблицы используют одну Task. Повторный старт ограничен интервалом 1 секунда; одновременно выполняются максимум две загрузки таблиц.
- Ошибки возвращаются в очередь существующего `OnlineServicesCoordinator`: backoff 5, 15, 30, 60 секунд с его штатным разбросом. Отказ одной таблицы сохраняет возможность обработать остальные.
- Вход в меню, восстановление сети/сессии, согласование профиля и подтверждение забега запускают нужное фоновое обновление. Повтор self-ошибки использует успешный top.
- Экран сравнивает таблицу и ContentVersion. При прежних серверных данных строки остаются на месте; состояние подключения и дата обновляются отдельно. При изменении результатов сохраняется позиция прокрутки выбранной таблицы.
- Подтверждённая неделя чтения может заполнить контекст будущих забегов только для согласованного текущего владельца. Старые LocalOnly сохраняют свой исходный статус.

### Участие и восстановление

Сохранить строгий контракт очереди: подходящий owner, актуальная сессия, облачное согласование для Linked, отсутствие блокирующего конфликта. Read-only доступ к таблице не меняет право отправки.

Сервис чтения передаёт UI состояния таблицы, личной записи и участия. Правило принятия legacy принадлежит `ProfileOwnershipService` и `GameDataManager`; облачное сравнение — CloudSync/ConflictService. Лидерборд вызывает готовый сценарий выбора.

Открытый экран слушает готовность сессии, восстановление сети, смену профиля, разрешение конфликта и подтверждение текущего weekly run. Запросы объединяются. При закрытии экрана подписки снимаются, персональные ответы проверяют session/profile generation. Ручной повтор сначала восстанавливает необходимые сетевые зависимости, затем читает выбранную таблицу. У refresh свой цикл: он не запускает отправку всех Pending и обход сезонов всех 12 таблиц. Завершение отправки отдельно обновляет выбранный рейтинг через RunChanged.

### Наблюдаемость

Штатный Diagnostic Log фиксирует таблицу, стадию top/self/cache/season и тип отказа. Сообщения ограничены ошибками и значимыми переходами; токены остаются внутри SDK.

## Матрица полной приёмки

Проверять на подготовленных профилях с резервной копией; текущий пользовательский прогресс сохраняется. Новые unit/EditMode/PlayMode harness не входят в этот план; сценарии проходят существующими инструментами и в игре.

1. Текущий случай: гостевая сессия + legacy + пустой owner. Top приходит; есть объяснение участия и рабочий выбор профиля. Повтор не зацикливается на общей ошибке.
2. Гость с owner смотрит рейтинг и отправляет подходящий новый результат без внешней привязки. После обычного перезапуска восстанавливается та же identity.
3. Legacy: `null` и `""`, первая миграция и повторный запуск; принятие сохраняет уровни, валюту, ProfileId и доказанно относящиеся журналы. LocalOnly не становится Pending.
4. Linked legacy: пустое облако, две ветки, «Позже», изменившийся cloud snapshot. Выбор и текст соответствуют числу реальных сохранений.
5. Owner A / сессия B: top доступен; чужая строка не помечается «Вы»; отправка A от имени B блокируется; выбор профиля явный.
6. Первичная синхронизация и конфликт того же owner: top и серверный self читаются; очередь ждёт согласования и возобновляется после решения.
7. Offline: холодный запуск, потеря связи после входа, кеш/пустой кеш, прошлый период. Возвращение сети обновляет открытый экран автоматически; кеш имеет дату.
8. Auth: задержанный первый вход, expiry, невосстановимые credentials. Появляется конечное понятное состояние; повтор восстанавливает нужную зависимость; новая identity не подменяет существующего владельца молча.
9. Top успешен, self ошибочен; отсутствие self; пустой top; успешный повтор self. Пустой результат отделён от сетевого отказа, DEV не считает отказ нулевым рекордом.
10. Быстрые нажатия «Повторить», смена вкладки/аккаунта, закрытие экрана, ответ старого запроса: одна актуальная загрузка и корректная персональная пометка.
11. Reset между запросами; сезонный cache; Pending, Expired, NotImproved, Unconfirmed, подтверждённый рекорд. Отображается фактический период и состояние; XP/receipts сохраняют прежний контракт.
12. Ошибка записи кеша и ошибка принятия owner: первая сохраняет видимый свежий top; вторая сохраняет игровой прогресс и возможность повторить выбор.
13. Если затронуты testing-команды — одинаковое поведение DEV/Tools/Testing, повторный вход в Play Mode. Android дополнительно проверяется отдельно от Editor.

Для C# финальный gate по проекту: regenerate_project_files, затем dotnet build affected generated csproj --no-restore. Runtime-приёмка — перечисленные сценарии после реализации по согласованному объёму.
