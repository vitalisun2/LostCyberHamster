# Универсальный алгоритм бота

> **Роль документа:** алгоритмический скелет — описывает чистый decision loop
> бота: как выбирается один шаг и как строятся цепочки.
>
> **Доменные детали** (модель мира, пространства дорога/крыша/переходы,
> конкретные инструменты, автоматические переходы, ульта) зафиксированы
> в [bot concept brainstrom](bot%20concept%20brainstrom).
>
> Оба документа вместе — основа для архитектуры бота.

## Секция: Обработка объекта, создание шага

### Группы ситуаций

* **Threat** — угроза, которую нельзя игнорировать
* **Target** — объект, на который можно напрыгнуть (с дороги или с крыши)
* **Collectible** — бонус, который можно собрать

`Neutral` объекты (не влияющие на решения) в алгоритме не участвуют.

### Алгоритм

1. Найти все действия, подходящие для обработки текущего объекта.
2. Для каждого действия спрогнозировать результат шага.
3. Оставить только безопасные действия.
4. Выбрать лучшее действие по приоритетам: максимальный профит → минимальная энергия.
5. Выполнить выбранный шаг.

## Секция: Построение и выбор цепочки шагов

### Группы ситуаций

* На экране есть несколько объектов
* Для их обработки требуется два и более шага
* Возможны одна или более безопасных цепочек

### Алгоритм

1. Определить набор объектов, которые нужно обработать в видимой области.
   Обработка идёт от ближайшего к дальнему, но выбор первого шага учитывает
   всю цепочку, а не только ближайший объект.
2. Для каждого действия спрогнозировать результат шага.
3. Продолжить построение цепочки из нового состояния.
4. Прервать построение цепочки, если на любом шаге хомяк теряет жизнь.
5. Сохранить только полностью безопасные цепочки.
6. Выбрать цепочку с максимальным профитом.
7. Если профит одинаковый — выбрать самую энергоэффективную цепочку.
8. Выполнить первый шаг выбранной цепочки.

### Приоритет выбора цепочки

1. Безопасность
2. Профит ресурсов
3. Энергоэффективность

### Профит

* Напрыгивание на Target (уничтожение угрозы, выпадение наград, заряд ульты)
* Подбор Collectible (жизни, энергия, кристаллы, монеты)

## Секция: Этапы отладки бота

### Общее правило для этапов 1–4

* Все тестовые ситуации должны требовать только один шаг.
* Даже если на экране несколько объектов, их расположение должно позволять обработку одним решением.
* Построение цепочек на этих этапах не используется.

### Этап 1. Проверка алгоритма на одном простом типе угрозы

* Обрабатывается только `Threat`.
* На экране один объект.
* Используется один простой тип угрозы.
* Бот строит один шаг.
* Проверяется корректность выбора безопасного действия.

### Этап 2. Проверка алгоритма на всех типах угроз

* Обрабатываются все типы `Threat`.
* На экране один объект.
* Для каждого типа угрозы проверяется корректность выбора безопасного действия.
* Если безопасных действий несколько, выбирается самое энергоэффективное.

### Этап 3. Один объект, один шаг, все группы объектов

* Обрабатываются:

  * `Threat`
  * препятствие, на которое можно напрыгнуть
  * `Collectible`
* На экране один объект.
* Для каждого типа объекта проверяется корректность выбора безопасного действия.

### Этап 4. Несколько объектов, один шаг

* На экране несколько объектов.
* Их расположение должно позволять обработку одним шагом.
* Бот определяет актуальный объект для обработки.
* Бот строит один безопасный и оптимальный шаг с учётом остальных видимых объектов.

### Этап 5. Последовательность одиночных шагов через пересчёт

* После завершения любого шага выполняется пересчёт.
* После изменения состава видимых объектов выполняется пересчёт.
* После каждого пересчёта бот заново выбирает следующий одиночный шаг.
* Полноценное построение цепочек ещё не используется.

### Этап 6. Цепочки из двух шагов

* Добавляется построение безопасных цепочек длиной 2.
* Если на любом шаге цепочки хомяк теряет жизнь, цепочка отбрасывается.
* Среди безопасных цепочек выбирается наиболее выгодная.

### Этап 7. Цепочки из трёх и более шагов

* Добавляется построение более длинных безопасных цепочек.
* Бот сравнивает несколько допустимых цепочек.
* Выбор выполняется по приоритетам:

  1. безопасность
  2. профит
  3. энергоэффективность

### Этап 8. Полный алгоритм

* Используются все группы объектов.
* Используется пересчёт после шага и при изменении состава видимых объектов.
* Используется построение и выбор безопасных цепочек.
* Бот должен стабильно проходить тестовые ситуации без потери жизни.
