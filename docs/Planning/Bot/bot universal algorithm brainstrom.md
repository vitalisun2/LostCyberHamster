# Универсальный алгоритм бота

> **Роль документа:** алгоритмический скелет — описывает чистый decision loop
> бота: как выбирается один шаг и как строятся цепочки.

## Секция: Обработка объекта, создание шага

### Группы ситуаций

* **Threat** — угроза, которую нельзя игнорировать
* **Target** — объект, на который можно напрыгнуть (с дороги или с крыши)
* **Collectible** — бонус, который можно собрать

`Neutral` объекты (не влияющие на решения) в алгоритме не участвуют.

### Алгоритм

1. Найти все действия, подходящие для обработки текущего объекта.
2. Для каждого действия спрогнозировать результат шага.
3. Оставить только безопасные действия.
4. Выбрать лучшее действие по приоритетам: максимальный профит → минимальная энергия.
5. Выполнить выбранный шаг.

## Секция: Построение и выбор цепочки шагов

### Группы ситуаций

* На экране есть несколько объектов
* Для их обработки требуется два и более шага
* Возможны одна или более безопасных цепочек

### Алгоритм

1. Определить набор объектов, которые нужно обработать в видимой области.
   Обработка идёт от ближайшего к дальнему, но выбор первого шага учитывает
   всю цепочку, а не только ближайший объект.
2. Для каждого действия спрогнозировать результат шага.
3. Продолжить построение цепочки из нового состояния.
4. Прервать построение цепочки, если на любом шаге хомяк теряет жизнь.
5. Сохранить только полностью безопасные цепочки.
6. Выбрать цепочку с максимальным профитом.
7. Если профит одинаковый — выбрать самую энергоэффективную цепочку.
8. Выполнить первый шаг выбранной цепочки.

### Приоритет выбора цепочки

1. Безопасность
2. Профит ресурсов
3. Энергоэффективность

### Профит

* Напрыгивание на Target (уничтожение угрозы, выпадение наград, заряд ульты)
* Подбор Collectible (жизни, энергия, кристаллы, монеты)
