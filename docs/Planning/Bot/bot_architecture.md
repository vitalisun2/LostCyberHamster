# Архитектура бота

**Версия:** 4.0
**Дата:** 2026-03-14

**Основа:**

* [bot universal algorithm brainstrom](bot%20universal%20algorithm%20brainstrom.md) — алгоритмический скелет (decision loop)
* [bot concept brainstrom](bot%20concept%20brainstrom) — доменные детали (модель мира, инструменты, переходы)

**Подход:** поэтапная разработка. Бот строится инкрементально по этапам
из [bot_implementation_plan.md](bot_implementation_plan.md).
Каждая секция архитектуры помечена номером этапа, на котором она становится актуальной.

---

## 1. Принципы

1. **Snapshot** — алгоритм работает по снимку мира, не по живым Unity-объектам.
2. **SRP** — каждый компонент отвечает за одну задачу.
3. **Pipeline** — обработка идёт по цепочке этапов с чёткими входами и выходами.
4. **Планирование отделено от исполнения** — выбор действия и его тайминг — разные компоненты.

---

## 2. Приоритеты выбора действия

Единый источник правды для всех этапов:

1. **Безопасность** — не потерять жизнь
2. **Профит** — максимальная выгода (уничтоженные Target, собранные Collectible)
3. **Энергоэффективность** — минимальная трата энергии

На этапах 1–2 (только Threat) профит не актуален — выбор идёт по безопасности → энергии.
Начиная с этапа 3 (появляются Target и Collectible) профит включается в выбор.

---

## 3. Сущности данных

### `BotSceneSnapshot` [Этап 1+]

Снимок мира на момент запуска алгоритма. Собирается один раз и не меняется.

* линия хомяка (верхняя / нижняя)
* пространство (дорога / крыша)
* энергия, жизни, заряд ульты, монеты
* список видимых объектов (ещё не классифицированных)

### `ObstacleInfo` [Этап 1+]

Снимок одного видимого объекта.

* тип (`ObstacleTypeEnum`)
* линия, флаг крыши
* координаты (leftX, rightX, centerX)
* расстояние до хомяка
* категория (`Target` / `Threat` / `Collectible` / `Neutral`)
* ID объекта

### `BotAction` [Этап 1+]

Действие, которое бот может выполнить.

* смена линии (бесплатно)
* обычный прыжок (10 энергии)
* суперпрыжок (20 энергии)
* прыжок с крыши (10 энергии)
* суперпрыжок с крыши (20 энергии)
* ульта (0 энергии, нужен полный заряд)

### `ChainStep` [Этап 1+]

Один шаг — решение бота по конкретному объекту.

* действие (`BotAction`)
* целевой объект (`ObstacleInfo`)
* условие исполнения (дистанция до объекта)
* стоимость по энергии
* ожидаемый результат

### `ProjectedState` [Этап 6+]

Спроецированное состояние хомяка после шагов в цепочке.

* линия, пространство, X-позиция
* энергия, заряд ульты
* набор ещё не обработанных объектов

Начальный `ProjectedState` строится из `BotSceneSnapshot`.
Каждый шаг порождает новый `ProjectedState`.

### `ChainCandidate` [Этап 6+]

Кандидатная цепочка шагов.

* список шагов (`ChainStep[]`)
* финальный `ProjectedState`
* суммарная стоимость по энергии
* суммарная выгода
* флаг безопасности

### `CurrentPlan` [Этап 6+]

Текущий рабочий план — FIFO-очередь шагов.

* очередь шагов (`ChainStep[]`)
* причина выбора (для логирования)

На этапах 1–5 бот работает с одиночными `ChainStep`, план не нужен.

## 4. Компоненты

### Обзор

| Компонент | Вход | Выход | Этап |
|-----------|------|-------|------|
| `HamsterBot` | runtime-триггеры | вызовы pipeline | 1+ |
| `SnapshotBuilder` | живые Unity-объекты | `BotSceneSnapshot` | 1+ |
| `ObjectClassifier` | `BotSceneSnapshot` | `ObstacleInfo[]` с категориями | 1+ |
| `ActionGenerator` | `ObstacleInfo[]`, состояние хомяка | безопасные `ChainStep[]` | 1+ |
| `ActionSelector` | `ChainStep[]` | лучший `ChainStep` | 1+ |
| `StepExecutor` | `ChainStep` | игровая команда в нужный момент | 1+ |
| `ChainGenerator` | `ObstacleInfo[]`, `ProjectedState` | `List<ChainCandidate>` | 6+ |
| `ChainScorer` | `List<ChainCandidate>` | ранжированные кандидаты | 6+ |
| `PlanManager` | кандидаты, текущий план | `CurrentPlan` | 6+ |

### `HamsterBot` [Этап 1+]

Оркестратор. Принимает триггеры, запускает pipeline, хранит результат.
Не принимает решений — только координирует.

### `SnapshotBuilder` [Этап 1+]

Вход: живые Unity-объекты.
Выход: `BotSceneSnapshot`.

Единственный компонент, обращающийся к живым объектам.
Читает состояние хомяка и сканирует видимые объекты.

### `ObjectClassifier` [Этап 1+]

Вход: `BotSceneSnapshot`.
Выход: `ObstacleInfo[]` с категориями.

Присваивает каждому объекту категорию: `Target`, `Threat`, `Collectible`, `Neutral`.
Учитывает контекст: тот же объект может быть `Target` с крыши и `Threat` с дороги.

### `ActionGenerator` [Этап 1+]

Вход: `ObstacleInfo[]`, состояние хомяка (линия, пространство, энергия).
Выход: список допустимых безопасных `ChainStep[]`.

Для каждого релевантного объекта — набор возможных действий.
Недопустимые действия отсечены (нет энергии, не тот тип объекта).
Небезопасные действия отсечены (результат ведёт к потере жизни).

**Прогнозирование результата шага** включает:

* зону приземления после прыжка
* отскок после напрыгивания на Target
* автоматический спуск с крыши (RunFromRoof, ~1.9 юнитов уязвимости)
* автопереход между смежными крышами

### `ActionSelector` [Этап 1+]

Вход: безопасные `ChainStep[]`.
Выход: лучший `ChainStep`.

Выбирает по приоритетам из секции 2:
безопасность (уже отфильтрованы) → профит → энергия.

### `StepExecutor` [Этап 1+]

Вход: выбранный `ChainStep`.
Выход: игровая команда.

Ждёт правильного момента (дистанция до объекта), проверяет через
`CollisionUtils`, отправляет игровое событие (JumpRequest, TapRequest и т.д.).

### `ChainGenerator` [Этап 6+]

Вход: `ObstacleInfo[]`, `ProjectedState`.
Выход: `List<ChainCandidate>`.

Строит цепочки рекурсивно, от ближайшего объекта к дальнему.
Каждый объект порождает ветвление (несколько вариантов действий).
Каждый шаг обновляет `ProjectedState`.
Цепочка отбрасывается целиком, если любой шаг ведёт к потере жизни.
Глубина: 2–5 шагов.

### `ChainScorer` [Этап 6+]

Вход: `List<ChainCandidate>`.
Выход: ранжированные кандидаты.

Оценивает по приоритетам из секции 2.

### `PlanManager` [Этап 6+]

Вход: ранжированные кандидаты, текущий `CurrentPlan`.
Выход: обновлённый `CurrentPlan`.

Два режима обновления:

* **keep tail + extend** — хвост текущего плана валиден → достроить новыми шагами
* **full rebuild** — хвост невалиден → выбрать лучшего кандидата целиком

Rebuild если: объекты шагов исчезли, путь больше не безопасен,
появилась более выгодная достижимая цель.

---

## 5. Pipeline: один шаг [Этапы 1–4]

На этапах 1–4 бот принимает одно решение за раз. Цепочки не строятся.

```
Trigger
  → SnapshotBuilder    → BotSceneSnapshot
  → ObjectClassifier   → ObstacleInfo[]
  → ActionGenerator    → безопасные ChainStep[]
  → ActionSelector     → лучший ChainStep
  → StepExecutor       → игровая команда
```

**Этап 1:** один объект, один тип Threat. Проверка базовой механики.
**Этап 2:** один объект, все типы Threat.
**Этап 3:** один объект, все категории (Threat, Target, Collectible).
**Этап 4:** несколько объектов, но ситуация решается одним шагом.

---

## 6. Pipeline: пересчёт [Этап 5]

Бот по-прежнему работает одиночными шагами, но после каждого —
пересчёт с нуля.

```
Trigger (завершение шага ИЛИ изменение состава видимых объектов)
  → Pipeline одного шага (секция 5)
```

### Runtime-триггеры

Алгоритм запускается только в состояниях `Run` и `RoofRun`.

Два триггера:

1. Завершён шаг, хомяк снова управляем
2. Изменился состав видимых объектов (вошёл, ушёл, уничтожен, собран)

---

## 7. Pipeline: цепочки [Этапы 6–8]

Бот строит несколько кандидатных цепочек и выбирает лучшую.
Выполняется первый шаг. После завершения — пересчёт.

```
Trigger
  → SnapshotBuilder    → BotSceneSnapshot
  → ObjectClassifier   → ObstacleInfo[]
  → PlanManager        → keep tail / rebuild решение
  → ChainGenerator     → List<ChainCandidate>
  → ChainScorer        → ранжированные кандидаты
  → PlanManager        → CurrentPlan
  → StepExecutor       → игровая команда (голова очереди)
```

**Этап 6:** цепочки длиной 2.
**Этап 7:** цепочки длиной 3+. Сравнение нескольких вариантов.
**Этап 8:** полный алгоритм — все категории, пересчёт, цепочки.

### Алгоритм генерации цепочек

1. Взять `ProjectedState` (из snapshot или из конца хвоста при keep tail)
2. Найти ближайший релевантный объект (Threat или Target на пути)
3. Threat → варианты уклонения. Target → варианты взаимодействия + уклонения.
4. Для каждого варианта: применить шаг → новый `ProjectedState`
5. Рекурсивно продолжить из нового состояния
6. Если нет объектов впереди — цепочка завершена
7. Если на любом шаге потеря жизни — цепочка отброшена целиком
