# Техническое задание: HamsterBot v2 — Chain Planner

**Версия:** 2.0
**Дата:** 2026-03-11
**Статус:** Проектирование
**Основа:** [bot concept brainstrom](bot%20concept%20brainstrom)

---

## 1. Цель

Реализовать бота, который автоматически управляет хомяком, используя детерминированный алгоритм
с построением цепочки действий. Бот должен проходить уровни без потери жизней, собирая бонусы
и накапливая ману для ульты.

Старая реализация (31 файл: BotBrain, BotPlanner, Learning/, Planning/) **удаляется полностью**.
Сохраняются только: HamsterBotUI.cs (упрощённый) и скелет HamsterBot.cs (toggle, lifecycle).

## 2. Архитектура

### 2.1 Принципы

1. **Минимум классов.** Вся логика бота — 5–6 файлов. Никаких абстракций «на будущее».
2. **Struct'ы вместо классов** для данных, передаваемых каждый кадр (ObstacleInfo, ChainStep, BotDecision).
3. **Чистая математика** для прогнозов (позиция приземления, время до столкновения). Никакой Physics.Simulate.
4. **Один алгоритм, одно поведение.** Никаких стратегий, стилей, режимов. Детерминированная логика.
5. **Бот = ещё один игрок.** Управление через те же AtomicEvent'ы, что и клавиатура. Ноль изменений в игре.
6. **Пересчёт по событиям**, а не каждый кадр. Dirty flag инвалидирует цепочку при значимых изменениях.

### 2.2 Структура файлов

```
Assets/Scripts/Bot/
├── HamsterBot.cs              — MonoBehaviour-оркестратор (переписанный, упрощённый)
├── HamsterBotUI.cs            — OnGUI оверлей (упрощённый)
├── BotAction.cs               — enum действий (6 значений)
├── BotChainPlanner.cs         — основной алгоритм: сканирование + построение цепочки
├── ObstacleInfo.cs            — readonly struct: снимок данных об одном объекте
└── ChainStep.cs               — readonly struct: один шаг цепочки (действие + цель + причина)
```

**Итого: 6 файлов** (вместо 31).

### 2.3 Диаграмма потока данных

```
HamsterBot.Update()
  │
  ├─ Проверка: нужен ли пересчёт? (dirty flag)
  │   ├─ Нет → выполнить текущий первый шаг цепочки
  │   └─ Да ↓
  │
  ├─ BotChainPlanner.BuildChain(hamster, obstacles)
  │   │
  │   ├─ 1. Сканировать ObstacleSpawner.SpawnedObstacles
  │   │      → заполнить массив ObstacleInfo[] (отсортирован по X)
  │   │
  │   ├─ 2. Классифицировать каждый объект: цель / угроза / бонус
  │   │
  │   ├─ 3. Найти ближайшую цель высокого приоритета
  │   │
  │   ├─ 4. Для каждого объекта на пути к цели:
  │   │      подобрать инструмент (смена линии / прыжок / суперпрыжок)
  │   │      проверить последствия (безопасно ли приземление?)
  │   │      учесть суммарный расход энергии
  │   │
  │   ├─ 5. Если путь безопасен → вернуть цепочку ChainStep[]
  │   │      Если нет → отказаться от цели, построить цепочку уклонения
  │   │
  │   └─ Вернуть ChainStep[] (первый элемент = следующее действие)
  │
  └─ ExecuteAction(chain[0])
      └─ hamster.JumpRequest.Invoke() / TapRequest.Invoke() / ...
```

### 2.4 Dirty flag — когда пересчитывать цепочку

Цепочка инвалидируется (`_dirty = true`) при:

| Событие | Источник |
|---|---|
| Новый объект появился в зоне видимости | Проверка в Update: кол-во объектов изменилось |
| Хомяк завершил действие | HamsterState изменился на `Run` или `RoofRun` |
| Хомяк получил урон | `IsDamaged` стал `true` |
| Энергия изменилась | `Energy.Value` изменился |
| Ульта стала доступна | `UltaChargeAmount.Value` достиг 100 |
| Прошло N кадров с прошлого пересчёта | Fallback: максимум 10 кадров без пересчёта |

В остальные кадры бот **исполняет** первый шаг текущей цепочки (если нужен тайминг — ждёт).

## 3. Структуры данных

### 3.1 BotAction (enum)

```csharp
public enum BotAction
{
    None,            // Ничего не делать (бежать)
    SwitchLane,      // Сменить линию (TapRequest)
    Jump,            // Обычный прыжок (JumpRequest, 10 энергии)
    SuperJump,       // Суперпрыжок (SuperJumpRequest, 20 энергии)
    RoofJump,        // Прыжок с крыши (RoofJumpRequest, 10 энергии)
    SuperRoofJump,   // Суперпрыжок с крыши (SuperRoofJumpRequest, 20 энергии)
    UseUlta          // Активировать ульту (UltaEvent)
}
```

### 3.2 ObstacleInfo (readonly struct)

Снимок данных об одном объекте. Создаётся при сканировании, не хранит ссылок на GameObject.

```csharp
public readonly struct ObstacleInfo
{
    public readonly ObstacleTypeEnum Type;
    public readonly float LeftX;          // Левый край объекта (мировые координаты)
    public readonly float RightX;         // Правый край
    public readonly float CenterX;        // Центр
    public readonly bool IsTopLane;       // true = верхняя линия
    public readonly bool IsOnRoof;        // true = стоит на крыше BigNotAlive/MediumNotAlive
    public readonly float DistanceToHamster;  // от RightX хомяка до LeftX объекта
    public readonly float TimeToReach;    // DistanceToHamster / GameSpeedBase

    // Классификация (вычисляется при создании)
    public readonly ObjectCategory Category;  // Target / Threat / Bonus / Neutral
}

public enum ObjectCategory
{
    Target,     // Цель высокого приоритета (можно напрыгнуть)
    Bonus,      // Collectible
    Threat,     // Угроза (столкновение = урон)
    Neutral     // Декор или объекты позади хомяка
}
```

### 3.3 ChainStep (readonly struct)

Один шаг в цепочке действий.

```csharp
public readonly struct ChainStep
{
    public readonly BotAction Action;
    public readonly int TargetObstacleIndex;  // Индекс в массиве ObstacleInfo (-1 если нет цели)
    public readonly float ExecuteAtDistance;   // На каком расстоянии до объекта выполнить действие
    public readonly int EnergyCost;           // Сколько энергии потратит этот шаг
    public readonly string Reason;            // Для дебага / лога
}
```

## 4. Алгоритм BotChainPlanner

### 4.1 Сканирование (BuildObstacleList)

1. Получить `ObstacleSpawner.Instance.SpawnedObstacles`
2. Для каждого элемента, у которого `LeftX > hamster.LeftX - 1.0` (не слишком далеко позади):
   - Заполнить `ObstacleInfo` из данных Obstacle + ObstacleType
   - Определить линию: `IsTopLane` по Y позиции (сравнение с `Consts.ObstacleY0Pos` / `ObstacleY1Pos`
     с допуском `ObstacleLineTolerance`)
   - Определить `IsOnRoof` по Y > порога крыши
   - Вычислить `DistanceToHamster` и `TimeToReach`
3. Классифицировать `ObjectCategory`:
   - `decor` → Neutral
   - `collectable*` → Bonus
   - Определение Target / Threat зависит от типа объекта и текущего состояния хомяка (см. таблицу ниже)
4. Отсортировать по `LeftX` (ближайшие первыми)

### 4.2 Классификация Target vs Threat

Зависит от **текущей позиции хомяка** (дорога / крыша) и **типа объекта**:

**Хомяк на дороге (`Run`):**

| Тип | Та же линия | Другая линия |
|---|---|---|
| SmallAlive | **Target** (напрыгнуть, 10 энергии) | Target (если сменить линию) |
| BigAlive | **Threat** (смена линии или суперпрыжок) | Нейтрально |
| BigNotAlive | **Threat** (прыжок на крышу или смена линии) | Нейтрально |
| MediumNotAlive | **Threat** (прыжок на крышу или смена линии) | Нейтрально |
| SmallNotAliveRoad | **Threat** (перепрыгнуть или смена линии) | Нейтрально |
| SmallNotAliveRoadAndRoof | **Threat** (перепрыгнуть или смена линии) | Нейтрально |

**Хомяк на крыше (`RoofRun`):**

| Тип | На крыше впереди | Ниже (на дороге) |
|---|---|---|
| SmallAlive | — | **Target** (прыжок с крыши) |
| BigAlive | — | **Target** (прыжок с крыши) |
| SmallNotAliveRoadAndRoof | **Threat** (перепрыгнуть) | — |

### 4.3 Построение цепочки (BuildChain)

Входные данные:
- `ObstacleInfo[]` — отсортированный массив объектов
- Состояние хомяка: линия, высота, энергия, жизни, ульта, `HamsterState`

Алгоритм:

```
1. Отфильтровать объекты на текущей линии хомяка (и на другой линии для анализа смены)
2. Найти ближайшую Target на текущей или доступной линии
3. Если Target найдена:
   a. Перебрать все объекты между хомяком и Target
   b. Для каждого объекта на пути → подобрать инструмент:
      - Threat → выбрать: смена линии (0), прыжок (10), суперпрыжок (20)
      - Bonus на пути → собрать, если не мешает
   c. Для каждого шага проверить последствия (см. 4.4)
   d. Подсчитать суммарный расход энергии
   e. Если суммарный расход > текущая энергия → проверить вариант без Target (экономный путь)
   f. Если путь безопасен → цепочка готова
4. Если Target не найдена или путь заблокирован:
   a. Построить цепочку уклонения: для каждой Threat подобрать самый дешёвый инструмент
5. Вернуть ChainStep[] (если пусто → BotAction.None)
```

### 4.4 Проверка последствий шага

Для каждого шага нужно проверить, что после выполнения действия хомяк не окажется в опасности:

**Прыжок (обычный / суперпрыжок):**
- Вычислить `X_приземления = X_объекта + GameSpeedBase * Длительность_анимации_прыжка`
- Проверить: есть ли Threat в зоне `[X_приземления - tolerance, X_приземления + tolerance]`
  на той же линии?
- Если есть → шаг опасен

**Напрыгивание на SmallAlive:**
- Объект уничтожается → исключить из дальнейшего анализа
- Вычислить позицию хомяка после анимации приземления
- Проверить: нет ли следующего объекта в зоне, куда хомяк вернётся

**Смена линии:**
- Проверить другую линию: нет ли Threat на расстоянии, которое хомяк пройдёт за время переключения
- Длительность переключения: ~0.3 сек (из анимации shift_transform)
- За это время сцена сдвинется на: `0.3 * 3.8 ≈ 1.14 юнита`

**Прыжок на крышу (BigNotAlive / MediumNotAlive):**
- Проверить: есть ли SmallNotAliveRoadAndRoof на крыше этого объекта?
- Если есть → учесть дополнительный прыжок на крыше (доп. расход энергии)

### 4.5 Выбор инструмента (SelectTool)

Для каждой Threat перебрать доступные инструменты **в порядке дешевизны**:

| Threat | Инструмент 1 (дешёвый) | Инструмент 2 | Инструмент 3 (дорогой) |
|---|---|---|---|
| BigAlive | Смена линии (0) | Суперпрыжок (20) | — |
| SmallNotAliveRoad | Смена линии (0) | Прыжок (10) | — |
| SmallNotAliveRoadAndRoof | Смена линии (0) | Прыжок (10) | — |
| BigNotAlive | Смена линии (0) | Прыжок на крышу (10) | — |
| MediumNotAlive | Смена линии (0) | Прыжок на крышу (10) | — |

Для каждого инструмента → проверить последствия (4.4).
Выбрать первый безопасный.

### 4.6 Тайминг выполнения действия

Бот не должен выполнять действие слишком рано или слишком поздно.

**Окно выполнения:**
- `ExecuteAtDistance` — расстояние, при котором нужно выполнить действие
- Для прыжка: расстояние, с которого прыжок попадёт в нужную зону
  (определяется из дальности прыжка animation clip)
- Для смены линии: расстояние, при котором нужно сместиться,
  чтобы избежать Threat / достичь Target

**Формулы:**
- `JumpExecuteDistance = JumpLandingDistance - (GameSpeedBase * JumpDuration)`
  где `JumpLandingDistance` — расстояние от хомяка до точки приземления
- Для смены линии: `SwitchExecuteDistance = ThreatDistance - SafeMargin`
  где `SafeMargin ≈ 1.5 юнита` (запас на анимацию)

Бот ждёт, пока объект не окажется в окне выполнения, и только тогда выполняет действие.

### Этап 3: Базовое уклонение от угроз

**Цель:** Бот умеет избегать препятствий (не теряет жизни), но ещё не стремится к целям.

4. Подключить к HamsterBot.Update():

5. Протестировать: запустить уровень, бот должен уклоняться от препятствий

### Этап 4: Напрыгивание на цели

**Цель:** Бот стремится напрыгнуть на SmallAlive (дорога) и SmallAlive/BigAlive (крыша).

**Файл:** `BotChainPlanner.cs` (расширение)
