# Account Service Manual Device Test Instructions

## Цель

Описать ручную проверку фичи аккаунта на реальных устройствах. Эти тесты нужны для того, что не покрывается EditMode и PlayMode: настоящий Unity Player Account login, мобильный lifecycle, сеть, отмена входа и поведение после переустановки.

## Что можно проверить уже сейчас

Текущий MVP проверяет identity flow:

- игра тихо создает guest identity;
- в настройках видно состояние аккаунта;
- игрок может привязать Unity Player Account;
- UI корректно показывает success, ошибку или already linked;
- после перезапуска linked state сохраняется.

Полное восстановление игрового прогресса между устройствами появится после `PlayerDataService + Cloud Save`. Сейчас проверяем только аккаунт и identity.

## Нужно ли второе Android-устройство

Для базового тестирования текущего AccountService MVP второе Android-устройство не обязательно. Достаточно одного телефона, чтобы проверить первый запуск, привязку, отмену, offline, перезапуск и переустановку.

Для полноценной проверки cross-device сценария второе Android-устройство желательно и фактически нужно. Без него можно частично имитировать сценарий через переустановку на одном телефоне, но это не проверяет реальное поведение на другом устройстве.

Когда появится `PlayerDataService + Cloud Save`, второй телефон понадобится для главного сценария:

```text
Телефон A: накопил прогресс -> привязал аккаунт -> Телефон B: вошел тем же аккаунтом -> увидел тот же прогресс
```

## Подготовка

1. Убедиться, что Unity Gaming Services project выбран правильно.
2. Проверить, что Unity Authentication включен в Unity Dashboard.
3. Проверить, что Unity Player Accounts включен и настроен.
4. Собрать development build для Android.
5. Установить билд на устройство.
6. Подготовить минимум два Unity Player Account:
   - основной тестовый аккаунт;
   - второй аккаунт для already linked / conflict сценариев.
7. Подготовить возможность быстро выключать сеть: airplane mode или отключение Wi-Fi/mobile data.

## Тест 1: первый запуск как guest

### Действия

1. Установить приложение на чистое устройство.
2. Запустить игру.
3. Дойти до меню.
4. Открыть настройки.

### Ожидаемый результат

- игра не требует login на первом экране;
- sign-in модалка не появляется автоматически;
- в настройках есть строка `Аккаунт`;
- статус `ГОСТЬ`;
- кнопка `СОХРАНИТЬ` доступна.

## Тест 2: успешная привязка аккаунта

### Действия

1. На экране настроек нажать `СОХРАНИТЬ`.
2. Пройти настоящий Unity Player Account login.
3. Вернуться в игру.

### Ожидаемый результат

- во время операции UI показывает состояние сохранения;
- после успешного login статус `ПРОГРЕСС СОХРАНЁН`;
- кнопка становится `СОХРАНЕНО` и disabled;
- игра не зависает и не требует повторного входа.

## Тест 3: перезапуск приложения после привязки

### Действия

1. Полностью закрыть приложение.
2. Запустить снова.
3. Открыть настройки.

### Ожидаемый результат

- статус остается `ПРОГРЕСС СОХРАНЁН`;
- кнопка сохранения disabled;
- guest state не возвращается.

## Тест 4: отмена login

### Действия

1. На чистом guest состоянии нажать `СОХРАНИТЬ`.
2. Когда откроется Unity Player Account login, отменить вход или закрыть окно.
3. Вернуться в игру.

### Ожидаемый результат

- игра не падает;
- статус показывает ошибку сохранения или остается guest в зависимости от фактического ответа Unity SDK;
- кнопка `СОХРАНИТЬ` снова доступна;
- повторная попытка возможна.

## Тест 5: offline при запуске

### Действия

1. Закрыть игру.
2. Отключить интернет.
3. Запустить игру.
4. Открыть настройки.

### Ожидаемый результат

- игра не падает на bootstrap;
- UI настроек открывается;
- статус аккаунта показывает ошибку сохранения или offline-состояние;
- после включения сети повторная попытка сохранения возможна.

## Тест 6: offline во время привязки

### Действия

1. Запустить игру с интернетом.
2. Открыть настройки.
3. Нажать `СОХРАНИТЬ`.
4. Отключить интернет во время login flow или перед подтверждением.

### Ожидаемый результат

- игра не зависает в вечном `СОХРАНЯЕМ...`;
- появляется ошибка;
- кнопка снова доступна;
- после включения сети можно повторить попытку.

## Тест 7: аккаунт уже используется

### Подготовка

1. На устройстве A или на текущей установке привязать Unity Player Account к одному player identity.
2. Получить новое guest состояние: чистая переустановка, очистка данных приложения или другой девайс.

### Действия

1. Запустить игру как новый guest.
2. Открыть настройки.
3. Нажать `СОХРАНИТЬ`.
4. Войти в тот же Unity Player Account, который уже привязан к другому player identity.

### Ожидаемый результат

- игра показывает `АККАУНТ УЖЕ ИСПОЛЬЗУЕТСЯ` или эквивалентную ошибку SDK;
- текущий guest player не помечается как linked;
- игра не теряет локальное guest состояние.

## Тест 8: переустановка на одном устройстве

### Действия

1. Привязать аккаунт.
2. Удалить приложение.
3. Установить приложение заново.
4. Запустить игру.
5. Попробовать сохранить прогресс через тот же Unity Player Account.

### Ожидаемый результат сейчас

- identity flow работает без падений;
- возможен конфликт already linked, потому что восстановление существующего linked account и merge локального guest-progress еще не финализированы;
- игровой прогресс может не восстановиться, потому что `PlayerDataService + Cloud Save` еще не реализованы.

### Ожидаемый результат после PlayerDataService

- игрок входит тем же аккаунтом;
- игра видит облачный прогресс;
- UI предлагает корректный restore/merge flow, если есть конфликт с локальным guest-progress.

## Тест 9: второй Android-телефон

Этот тест является обязательным для будущей проверки Cloud Save, но для текущего AccountService MVP он дополнительный.

### Действия сейчас

1. На телефоне A привязать Unity Player Account.
2. На телефоне B установить тот же билд.
3. Запустить игру как guest.
4. Попробовать сохранить прогресс через тот же Unity Player Account.

### Ожидаемый результат сейчас

- приложение не падает;
- SDK возвращает expected linked/conflict behavior;
- игра показывает ошибку или linked-состояние согласно фактическому сценарию;
- игровой прогресс между телефонами пока не обязан совпадать.

### Действия после PlayerDataService

1. На телефоне A накопить монеты/кристаллы/открыть прогресс.
2. Привязать аккаунт.
3. На телефоне B войти тем же аккаунтом.
4. Проверить восстановление прогресса.

### Ожидаемый результат после PlayerDataService

- прогресс на телефоне B совпадает с облачным прогрессом телефона A;
- конфликт локального прогресса обрабатывается по утвержденному UX.

## Что фиксировать при ручной проверке

- модель телефона;
- версия Android;
- тип сети: Wi-Fi/mobile/offline;
- версия билда;
- Unity account, который использовался;
- шаг, на котором произошла ошибка;
- скриншот UI;
- Android logcat около ошибки;
- фактический статус в настройках после каждого сценария.

## Stop conditions

Тест останавливаем и фиксируем баг, если:

- игра падает;
- кнопка остается disabled навсегда;
- статус зависает на `СОХРАНЯЕМ...`;
- после success статус не становится `ПРОГРЕСС СОХРАНЁН`;
- linked account после перезапуска снова отображается как `ГОСТЬ`;
- отмена login ломает UI или блокирует повторную попытку.
