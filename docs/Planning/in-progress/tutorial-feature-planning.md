# Tutorial Feature Planning

## Назначение

Документ фиксирует рабочий план фичи tutorial: пользовательский flow, список уроков, требования к уровню, runtime-управлению, вводу и UI.

Tutorial должен обучить игрока базовым и продвинутым действиям в контролируемой среде, где игра реагирует только на действие, ожидаемое текущим уроком.

## Статус

In progress.

## Цели

- Провести игрока через набор коротких уроков по основным действиям.
- Показывать понятную инструкцию ровно в момент, когда действие нужно выполнить.
- Блокировать нерелевантный ввод во время обучения.
- Дать возможность пропустить tutorial.
- Дать возможность перепройти tutorial позже через пункт меню `Обучение`.

## Не входит в текущий план

- Финальная полировка визуальных ассетов tutorial.
- Полная переработка onboarding flow.
- Баланс обычных уровней вне tutorial.
- Детальная реализация магазина и скинов, кроме tutorial-сценария "купить и надеть скин".

## Базовый UX Flow

1. Запускается tutorial level.
2. На экране отображается заголовок текущего урока, например `Обучение 1 - увернуться от препятствия`.
3. Внизу экрана отображается кнопка `Пропустить обучение`.
4. Игра принимает только действия, разрешенные текущим уроком.
5. Хомяк добегает до tutorial-ситуации.
6. Игра останавливается.
7. Экран затемняется, кроме области нужного действия.
8. В подсвеченной области появляется анимация пальца или аналогичная подсказка действия.
9. В центре экрана показывается облачко с короткой инструкцией, например `Тапни, чтобы увернуться`.
10. Игрок выполняет ожидаемое действие.
11. Игра продолжает движение до следующей tutorial-ситуации.
12. После последнего урока tutorial завершается и игрок возвращается в основной flow.

## Правила Поведения Tutorial

- Каждый урок должен обучать одному основному действию или одному понятному составному действию.
- Во время активного урока игра должна игнорировать все действия, кроме разрешенного.
- Остановка игры происходит перед моментом, когда игрок должен принять решение.
- Подсветка должна выделять область взаимодействия, а не всю игровую ситуацию.
- Инструкция должна быть короткой и императивной: `Тапни, чтобы увернуться`, `Прыгни через препятствие`.
- Пропуск tutorial должен быть доступен с экрана каждого урока.
- Завершенный или пропущенный tutorial должен оставаться доступным для повторного прохождения из меню.

## Tutorial Level

Tutorial должен использовать отдельный уровень.

Требования к уровню:

- Каждая tutorial-ситуация собирается отдельным паттерном.
- Паттерны разделены большим расстоянием, чтобы на экране одновременно была только одна tutorial-ситуация.
- Расстояние между паттернами подбирается так, чтобы прошлая ситуация уже ушла за экран, а следующая сразу появилась.
- Паттерны должны быть стабильными и предсказуемыми: без случайных элементов, которые могут сломать обучение.
- Для каждого урока нужен понятный trigger point, в котором tutorial controller останавливает игру и показывает подсказку.

## Список Уроков

| # | Урок | Ожидаемое действие | Черновая инструкция |
|---|---|---|---|
| 1 | Увернуться от препятствия | Tap / смена линии | `Тапни, чтобы увернуться` |
| 2 | Перепрыгнуть препятствие | Jump | `Прыгни через препятствие` |
| 3 | Напрыгнуть на препятствие | Jump with landing on obstacle | `Прыгни на препятствие сверху` |
| 4 | Использовать super jump для перепрыгивания | SuperJump | `Сделай суперпрыжок, чтобы перелететь дальше` |
| 5 | Использовать super jump для напрыгивания | SuperJump with landing on obstacle | `Сделай суперпрыжок и приземлись сверху` |
| 6 | Запрыгнуть на крышу | JumpOnRoof / RoofJump entry | `Запрыгни на крышу` |
| 7 | Перепрыгнуть с крыши на крышу | RoofJump / SuperRoofJump | `Прыгни на следующую крышу` |
| 8 | Напрыгнуть с крыши | JumpFromRoof on obstacle | `Прыгни с крыши на препятствие` |
| 9 | Купить и надеть скин Electric Strike | Shop action | `Купи и надень скин с молнией` |
| 10 | Применить супер удар | Super hit action | `Примени супер удар` |

### Урок 9: Electric Strike Skin

Сценарий идет после завершения gameplay-уроков 1-8:

1. Показать существующую win modal с сообщением `Вы освоили управление` и коротким текстом про учебные кристаллы.
2. Подсветить кнопку перехода в меню.
3. В меню подсветить кнопку раздела скинов.
4. В разделе скинов открыть Electric Strike skin (`id = 2`, скин с молнией).
5. Подсветить кнопку покупки, выдать только tutorial sandbox-кристаллы для учебной покупки.
6. После покупки подсветить эту же кнопку для надевания.
7. После надевания завершить tutorial и показать финальное окно `Скин надет` / `Суперудар открыт`.

Экономика урока 9 работает в sandbox:

- tutorial стартует с default-скином независимо от реального сохранения игрока;
- реальные `PurchasedSkinIds`, `AppliedSkinId`, монеты и кристаллы не изменяются;
- если Electric Strike уже куплен в реальном сейве, tutorial все равно показывает учебный сценарий покупки;
- после выхода из tutorial runtime-состояние ресурсов и скинов восстанавливается из реального `PlayerData`;
- порядок отображения скинов: default, Electric Strike, затем остальные.

## Архитектурные Компоненты

### Tutorial Game Controller

Класс, управляющий состоянием tutorial во время gameplay.

Ответственность:

- хранить текущий урок;
- знать, какое действие разрешено в текущем уроке;
- останавливать и продолжать игру в tutorial trigger point;
- принимать факт успешного tutorial-действия;
- переводить tutorial к следующему уроку;
- завершать tutorial или обрабатывать skip.

### Tutorial Input Gate

Компонент, который ограничивает ввод во время tutorial.

Ответственность:

- пропускать только действия, ожидаемые текущим уроком;
- игнорировать нерелевантные действия;
- не ломать обычный input flow вне tutorial;
- поддерживать составные действия вроде super jump, если они требуют последовательности input events.

### Tutorial UI Controller

Класс, управляющий tutorial-интерфейсом.

Ответственность:

- показывать заголовок урока: `Обучение 1 - увернуться от препятствия`;
- показывать облачко с короткой инструкцией;
- показывать кнопку `Пропустить обучение`;
- затемнять экран;
- оставлять незатемненной область нужного действия;
- показывать анимацию пальца или подсветку кнопки/области действия;
- скрывать tutorial UI после успешного действия.

### Tutorial Content/Data

Нужен формат данных, который связывает уроки, паттерны, разрешенные действия, тексты и trigger points.

Черновые поля:

- tutorial step id;
- title;
- instruction text;
- expected action;
- allowed input actions;
- pattern id или marker id;
- pause trigger condition;
- highlight target;
- completion condition;
- next step id.

## UI Требования

- Заголовок текущего урока должен быть постоянно виден во время шага.
- Кнопка `Пропустить обучение` должна быть доступна внизу экрана.
- Инструкционное облачко появляется только в момент остановки перед действием.
- Затемнение не должно закрывать подсвеченную область действия.
- Анимация пальца должна явно показывать нужный gesture.
- Для действий на кнопках можно использовать подсвечивание кнопки вместо области тапа.

## Меню

После завершения или пропуска tutorial игрок должен иметь возможность запустить его снова.

Требование:

- добавить пункт меню `Обучение`;
- пункт меню запускает tutorial level с первого урока;
- состояние "tutorial уже пройден" не должно скрывать возможность перепрохождения.

## Открытые Вопросы

- Как именно runtime должен ставиться на паузу: глобальная пауза мира, остановка спавна/движения или специальный tutorial freeze?
- Как tutorial controller будет находить trigger point: через pattern marker, obstacle marker, расстояние до obstacle или отдельные tutorial triggers?
- Как корректно обучать super jump: отдельной двухтаповой подсказкой или через существующий input gesture?
- Что именно означает `супер удар` в терминах текущих runtime-команд и UI?
- Должен ли tutorial позволять ошибку и повторять ситуацию, или ошибка должна быть невозможна из-за остановки и input gate?
- Как сохранять факт завершения tutorial и как отличать skip от полного прохождения?
