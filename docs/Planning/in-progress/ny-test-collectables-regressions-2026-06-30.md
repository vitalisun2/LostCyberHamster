## Confirmed regressions

### REG-2026-06-30-001 - test_collectables_05 skips roof life and collects ground bonuses

- `type`: `Bot architecture / decision logic`
- `level`: `01_New_York/Morning/test_collectables`
- `pattern`: `test_collectables_05`
- `case`: `should ignore all bonuses for collecting life on roof if enough energy for jump on roof`
- `expected`: collect `Life` 1 time; do not collect `Coin`, `Crystal`, `Energy`.
- `actual`: `Life` 0; collected `Coin` 1, `Crystal` 1, `Energy` 1; run finished `WIN`, stars=2.
- `expected source`: `LostCyberHamster/Assets/Content/locations/level_design_templates/levels/PatternsCollection.json`, pattern `test_collectables_05` description and obstacle set; semantic assertion generated by `tools/invoke_run_all_test_levels.ps1`.
- `repro`: `.\tools\invoke_run_all_test_levels.ps1 -TimeoutSeconds 180`.
- `artifacts`:
  - Batch log: `C:\Personal\crystal-wave\repos\LostCyberHamster_2025\Temp\all_test_levels_2026-06-30_160414\01_New_York_Morning_test_collectables.txt`.
  - Diagnostic repro log: `C:\Personal\crystal-wave\repos\LostCyberHamster_2025\Temp\test_collectables_diag_2026-06-30_200605\diagnostic_log.txt`.

Root cause: `test_collectables_05` spawns while the bot is still on the previous bottom roof, not after it has returned to ground. The diagnostic repro captured the exact spawn/replan state: `[Bot TEMP_DIAG] pattern_spawn patternIndex=8 pattern=test_collectables_05 state=RoofRun lane=bottom lives=2 energy=91`, followed by `[Bot TEMP_DIAG] replan_capture reasons=SpawnPattern state=RoofRun lane=bottom isOnRoof=True roofSupport=-770964 lives=2 energy=91 currentActions=0`. In this state `ActionGenerator.CollectOppositeCollectibleRouteActions` selects the roof path entry strategy when `planningState.Hamster.IsOnRoof` is true (`ActionGenerator.cs:198-220`), while `CollectibleDecisionPointDetector.CanDetectRoofCollectibles` is scoped to current `RoofRun`/`IsOnRoof` planning (`CollectibleDecisionPointDetector.cs:237-249`) and `RouteDecisionPointDetector.GetRoofRouteStartIndex` treats the current passive roof chain as the active route context (`RouteDecisionPointDetector.cs:159-181`). There is no model for "finish the current roof run, then plan a ground `SwitchLane -> JumpOnRoof -> PassiveCollect[Life]` route to the next roof-life reward". After the roof naturally ends, `RuntimeBotController` only requests replans from execution results and explicit events (`TickBot` + `RequestReplanForExecutionResult`, `RuntimeBotController.cs:428-452` and `RuntimeBotController.cs:1100-1107`); the automatic `RoofRun -> Run` state transition does not trigger a new replan. The result is an empty plan for the reward pattern, and the hamster later reaches the ground collectibles in `Run`: the repro log records `collectableCoin`, `collectableCrystal`, and `collectablePizza` pickups at `20:06:00.940..20:06:02.302` with `lives=2`, while no `Bot PLAN` line is emitted after the `test_collectables_05` spawn.

Expected is reachable by contract because the same test level immediately proves the required route shape on `test_collectables_04`: after scripted life loss to `lives=2`, the bot plans `SwitchLane -> JumpOnRoof -> PassiveCollect[Life:1]` and completes `PassiveCollect Life` on the roof. Energy starvation is excluded: `test_collectables_05` has `energy=91` at replan capture and reaches 95 before the first ground pickup, while `JumpOnRoof` costs 10. Level geometry/dead end is excluded: no `[Bot DAMAGE]` or `[TEST RESULT] FAIL` markers are present, and the failure is a semantic route choice with `WIN` result rather than physical blockage. Test expectation/source issue is excluded because the pattern description is explicit and the semantic parser checks exactly the collectable contract encoded by the fixture. Branch scoring is excluded because the failing repro produces no roof-life branch after `test_collectables_05` spawn; there is no competing candidate that loses ranking.

Architectural recommendation: make the planning layer own transitions across short-lived movement states instead of relying only on spawn/action-completion replans. The fix should either model an imminent roof exit as a projected planning state that can generate the subsequent ground `SwitchLane -> JumpOnRoof -> PassiveCollect` branch, or introduce a general replan trigger when movement state changes from roof traversal to ground run. Do not solve this by special-casing `test_collectables_05`, changing collectible thresholds, or forcing fallback actions for this fixture.
