# Normalize roof gap idea

## Контекст

Сейчас passive RoofRun использует общий порог `Consts.GetRoofRunPassiveContinuationGap(...)`.
При текущих настройках хомяк может продолжать RoofRun через gap между roof-platforms, который технически еще проходим, но визуально уже выглядит слишком широким.

Проблема не в самом факте проходимости, а в промежуточной зоне:

- крыши уже не выглядят достаточно близкими для естественного перебегания;
- но runtime все еще считает gap допустимым для passive RoofRun;
- из-за этого уровень может выглядеть визуально неаккуратно: игрок видит "почти провал", но хомяк проходит без прыжка.

## Идея

Найти range gap-значений между крышами, который выглядит "ни туда ни сюда":

- нижняя граница: gap уже визуально выглядит слишком широким для спокойного перебегания;
- верхняя граница: gap все еще находится внутри текущего runtime-порога passive RoofRun;
- за верхней границей gap уже должен восприниматься как настоящий провал, через который нужен прыжок.

Этот range можно использовать в Level Tilemap Editor для нормализации roof gaps.

## Возможный editor tool

Добавить кнопку в Level Tilemap Editor, рабочее название:

- `Normalize Roof Gap`
- `Normalize In-Between Roof Gap`
- `Normalize Roof In-Between Gap`

Поведение кнопки:

1. Найти соседние roof-platforms на одной линии.
2. Посчитать фактический gap между визуальными краями крыш.
3. Если gap попадает в найденный "некрасивый" in-between range, нормализовать его одним из способов:
   - сдвинуть следующую крышу ближе, к красивому passable gap;
   - или раздвинуть дальше, к явному fail gap, где passive RoofRun уже невозможен и нужен прыжок.

## Что надо продумать

- Как выбрать визуальную нижнюю границу in-between range: по тестовым уровням, скриншотам, ручной настройке или через editor preview.
- Должна ли нормализация всегда двигать следующую крышу ближе, или решение должно зависеть от свободного места, соседних obstacles и intended route.
- Нужно ли делать режимы: `Pull Closer`, `Push Apart`, `Auto`.
- Нужно ли нормализовать только выбранный pattern или весь открытый level/template.
- Нужно ли после нормализации сразу пересчитывать/показывать, стал ли gap passable или fail с точки зрения текущего runtime threshold.

## Цель

Не менять текущую отлаженную механику passive RoofRun и не переделывать уровни вручную.
Вместо этого добавить editor-помощник, который найдет визуально спорные roof gaps и приведет их к явно читаемому состоянию: либо красиво близко, либо явно требует прыжка.
