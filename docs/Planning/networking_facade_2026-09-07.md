# Networking: реализация и ручная проверка

Дата: 2026-09-07. Ветка: `integration/unity-live`.

## Результат

Добавлены два C#-класса: `GameNetworkFacade` и `NetworkingDevToolsScreen`. Фасад оборачивает существующие SDK-адаптеры, использует существующие интерфейсы и хранит DEV-режим офлайна. Формат игровых сохранений и экономика сохранены.

| Подсистема | Подключение |
|---|---|
| UGS | Фоновая инициализация через фасад |
| Аккаунт | Гостевой вход, Player Account flow, привязка, вход существующего аккаунта, имя и unlink через фасад |
| Облако | Общий `ICloudSaveGateway` для синхронизации, конфликтов и восстановления аккаунта |
| Рейтинг | Неделя, top, собственный результат и versioned submit через фасад |
| Реклама | Общий `IRewardedAdProvider`; готовое видео допускается к показу при офлайне |
| XP testing tool | Завершение уровня и production FIFO; подтверждённые XP начисляет координатор |

`ProjectInstaller` связывает существующие интерфейсы с одним `GameNetworkFacade.Instance`. Локальные SDK-статусы, выход и выбор credentials доступны независимо от переключателя. Статусы двух систем авторизации делегируются раздельно.

Фасад проверяет режим перед каждым сетевым шагом. Дополнительное имя после входа и собственная позиция после top выполняются отдельно. Ошибка имени сохраняет успешную авторизацию. Уже отправленные запросы сохраняют обработку ответа с исходными проверками владельца, поколения, ревизии и недели.

При включении доступа используется существующий `OnlineServicesCoordinator.Resume()`. Локальные checkpoints, FIFO, повторы записи на диск и применение сохранённого подтверждения рекорда продолжаются офлайн. Применение подтверждённых XP проверяет durable владельца, конфликт и смену профиля; новая авторизация для него не требуется.

DEV Full Reset отвязывает текущую подтверждённую сессию одним запросом. Credentials очищаются после ACK. Потерянный ACK сохраняет credentials и запускает штатное уточнение сессии; автоматическая очистка по предположению о результате не выполняется.

## Управление

1. Открыть `DEV → Networking`.
2. Нажать `Turn off network`. Статус: «Симуляция офлайна включена».
3. Закрыть панель. Кнопка открытия показывает `DEV OFF` и выделена цветом.
4. Для восстановления открыть Networking и нажать `Turn on network`.

Режим хранится в `PlayerPrefs`, ключ `DevTools.Networking.ForcedOffline`, и читается до первого сетевого старта. Перезапуск DEV-сборки сохраняет режим. Новая установка разрешает доступ. Релиз игнорирует ключ и не содержит управление симуляцией.

Переключатель управляет обращениями игры. Analytics, доставка диагностических логов и внутренний фоновый трафик SDK сохраняют текущий путь. Разрешение доступа означает возможность попытки запроса; успешную синхронизацию подтверждает сервер.

## Выполненная проверка

- Проверены прямые SDK-вызовы и их потребители: активные обращения находятся в фасаде и пяти его адаптерах. Старый DEV submit и создание отдельного leaderboard-сервиса при открытии меню удалены.
- Выполнен статический review DI, поздних callbacks, отмены рекламной подготовки, владельца наград, синхронного события постановки в FIFO и очистки подписок.
- Новые `.meta` созданы Unity через импорт исходников.
- Выполнен штатный `regenerate_project_files`: `LegacyStyleProjectGeneration.Sync()`.
- `dotnet build Assembly-CSharp.csproj --no-restore --nologo -v:minimal`: **0 ошибок, 21 предупреждение**. Предупреждения относятся к существующим ссылкам сборок, nullable, старому API, неawait-вызовам, полям каталогов и Unity message signatures.
- Unity CLI 1.0.0.20008 обнаруживает Editor, но выполнение команд несовместимо с Pipeline 0.5.0-exp.1 (`too old to parse command lines`). Та же существующая операция regeneration выполнена через Unity MCP. Версии пакетов сохранены.

Проверка поведения в Play Mode и на Android в этой задаче не запускалась. APK не собирался. Ниже — приёмка для пользовательского прогона.

## Ручная приёмка

Использовать DEV-сборку с этими изменениями. Для облака и рейтинга — тестовый аккаунт. Сначала выполнить обычный онлайн-запуск, дождаться готовности аккаунта и рейтинга; записать баланс, уровень, XP и видимый прогресс. Для подтверждения отправки офлайн-рекорда серверная неделя должна быть получена до попытки.

| № | Действия | Критерий |
|---|---|---|
| 1 | Отключить доступ; открыть рейтинг, запросить изменение имени и вход/привязку | Понятная недоступность; браузерный вход не начинается; остальные действия доступны |
| 2 | При выключенном доступе завершить процесс обычным способом ОС и снова запустить | Меню открыто, прежний прогресс восстановлен, `DEV OFF` виден сразу |
| 3 | Офлайн завершить уровень, купить за игровые ресурсы, забрать награду задания; перезапустить | Баланс, прогресс и отметки получения сохранены согласованно |
| 4 | Офлайн открыть рейтинг с ранее полученным кэшем | Кэш доступен с временем получения; сеть не требуется для его чтения |
| 5 | Онлайн нажать `Prepare New Record`; затем отключить доступ и выполнить `Complete Next Level` | Уровень сохранён; видны runId и «Ожидает отправки»; рекордные XP ещё не начислены |
| 6 | Включить доступ после № 5 | Тот же runId проходит production FIFO; при доказанном улучшении receipt и XP сохранены один раз |
| 7 | Офлайн нажать `Prepare New Record`, затем обычное завершение уровня | Подготовка сообщает недоступность; обычное завершение работает. Неизвестная серверная неделя даёт «Только на устройстве» |
| 8 | Начать подготовку рекламы, отключить доступ до Show | Подготовка завершена, игра доступна, поздняя загрузка сама не запускает показ |
| 9 | Если ролик уже загружен, отключить доступ и запросить показ | SDK получает готовый ролик; подтверждённый просмотр даёт одну награду |
| 10 | Отключить доступ при незавершённом чтении top или облака | Следующий запрос операции блокируется; локальные данные и кэш сохранены |
| 11 | Отключить доступ после отправки облака/рекорда до ответа | ACK исходной операции обрабатывается; новые локальные изменения остаются pending |
| 12 | При существующем конфликте отключить доступ, выбрать «Позже», перезапустить | Локальная игра доступна; конфликт и отсрочка сохранены |
| 13 | Быстро переключить режим несколько раз, закрыть/открыть DEV, вернуть приложение из фона | Один актуальный режим, корректная кнопка; фоновые повторы не дублируют отправку и награды |
| 14 | В Editor остановить и снова запустить Play Mode с включённой симуляцией | Настройка сохранена, старые подписки и рекламные запросы не переходят в новую сессию |
| 15 | В релизной сборке с сохранёнными данными DEV-установки | DEV-переключатель отсутствует, его старый ключ не запрещает сетевые попытки |

Сценарии 10–11 засчитывать только при подтверждённом незавершённом запросе. Быстрый ответ до переключения не проверяет эту гонку. Кнопка не моделирует потерю ответа или задержку сервера.

Для рекламы, полностью перекрывающей DEV-меню, отключение во время самого видео проверяется внешним отключением связи на устройстве. После возврата ожидается обработка результата SDK и одна сохранённая награда. Отсутствующий ролик или неподтверждённый просмотр награду не создают.

Диагностика режима: канал `STAB`, строки `[NETWORK] forcedOffline=...` и `[NETWORK] blocked=<операция>`. Повтор отказа одной операции объединяется до следующей смены режима. Логи не содержат токенов и полного содержимого сохранений.
