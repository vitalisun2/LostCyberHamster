# Unity-интеграция UI-ассетов

Обязательный порядок для новых UI-экранов Lost Cyber Hamster.

## Перед работой

1. Прочитать этот документ и brief конкретного экрана.
2. Найти утверждённый экранный эталон.
3. Проверить текущую UI-архитектуру и доступные ресурсы `shared`.
4. Подготовить и проверить визуальные ассеты.
5. После этого интегрировать экран в Unity.

## Хранение

- Финальные подготовленные PNG: `C:\Personal\ChatGpt\WorkOnScreens\Prepared for Unity Integration\<Screen>/`.
- Общие подготовленные PNG: `C:\Personal\ChatGpt\WorkOnScreens\Prepared for Unity Integration\Shared/`.
- Игровые спрайты экрана: `LostCyberHamster/Assets/Content/ui/sprites/<screen>/`.
- Общие игровые спрайты: `LostCyberHamster/Assets/Content/ui/sprites/shared/`.
- Папки `Prepared for Unity Integration` содержат готовые UI-ассеты. Экранные эталоны и рабочие исходники хранятся отдельно в рабочих папках экрана.
- Экранные эталоны и рабочие исходники остаются вне Unity. В Unity попадает только финальный игровой набор.
- Переиспользуемый ресурс хранится в `shared` один раз. Экраны используют его без локальных копий.

Имена игровых файлов — `lower_snake_case`, по назначению элемента.

## Подготовка ассетов

- Отдельный PNG получает каждая UI-часть, которая меняет состояние, размер, содержимое или действие независимо.
- Текст, числа, прогресс, цены, статусы и другие данные выводятся из кода.
- Панели, плашки, слоты и кнопочные оболочки с сохраняемыми углами готовятся под 9-slice, где форма допускает растяжение.
- Цельный фон готовится отдельным непрозрачным ассетом без UI-элементов.
- Прозрачные элементы имеют чистый alpha без цветного matte, halo и фоновых пикселей.
- Один визуальный ресурс используется во всех подходящих размерах и состояниях, если качество и смысл совпадают.

## Импорт в Unity

Базовые настройки UI-текстур:

- Texture Type: `Sprite (2D and UI)`.
- Sprite Mode: `Single`.
- sRGB: включён.
- Generate Mip Maps: выключен.
- Wrap Mode: `Clamp`.
- Filter Mode: `Bilinear`.
- Alpha Is Transparency: включён для RGBA-ассетов.
- AssetBundle: `ui`.

Настройки по типу:

- Фон: `Full Rect`, без alpha, `Max Size` не меньше исходного рабочего разрешения.
- 9-slice-оболочка: `Full Rect`, проверенные Sprite Borders, прозрачность по исходнику.
- Иконка или cutout: прозрачность включена, границы и пустые поля минимальны.
- Эталон экрана: хранится вне Unity и служит только для сверки.

Дополнительные Addressables-настройки сохраняют действующий контракт загрузки экрана и его зависимостей.

## Интеграция

- Встраивать новый вид в существующие screen controllers, UXML/USS, сервисы и навигацию проекта.
- Presentation-логика остаётся в UI-слое. Соблюдать SOLID, DRY и KISS.
- Общие визуальные и поведенческие компоненты переиспользуются.
- Ландшафтная вёрстка сохраняет композицию, относительные отступы и safe area на поддерживаемых соотношениях сторон.
- Кнопки и навигационные элементы сохраняют утверждённое назначение и текущие маршруты.
- Художественный спрайт задаёт внешний вид; вёрстка отвечает за размер, позицию и адаптивность.

## Проверка

1. Проверить alpha на светлом, тёмном и шахматном фоне: края чистые, matte и halo отсутствуют.
2. Проверить каждую 9-slice-оболочку в исходном, узком и широком размере: углы, контур и объём сохраняются.
3. Собрать экран и сверить композицию с утверждённым эталоном.
4. Проверить динамические данные, состояния, действия кнопок, маршруты и поддерживаемые landscape-размеры.
5. Выполнить независимый visual QA после исправлений.
