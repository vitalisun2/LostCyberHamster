# 04. Очередь checkpoint-снимков

## Результат

Каждый успешный локальный checkpoint обновляет облако последним полным снимком без ожидания сети. Зависит от задачи 03.

## Что сделать

- Подключить `CloudSyncService` к успешному `PlayerProgressCommitter.Commit(reason)`.
- После локального сохранения создать глубокую неизменяемую копию текущего `PlayerData`.
- При свободном сервисе сразу начать её отправку.
- Во время активной отправки продолжать её без изменений, а новый снимок хранить как единственный pending.
- Каждый следующий checkpoint заменяет только pending-снимок.
- После активной отправки сразу отправить самый новый pending.
- Подтверждение старой отправки не должно очистить или пометить сохранённым более новый pending.
- Работать только после определения связанного аккаунта и только с его `PlayerId`.

## Проверка

Fake gateway удерживает первую отправку. Несколько новых checkpoint не меняют её данные и оставляют только последний pending; после завершения первой отправляется последний. Отдельно проверяются порядок local-first, отсутствие ожидания gateway, защита нового pending от старого ответа и владелец.
