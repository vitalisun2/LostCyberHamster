# 01. Контракт полного снимка и локальное сохранение

## Цель

Зафиксировать один целостный снимок всей `PlayerData` для текущего UGS `PlayerId` и сначала надёжно сохранять его локально. Это базовый проверяемый кусок без облачной отправки.

## Depends on

- Нет.

## Feature links

- [Первый облачный снимок](../features/01-first-cloud-snapshot.md)
- [Автоматическая синхронизация](../features/03-automatic-checkpoint-sync.md)

## Scope

- Один атомарный снимок всей игры, без полевого сохранения.
- Владелец снимка — текущий UGS `PlayerId`.
- Локальная запись и чтение полного снимка.
- Данные, необходимые следующим задачам для определения актуальности снимка.

## Audit-based предполагаемые components

- `PlayerData` и существующие progress/economy/runtime storages как источник состояния.
- `GameDataManager` и его текущий local save/load path.
- Legacy cloud-методы `GameDataManager` только как граница будущего удаления; в этой задаче они не расширяются.

## Минимальный алгоритм

1. Собрать актуальное состояние игры в одну целую `PlayerData`.
2. Связать снимок с текущим `PlayerId`.
3. Атомарно сохранить снимок локально.
4. Прочитать его обратно как один целый объект без выборочного объединения полей.
5. Не запускать облачную операцию в этой задаче.

## Acceptance

- Локальный round-trip сохраняет прогресс, экономику и владельца снимка.
- Частично записанный снимок не применяется.
- Снимок одного `PlayerId` не принимается как состояние другого.
- Gameplay не зависит от доступности сети.

## Out of scope

- Облачная запись и чтение.
- Account link/sign-in integration.
- Очередь, reconnect, конфликты и sync UI.

## KISS и сигналы рефакторинга

- Начать с существующих `PlayerData` и local path `GameDataManager`, без нового framework.
- Если построение снимка дублируется в нескольких call sites — предложить одно переиспользуемое место и дождаться одобрения.
- Если `GameDataManager` начинает одновременно собирать снимок, хранить его и управлять облаком — предложить разделение ответственности до следующего усложнения.
- Если для снимка приходится передавать много отдельных значений — предложить DTO и дождаться одобрения.
