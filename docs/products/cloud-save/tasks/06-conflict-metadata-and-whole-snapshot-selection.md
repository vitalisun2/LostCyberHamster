# 06. Выбор при конфликте устройств

## Результат

При независимом изменении двух устройств синхронизация ждёт выбор игрока. Выбранный целый снимок становится локальной и облачной версией. Зависит от задачи 05.

## Что сделать

- Определять конфликт, когда локальная pending-ветка и облако изменились после общей базовой revision.
- Простое отставание одной стороны разрешать без модалки. Вход в существующий аккаунт использует восстановление задачи 03.
- Отдавать UI данные конфликта из `CloudSyncService`; окно открывает UI в безопасной точке.
- Показать две карточки: пройденные уровни из `PlayerData.Progress`, постоянные очки, монеты, кристаллы и время.
- Оставить действия `Выбрать облачное` и `Выбрать локальное`.
- Облачный выбор проверить и атомарно применить локально. Локальный выбор записать поверх актуальной cloud revision.
- В обоих случаях использовать один полный снимок.

Пока постоянные очки не хранятся в `PlayerData`, строка очков не берётся из runtime static-данных.

## Проверка

Unit-тесты отличают две ветки от простого отставания и входа в аккаунт. Выбор применяет один целый снимок, повреждённое облако не применяется. UI-model содержит одинаковые поля карточек и два действия.
