# 03. Восстановление существующего аккаунта

## Результат

После подтверждённого входа облачный прогресс целиком и атомарно заменяет временного гостя. Зависит от задачи 02.

## Что сделать

- После смены `PlayerId` загрузить снимок нового владельца.
- Проверить владельца и данные через `PlayerDataValidator`.
- Добавить или переиспользовать одну операцию `GameDataManager` для атомарной замены текущего и локального `PlayerData`.
- После успеха принять cloud revision как новую базу синхронизации.
- Вернуть account flow явный результат при ошибке, отсутствии снимка или неверном владельце.

До успешного применения гостевые данные не сохраняются под новым владельцем.

## Проверка

Unit-тесты проверяют полную замену валидным снимком. Ошибка загрузки, чужой владелец и отклонение валидатором сохраняют прежнее состояние; гостевые поля не попадают в аккаунт.
