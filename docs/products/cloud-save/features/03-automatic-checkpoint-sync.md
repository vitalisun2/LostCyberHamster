# 03. Автоматическая синхронизация сохранений

## Суть

Каждый checkpoint сначала сохраняет текущий `PlayerData` локально. Затем игра делает глубокую неизменяемую копию именно этого состояния и отправляет её в фоне.

## Как работает

1. Checkpoint завершает локальное сохранение текущего `PlayerData`.
2. Игра сразу создаёт его глубокую копию. Следующие изменения игры её не меняют.
3. Если отправки нет, снимок уходит сразу.
4. Если отправка уже идёт, она продолжается. Новый снимок становится единственным pending.
5. Следующий checkpoint заменяет только pending-снимок; активная отправка не меняется.
6. После завершения активной отправки сервис отправляет самый новый pending, если он есть.
7. Ошибка облака не отменяет локальный commit.

## Проверка

Пока первый снимок отправляется, несколько новых checkpoint оставляют в pending только последний. Первая отправка получает исходные данные, затем отправляется последний pending-снимок.
