# Cloud Save MVP

## Что это

Cloud Save хранит в UGS один полный снимок `PlayerData`, связанный с текущим `PlayerId`.

Игра всегда работает с локальным сохранением. Облако защищает прогресс после удаления игры и переносит его между устройствами.

## Задача

- Восстанавливать прогресс после переустановки или смены устройства.
- Продолжать игру на другом устройстве через тот же аккаунт.
- Сохранять игру без ожидания сети.
- Не смешивать части разных сохранений и не дублировать награды или покупки.

## Аналоги

- [Royal Match](https://dreamgames.helpshift.com/hc/en/3-royal-match/faq/33-how-to-save-my-progress/?l=en&p=all): онлайн-сохранение восстанавливается через связанный Google или Facebook.
- [Subway Surfers](https://sybo.helpshift.com/hc/en/5-subway-surfers/faq/116-lost-progress/?p=ios): тот же Google, Apple или Facebook возвращает Online Save.
- [Candy Crush](https://community.king.com/en/blog/kb/articles/393-can-i-move-my-game-progress-onto-a-new-device): аккаунт переносит основной прогресс и золото, а часть данных остаётся на устройстве.

Общий подход: игра сохраняется локально, аккаунт включает фоновую синхронизацию, новое устройство загружает облачный прогресс. UI нужен при входе, ошибке или конфликте.

## Наш MVP

В облаке хранится полный игровой `PlayerData`:

- пройденные уровни;
- постоянные очки;
- монеты и кристаллы;
- открытые скины;
- квесты и storyline;
- состояние туториала;
- остальные поля игрового прогресса.

Язык, звук и другие настройки устройства остаются локальными.

Основные правила:

- Сначала проходит локальный commit, затем создаётся его неизменяемая копия для облака.
- Сеть не задерживает запуск, уровень, награду или покупку.
- Синхронизация работает только для связанного аккаунта.
- В облако уходит один полный снимок. Поля разных снимков не объединяются.
- После связывания гостя его прогресс становится первой облачной версией без смены `PlayerId`.
- При входе в существующий аккаунт его облачный прогресс заменяет временного гостя после предупреждения.
- Неудачная отправка остаётся pending и повторяется позже.
- Обычная синхронизация незаметна. Settings показывает статус; отдельный UI появляется при конфликте или ошибке.

## Готовая основа

- `PlayerData` содержит полный игровой прогресс.
- `PlayerProgressCommitter` создаёт смысловые локальные checkpoint.
- `GameDataManager` загружает и сохраняет локальные данные.
- `PlayerDataValidator` проверяет данные; локальное сохранение имеет backup.
- Account foundation создаёт гостя, связывает его и возвращает существующий аккаунт со стабильным UGS `PlayerId`.
- Подключён UGS Cloud Save `3.2.0`.

Cloud Save runtime создаётся поверх этой основы.

## Основные сценарии

### Обычная игра

1. Игра загружает локальный `PlayerData`.
2. Checkpoint сохраняет текущее состояние локально и создаёт глубокую копию этого состояния.
3. Свободная очередь сразу отправляет снимок. Активная отправка завершается, а последний новый снимок ждёт следующим.
4. Ошибка не мешает игре; последняя версия повторяется позже.

### Первое связывание гостя

1. Игрок связывает гостя с аккаунтом.
2. `PlayerId` остаётся прежним.
3. Текущий прогресс локально сохраняется и загружается как первая облачная версия.

### Новое устройство или переустановка

1. Игрок выбирает вход в существующий аккаунт.
2. UI предупреждает о замене временного гостевого прогресса.
3. После подтверждения игра загружает снимок аккаунта.
4. `PlayerDataValidator` проверяет снимок.
5. Валидный снимок целиком и атомарно становится локальным прогрессом.

Ошибка загрузки, чужой владелец или отклонённые данные оставляют текущий локальный прогресс без изменений.

## Конфликт двух устройств

Конфликт появляется, когда два устройства независимо изменили одну облачную версию:

1. A и B получили revision 10.
2. A играет offline и создаёт ветку 11A.
3. B загружает ветку 11B.
4. A выходит online с другой допустимой веткой.

Автоматический merge может задвоить валюту, награды или покупки. Выбор только по времени тоже может удалить более ценный прогресс. Поэтому игрок выбирает один целый снимок.

Вход временного гостя в существующий аккаунт не считается конфликтом: после подтверждения используется облачный прогресс аккаунта.

### Модалка конфликта

Модалка открывается в меню или после уровня.

```text
┌───────────────────────────────────────────────────────────┐
│              НАЙДЕНЫ ДВА СОХРАНЕНИЯ                      │
│       Выберите прогресс, который хотите оставить          │
│                                                           │
│ ┌────────────────────────┐  ┌────────────────────────┐    │
│ │ ОБЛАЧНОЕ               │  │ НА ЭТОМ УСТРОЙСТВЕ    │    │
│ │ Пройдено уровней: 18   │  │ Пройдено уровней: 15  │    │
│ │ Очки: 12 450           │  │ Очки: 10 900          │    │
│ │ Монеты: 2 400          │  │ Монеты: 3 100         │    │
│ │ Кристаллы: 35          │  │ Кристаллы: 22         │    │
│ │ Сохранено: 12:30       │  │ Сохранено: 14:10      │    │
│ │                        │  │                        │    │
│ │ [ВЫБРАТЬ ОБЛАЧНОЕ]     │  │ [ВЫБРАТЬ ЛОКАЛЬНОЕ]   │    │
│ └────────────────────────┘  └────────────────────────┘    │
│                                                           │
│       Выбранный прогресс заменит другое сохранение        │
└───────────────────────────────────────────────────────────┘
```

- `Пройдено уровней` — число завершённых уровней из `PlayerData.Progress`.
- На узком экране карточки стоят вертикально.
- Доступны только два выбора; закрытия и кнопки `Позже` нет.
- Выбранный снимок целиком сохраняется локально и в облаке.

## Фичи

1. **Первый облачный снимок.** Связанный гость получает первую облачную версию без смены `PlayerId`.
2. **Восстановление существующего аккаунта.** Проверенный облачный снимок целиком заменяет временного гостя.
3. **Автоматическая checkpoint-синхронизация.** Каждый локальный commit обновляет очередь последним полным снимком.
4. **Offline pending и retry.** Последний снимок переживает перезапуск и отправляется после возвращения сети.
5. **Конфликт устройств.** Игрок выбирает одну из двух независимо изменённых версий.
6. **Статус и ручной retry.** Settings показывает состояние и повторяет неудачную отправку.

## Архитектура

```text
Игровой use case
      │ изменяет PlayerData
      ▼
PlayerProgressCommitter.Commit(reason)
      │
      ├── GameDataManager: локальный commit
      │
      └── CloudSyncService: глубокая копия и очередь
                         │
                         ▼
                 UGS Cloud Save Gateway
```

- `GameDataManager` отвечает за локальные данные.
- `PlayerProgressCommitter` остаётся единой точкой checkpoint.
- `CloudSyncService` управляет снимками, очередью, retry, revision, загрузкой и статусом.
- Gateway изолирует Unity Cloud Save SDK.
- UI читает состояние сервиса и передаёт выбор конфликта; сервис не открывает окна.
- Загруженный снимок проходит `PlayerDataValidator` до применения.
- Синхронизация начинается после определения аккаунта и не блокирует запуск.

## Реализация

Cloud Save создаётся заново поверх локального сохранения и Account foundation. Сначала добавляется полный upload/download, затем очередь, восстановление, offline retry и конфликты.
