# Структура системы квестов

Статус: planning in progress.

Документ фиксирует подсистемы продукта, их состав и технические средства.

## Подсистемы по важности

1. **Ядро квестов** — модель одного квеста и правила его прогресса.
2. **Каталог квестов** — источник реальных описаний квестов.
3. **Управление квестами** — запускает квесты и управляет их жизненным циклом.
4. **Интерфейс квестов** — показывает квесты и принимает действия игрока.

`questData.json` лежит в `Assets/Content/quests` и относится к каталогу.

UI и общая игровая инфраструктура находятся вне папки `Quests`.

## 1. Ядро квестов

Ядро описывает один квест, его состояние и общие правила прогресса.

1. `QuestDefinition.cs` — контентное описание квеста.
2. `Quest.cs` — состояние и жизненный цикл одного квеста игрока.
3. `QuestType.cs` — тип логики квеста.
4. `QuestCategory.cs` — категория квеста.

## 2. Каталог квестов

Каталог загружает production-описания и выдаёт их по категории или ID.

1. `QuestCatalog.cs` — загружает, индексирует и выдаёт определения.
2. `QuestCatalogData.cs` — описывает структуру JSON-каталога.
3. `questData.json` — хранит реальные определения квестов.

## 3. Управление квестами

Управление связывает каталог, ядро, игровой процесс, сохранение, награды и UI.

1. `QuestManager.cs` — создаёт активные квесты, принимает прогресс, завершает квесты и выдаёт награды.

Подсистема находится в папке `Runtime`.

## 4. Интерфейс квестов

Интерфейс показывает категории, карточки, прогресс, награду и статус её получения.

1. `QuestsScreenController.cs` — управляет экраном и обновляет список квестов.
2. `QuestItem.cs` — заполняет карточку квеста и обрабатывает получение награды.
3. `QuestsScreen.uxml` — разметка экрана квестов.
4. `QuestItem.uxml` — разметка карточки квеста.
5. `Assets/Content/quests/quest-*.png` — изображения дневных квестов.
6. `Assets/Content/quests/story-*.png` — изображения сюжетных квестов.

## Технические средства

Технические средства обслуживают подсистемы и связывают их между собой.

1. **Типизированные события** — передают факты, понятные конкретному типу квеста.
   - `QuestEvent.cs` — общий контракт события.
   - `ActionCounterQuestEvent.cs` — событие выполненного игрового действия.
   - `LevelResultQuestEvent.cs` — событие результата уровня.
   - `GameEventsManager.cs` — публикует игровые события.
   - `QuestManager.cs` — создаёт типизированное событие результата уровня.

2. **Стратегии прогресса** — отделяют расчёт прогресса от состояния квеста.
   - `IQuestStrategy.cs` — общий контракт стратегии.
   - `ActionCounterQuestStrategy.cs` — считает подходящие действия.
   - `LevelResultQuestStrategy.cs` — проверяет уровень и число звёзд.

3. **Идентификаторы действий** — связывают каталог, события и стратегию.
   - `GameplayActionIds.cs` — хранит стабильные ID игровых действий.

4. **Валидация** — проверяет данные и связи системы.
   - `QuestValidator.cs` — проверяет определения, стратегии, каталог и состояние.

5. **Буфер попытки** — копит действия уровня и передаёт их в прогресс после победы.
   - `QuestAttemptBuffer.cs` — хранит действия текущей попытки.

6. **Сохранение состояния** — хранит прогресс квестов в общем профиле игрока.
   - `PlayerData.cs` — хранит список состояний квестов.
   - `PlayerDataValidator.cs` — проверяет сохранённые состояния.
   - `GameDataManager.cs` — загружает и сохраняет профиль игрока.
   - `PlayerProgressCommitter.cs` — фиксирует изменение прогресса.
   - `CheckpointReason.cs` — указывает причину сохранения.

7. **Выдача награды** — начисляет ресурсы и опыт после завершения квеста.
   - `ResourceManager.cs` — начисляет ресурс.
   - `PlayerExperienceService.cs` — начисляет опыт.

8. **Уведомления состояния** — обновляют внешние потребители после изменения квеста.
   - `GameEventsManager.cs` — публикует изменение состояния, завершение и получение награды.

9. **Runtime-подключение** — запускает квесты и управляет подписками.
   - `MenuEntryPoint.cs` — инициализирует систему квестов.
   - `GameEventSystemController.cs` — включает и отключает подписки `QuestManager`.

## Типы квестов

### Реализовано

1. **Счётчик действий (`ActionCounter`)** — считает выбранные игровые действия.
2. **Результат уровня (`LevelResult`)** — проверяет результат выбранного уровня.

### Запланировано

1. **Состояние игрока (`PlayerState`)** — проверяет постоянный прогресс игрока.
2. **Составной квест (`Composite`)** — проверяет выполнение нескольких других квестов.

## Общий поток

1. Каталог загружает определение квеста.
2. Управление создаёт или восстанавливает `Quest`.
3. Игровое событие приходит в стратегию нужного типа.
4. `Quest` обновляет прогресс и статус завершения.
5. Состояние сохраняется в профиле игрока.
6. UI получает уведомление и обновляет карточку.
