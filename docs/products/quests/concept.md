# Quests

## Целевая архитектура

Подход: data-driven система с постепенным переходом к Strategy.

1. `QuestDefinition` хранит ID, текст, тип условия, цель и награду в контентных данных.
2. `QuestState` отдельно хранит прогресс, завершение и получение награды.
3. Игровые события передают системе факты о действиях игрока.
4. Каждый тип условия получает один обработчик с общим контрактом расчёта прогресса.
5. Простой реестр выбирает обработчик по типу условия.
6. MVP с одним типом использует прямой обработчик. Реестр и Strategy подключаются при появлении второго типа.

## MVP

Один ежедневный квест даёт игроку короткую цель внутри обычного уровня и открывает награду.

1. Квест «Перепрыгнуть 5 препятствий» активен автоматически.
2. Успешный уровень переносит перепрыгивания в прогресс квеста.
3. Достижение цели завершает квест.
4. Прогресс сохраняется в `PlayerData`.
5. Новая локальная дата создаёт чистое состояние.
6. Экран показывает цель, прогресс и завершение.
7. Игрок вручную получает награду один раз.
