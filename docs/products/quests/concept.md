# Quests

## Идея

Квесты дают игроку понятные цели поверх обычного игрового процесса. Дневные квесты считают короткие действия, сюжетные фиксируют важные результаты прохождения.

## Архитектура

Подход: data-driven система со стратегией для каждого типа логики.

1. `QuestDefinition` хранит ID, категорию, тип, условие, цель и награду.
2. `Quest` хранит состояние и управляет жизненным циклом одного квеста.
3. `QuestCatalog` загружает реальные определения из `questData.json`.
4. Типизированные события передают стратегиям игровые факты.
5. `QuestManager` выбирает стратегию из простого словаря по `QuestType`.
6. Добавление типа требует события, стратегии, полей определения и одной записи в словаре.

## Текущий MVP

1. Дневной `ActionCounter`: перепрыгнуть 5 препятствий.
2. Действия дневного квеста переходят в прогресс после победы на уровне.
3. Сюжетный `LevelResult`: завершить уровень №1 с тремя звёздами.
4. Достижение цели завершает соответствующий квест.
5. Прогресс и получение награды сохраняются в `PlayerData`.
6. Экран показывает дневную и сюжетную категории.
7. Игрок получает награду каждого квеста один раз.

## Реализованные типы

1. `ActionCounter` — считает выбранные игровые действия.
2. `LevelResult` — проверяет номер уровня и полученные звёзды.

## Следующие типы

1. `PlayerState` — проверяет постоянный прогресс игрока.
2. `Composite` — объединяет несколько условий.
