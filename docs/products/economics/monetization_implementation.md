## Проверка наград и сохранений

Review действующих execution paths:

- Rewarded: terminal callback принимается один раз; skip/отмена до completion не выдают награду. Completion journal сохраняется до выдачи. ID, валюта, cooldown или право revive записываются одной транзакцией. Повтор ID не прибавляет валюту; recovery использует тот же Settle.
- Win: базу образуют собранные за забег монеты; траты её не уменьшают. Бонус читает сохранённый Win receipt. Внешняя выдача через EarnCoins не увеличивает gross; старый JSON intent сохраняет магазинную семантику.
- Revive: кристалл списывается вместе с правом однократного продолжения; игровой эффект вызывается после commit. Ad-путь проверяет живой контекст до фиксации использованного права. Profile/generation/scene отсекают чужой callback.
- IAP: pending заказ привязан к store account binding; другой владелец его не подтверждает. Fulfillment должен проверить чек и атомарно сохранить серверный grant/ledger и локальный профиль. Только durable=true разрешает ConfirmPurchase. Повтор transaction ID не выдаёт валюту; restore confirmed consumable пропускается; Starter restore возвращает право, баланс берётся из авторитетного профиля.
- Interstitial: суточный резерв сохраняется до native Show; подтверждённый отказ до показа освобождает резерв. Неизвестный исход сохраняет максимум. Navigation continuation защищён от повторного выполнения. Tutorial, testing profile и automation исключены из счётчика посещений.
- Analytics получает SHA-256 digest receipt, полный Google purchase token туда не передаётся. События используют существующее подавление тестовых/Editor данных и consent.

Это review кода; реальные SDK callback, дисковый сбой и серверное восстановление в этой задаче не воспроизводились. Локальные часы/ledger не обеспечивают доверенный суточный лимит между устройствами.
