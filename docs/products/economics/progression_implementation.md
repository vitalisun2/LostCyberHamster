## Локальные гарантии

- Win сохраняет best и XP одной транзакцией; UI получает фактическую квитанцию после commit. Это квитанция XP, а не уникальный ID победы для блока 3.
- Quest сохраняет валюту, XP и Claim вместе. Общая Daily-награда подтверждает именно предъявленный набор, включая старую FIFO-награду.
- W1 хранит решение в локальном журнале раньше применения XP. Apply записывает XP и applied-run ID вместе; 0 XP тоже получает маркер. Cloud rollback игрового payload использует сохранённый local decision.
- W1 использует UTC устройства при первом durable подтверждении. Независимые устройства и доверенная серверная квота отсутствуют. Переход часов на новую дату открывает новую локальную квоту; возврат на уже использованную дату её не повторяет. Это принятое частичное обеспечение, не глобальная гарантия.
- Бонус способности ограничен на активацию: щит II/III — 25/50%, cap 2/3; молния I/II/III — 0/20/50%, cap 0/2/3. Ключ экземпляра препятствия включает поколение пула.
- AddCoinsOrBonusMechanics начисляет результат roll сразу: 3 монеты, до 20 энергии, до 1 жизни или 1 кристалл. Анимации показывают выплату. Collectible-подбор — отдельный источник. Ожидание одного полного бонуса: 2,1 монеты и 0,03 кристалла; для способности без cap умножается на p. С cap число бонусов равно min(Binomial(n,p), C). Доходность реального забега не измерялась.

## DEV и Tools

Обе поверхности находятся в существующем разделе **XP/Level Progress Testing**, в блоке Progression. Новая регистрация меню и отдельный экран не потребовались.

Команды: создать отдельный профиль L1/L6/L7 с 239 XP; +1 XP; Claim готовой карточки/общей Daily-награды; улучшить/экипировать способность; roll 0/1/random; показать вычисленные W1-решения около UTC-полуночи и retry. W1-предпросмотр использует production policy без сети, сохранения и выплаты. Реальный сетевой сценарий остаётся в существующем Prepare New Record/Complete.

Begin сохраняет encrypted полный envelope, создаёт новый profile ID без owner и блокирует привязку/cloud apply. Restore возвращает исходный профиль и его журналы. Выход Play/app сбрасывает override и вызывает Restore; после аварии backup восстанавливается при следующем LoadDataAsync, включая обычную сборку. Ошибка восстановления оставляет recovery marker. Команды мутации требуют именно активный DEV-профиль.

API GameDataManager: `HasProgressionTestingBackup`, `IsProgressionTestingProfile`, `BeginProgressionTestingProfile(Action<PlayerData>)`, `RestoreProgressionTestingProfile(bool endingSession = false)`. Эти методы переданы владельцу блока 3.
