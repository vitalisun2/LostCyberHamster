# Карточки ближайших целей: ограниченный объём

Решение пользователя: 2026-09-10. Статус: реализовано, ревью завершено, компиляция пройдена. [Результат и проверка на устройстве](next_goal_cards_delivery.md).

## Назначение

Помочь заметить конкретную доступную возможность в существующих системах игры. Показывать одну необязательную карточку по содержательному поводу. При отсутствии подходящего повода скрывать карточку.

Текущая цепочка онбординга сохраняется. После неё используются четыре случая из этого документа. Они заменяют ранее обсуждавшийся объём из девяти категорий.

## Четыре случая

| Случай | Основание показа | Значок |
|---|---|---|
| Готовая награда | Игровая система подтверждает доступную неполученную награду | Выбранный сундук `reward_1` |
| Доступная способность или скин | Существующий сервис подтверждает доступное действие с конкретным предметом; текст различает открытие, покупку и экипировку | Книга `skills_2` для способности; существующий портрет конкретного скина для скина |
| Близкое завершение задания | Активное незавершённое задание достигло порога близости к завершению | Выбранный свиток `quest_3` |
| Открытие нового этапа | Доступно новое время суток или новая локация, к которым игрок ещё не приступил | Выбранная карта с флагом `progress_3` |

Способности и скины относятся к одному случаю доступного развития. Обычный следующий уровень выбирается кнопкой Play; открытие нового этапа — отдельный повод для карточки.

## Механизм

- Один координатор, небольшие правила четырёх случаев, общий компонент карточки.
- Источники состояния и действий — существующие задания, прогресс, развитие персонажа и активности блоков 2–3.
- Пересчёт после сохранённых изменений и при входе на подходящий экран. Несколько событий одного изменения объединяются.
- Приоритет по умолчанию: награда, доступное развитие, близкое завершение задания, новый этап.
- Выбор стабилен в пределах посещения экрана. При смене профиля текущее состояние карточки сбрасывается.
- Перед действием повторно проверяется доступность именно показанной цели.
- Важные окна и начатый урок имеют приоритет. На Home учитывается уже видимая панель активностей, чтобы один повод не отображался дважды.
- Карточку можно скрыть до конца текущей сессии. Отсутствие карточки — нормальное состояние.

## Конфигурация

Локальный JSON `Assets/Content/configuration/next_goal_cards.json`: включение дополнительных карточек и четырёх случаев, приоритеты, разрешённые экраны, порог близости завершения, интервалы повторов. Адрес `next_goal_cards` находится в локальной группе UI. Загрузка отделена от выбора целей. Текущий онбординг сохраняется независимо от включения дополнительных карточек.

По умолчанию: близость задания 80%, повтор через 300 секунд, приоритеты 400/300/200/100. Доступная текущая карточка сохраняется в пределах экрана. Подсказки онбординга доступны при возвращении без интервала повторов. Закрытие скрывает карточки до конца сессии.

Правила наград, стоимости и реальной доступности остаются в игровых сервисах. CDN и дополнительные категории отложены до подтверждённой потребности.

## Графика

- Утверждённый вид — кремовая карточка №1, общий компонент для Home, Select Level и победы.
- Четыре выбранных варианта из [галереи](../../../.temp/first-session-feedback/icon-options-20260909/index.html) подготовлены и импортированы в `Content/ui/sprites/shared/next_goal/`. Прозрачность, читаемость и растяжение шапки проверены.
- Для скина используется существующее изображение предмета. Отдельная категория или новая серия значков для этого не требуется.
- Размещение учитывает верхний HUD, центральную панель победы, панель активностей и нижнюю навигацию.
- Поле Select Level остаётся 3×3 с прежними позициями и маршрутом. Скрываются только несуществующие ячейки.

## Связанные согласованные работы

- Утро каждой локации расширяется до пяти уровней. New York 4–5 возвращают прежние 2–3; Paris и Barcelona получают вариации средних участков.
- Урок щита предлагается при первом Level Up; награда за утро — после всех пяти уровней.
- Сохраняются [исправления после игровой проверки](first_session_feedback.md): HUD обучения, Skip, подписи XP, свайпы городов и продолжение через Play.

## Проверка результата

После каждой задачи: ревью кода и затронутых ассетов. После изменений C#: регенерация проектов и компиляция затронутых проектов. Игровая проверка на устройстве выполняется пользователем.

Для оценки пользы на soft launch сравниваются постоянные случайные группы с одинаковыми уровнями, онбордингом и блоками 2–3; отличается показ дополнительных карточек после онбординга. Учитываются возвраты D1/D7, использование доступного развития, получение наград и продолжение забегов. Клики по карточке сами по себе не подтверждают пользу для удержания.
