## Композиция A — под логотипом, предпочтительная

Слева логотип занимает верхнюю часть своей колонки, под ним **одна светлая плашка «Активности» с двумя строками**. Справа текущие Play и SelectLevel. Верхний HUD и пять нижних кнопок сохраняют место/маршруты.

```text
Монеты  Кристаллы           XP / уровень                  Settings

       ЛОГОТИП                          PLAY

  Активности                      Select Level
  7 дней · 3/7   [15 монет]   >
  Неделя · 4/5 побед · 2/3 дня >

          Shop   Hero   Skills   Quests   League
```

Схема передаёт иерархию, не пиксельный эталон. Плашка опирается на `panel_reward_base`; текст тёмный, обычный контур LCH, небольшие currency-icons. Жёлтый акцент только у готовой награды/седьмого дня; Play сохраняет самый крупный и яркий акцент. Цвет дополняется подписью и значком состояния. Отдельный художественный фон всей карточки с запечёнными числами непригоден для этих данных.

Кандидат для1280×720: плашка до468×124 layout px, ширина100% доступной колонки; gap12; логотип до420×300, flex-shrink в собственной колонке. Main по текущим USS около461px высоты: пример300+12+124=436 помещается до safe-area поправок. Это расчёт вёрстки, не измерение телефона. Сохранять пропорции логотипа; исходные88% высоты заменить ограничением свободного места **в задаче интеграции**, иначе карточка переполнит колонку.

Каждая строка имеет минимум48 layout px высоты; реальный physical touch-target проверяется на устройстве с текущим PanelSettings scale. Узкая колонка переносит вторую подпись на две строки и повышает плашку до148px, сокращая только логотип. RU/EN не уменьшаются до нечитаемого шрифта. Родитель нового элемента и дети получают правильный picking-mode; клик попадает в строку, currency-icon не поглощает ввод.

Первая строка — приоритетная рекомендация; вторая всегда показывает другую активность. Никакой автоматической карусели. У двух строк явные названия «7 дней» и «Неделя»; смена приоритета не меняет их ID и click target. Полная семисегментная шкала на Home не обязательна: `3/7` экономит место, всю последовательность показывают подробности.

## Композиция B — общая полоса над нижней навигацией

Две компактные карточки рядом на ширину main, между логотипом/Play и навигацией. Логотип сохраняет относительную центральную роль; активности одинаково заметны.

Цена: обе колонки main теряют высоту, включая Play/Select; добавляется ещё одна горизонтальная полоса над пятью кнопками. На низком landscape получается плотная «панель управления». Для текущего двухколоночного Home A требует меньше перераспределения главного действия, поэтому предпочтительна. B — запасной макет, если утверждённый эталон требует крупный логотип. Одновременно варианты не внедряются.

## Выбор ближайшего действия

Селектор читает единый activity snapshot. «Ближайшее» — достижимость, а не сравнение несопоставимых процентов7/7 и5/5.

1. Available reward: первая строка «Забрать награду · 15 монет». Нажатие открывает подробности с конкретным rewardId и явным Claim; Home-клик сам не начисляет. При двух доступных видах: «Доступно2 награды», ниже кратко оба вида; сначала самый старый earned по времени/ID, другая строка остаётся видимой. Цифра2 — число entitlements, не новая сумма к выдаче.
2. Если награды отсутствуют и weekly можно завершить **следующей победой сейчас**, показывать weekly первым. Условие: недостающих побед≤1 и `distinctDays + (текущая дата ещё не учтена ? 1 : 0) >= 3`. Второй строкой цикл.
3. Иначе, если шаг цикла сегодня ещё доступен: «Одна победа · награда дня15», прогресс `2/7` и целевой день3 в подробностях. Число уже earned и следующий шаг не смешиваются.
4. Если день цикла уже зачтён, но weekly допускает полезные победы сейчас: «Неделя · ещё2 победы», при недостатке дат рядом «и1 новый день». Достигнутые5/5 с2/3 днями: «Ещё1 игровой день», а не «одна победа» без уточнения даты.
5. Если оба доступных на текущую дату действия завершены: «День зачтён · следующий шаг после03:00» (локальное время границы, пример Москвы); вторая строка — статус недели. После7/7: «Цикл завершён · новый после03:00» до следующей eligible даты, независимо от Claim.

Заголовок «Сегодня/Завтра» сам по себе недостаточен при UTC-политике и local Daily. До00:00 UTC в Москве может быть уже следующий календарный день. Использовать «Награда дня», «После03:00», а в подробностях — дата периода, UTC и локальное время. [16](16_activity_day_policy.md) сравнивает обе политики. Если выбран local-вариант, текст и countdown генерирует его provider, без ручных UTC-исключений в Home.

## Подробности «Активности»

Один отдельный экран `ReturnActivitiesScreen`, landscape. Back возвращает в Home; переход открывает выбранную секцию. Существующие Quests и League остаются отдельными маршрутами.

- Верх: заголовок, Back, текущие ресурсы штатным способом.
- Левая зона около55%: «7 победных дней», пояснение «Первая победа дня. Пропуски сохраняют прогресс»; горизонтальные7 слотов с номером, валютой и состоянием. На узком landscape допускается4+3 с устойчивым порядком. День7 шире/акцентнее, показывает50+1 как один приз.
- Правая зона около45%: «Цель недели», точные5 побед/3 дня с двумя счётчиками, награда50, абсолютный диапазон дат и остаток, следующая цель с датой старта. Состояние Claim независимо от нового недельного прогресса.
- Earned-квитанции доступны в своей секции: одна выбранная награда, её дата/цикл, «Получить», «Ещё:N». Старые earned листаются добровольно; каждая транзакция по одному ID. Два coin/gem в дне7 — одна транзакция, два reward IDs — две.
- Внизу спокойная «Играть» ведёт в текущий обычный уровень через существующую навигацию. Фактическая выбранная цель не меняет доступ к уровням. Вход из Home не требует обхода урока щита/восстановленного маршрута.

Период/награда/состояние — runtime labels и data binding. Новый PNG нужен только если shared оболочки и значки не дают согласованный эталон; подготовка, alpha,9-slice и импорт по [UI-гайду](../../approaches/unity_ui_asset_integration.md).

## Представление выигрыша и очередь

- После Win durable прогресс обновлён. На Home при возвращении видна ready-плашка. При Next/Restart путь игрока продолжается через существующий Level Up/урок; отдельный обязательный activity-popup после каждой победы не вводится согласно границам13.
- Добровольный Claim открывает компактное подтверждение по выбранному snapshot: название шага/недели, крупная сумма, «Получить», «Позже». После commit — квитанция «+15 монет» либо «+50 монет +1 кристалл», новый баланс, «Готово». Нажатие на анимацию завершает только анимацию; повторное отдельное действие закрывает/продолжает.
- День7: заголовок «7 победных дней пройдены», один акцент/одна квитанция; неделя: «Цель недели выполнена». Визуальное торжество отличается заголовком и семью отметками, валюта остаётся из сервиса. Кандидат анимации до0,6с, текст/CTA сразу доступны; значение времени проверяется на устройстве.
- Открытая пользовательская модалка завершается первой. Pending LevelUp/сохранённый урок щита обслуживаются штатным priority coordinator. Daily продолжает показываться в Quests по11. Activity confirmation стартует только по явному действию на безопасном Home/Activities; повторный клик во время занятого host не создаёт второй dialog.
- При позднем W1 во время activity dialog дождаться его закрытия, затем обслужить LevelUp. Activity XP0; новый LevelUp от стороннего источника не теряется. Existing `prepareContinuation`, ack+route и profile/scene/generation guards сохраняются.
- Ошибка save оставляет Claim доступным для Retry и исходные суммы. Ошибка UI после успешного save восстанавливает receipt, не выдаёт валюту снова. Later закрывает представление, earned остаётся; автоповтор модалки на каждом bind отсутствует по требованию добровольного входа.
