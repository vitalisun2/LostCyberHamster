## Текущий LCH

`QuestsScreenController.ScheduleDailyCommonRewardModal` планирует окно через 1000 мс на Daily-вкладке при доступной награде. `DailyQuestRewardModalController` показывает 30 монет и «Получить»; крестик скрыт. `QuestManager.ClaimDailyCommonReward()` транзакционно начисляет валюту и отмечает Claim. `DailyQuestService` держит очередь `PendingCommonRewards` с `SetId`; старые завершённые незабранные карточки удерживают слоты при смене локальной даты.

После 09 одна карточка=10 монет+5 XP. Свежий полный набор=60 монет+15 XP вместе с общими 30. Общий бонус=0 XP. Выполнить три цели, забрать три карточки и забрать общий бонус — три разных состояния.

## Сравнение двух вариантов

| Критерий | A: усилить окно в Quests после трёх Claim | B: представить после победы |
|---|---|---|
| Причина доступности | Игрок только что забрал карточки; 3/3 рядом | Победа подтверждает действия, но карточки могут оставаться незабранными |
| Все выполнены,0/3 Claim | Карточки доступны, общий бонус ждёт | Допустим CTA «К заданиям»; «Получить 30» ещё недоступен |
| Бонус уже доступен | «Получить 30» через текущий сервис | Можно показать то же окно после результата, используя тот же SetId/Claim; нужен дополнительный безопасный trigger |
| Поздний Claim в меню | Поздравление сразу | Ожидание следующей победы задерживает обратную связь; всё равно нужен Quests-fallback |
| Очередь окон | Контекст Claim сохраняется | Конкуренция с Level Up, уроком щита и выбранным Next |

**Рекомендация A.** Общая награда остаётся в квестах. После Win допустима существующая цель «Забери награды в заданиях» со счётчиком; выплата следует отдельному Claim. Автоматическое получение незабранных карточек ради вариантаB изменило бы утверждённый ручной поток. ВариантB исследован как альтернатива и в план реализации не включён.

## Конкретный вид и состояния

- Постоянная плашка Daily: иконка монет, «Бонус набора:30», «Награды получены:2/3». Три маркера с галочками соответствуют забранным карточкам; выполненная карточка сохраняет свой CTA.
- При 3/3: плашка «Бонус доступен». После квитанции третьей карточки и освобождения очереди — существующая landscape-модалка: «Все награды заданий собраны», три галочки, крупная иконка+30, «Получить». Данные суммы идут из сервиса.
- Акцент иконки до 0,6 с, текст/CTA доступны сразу; касание завершает анимацию отдельно от Claim. После успешного сохранения короткая квитанция «+30 монет», окно закрывается, баланс обновлён.
- Добавить «Позже»/Back: закрывает представление, entitlement остаётся; постоянная плашка открывает его снова. Автопоказ один раз на непрерывное посещение Daily, чтобы Later не открывал окно через секунду снова.
- Старые награды: одна за раз, FIFO существующей очереди; показать дату набора и «Ещё наград: N», затем добровольное «Следующая награда». Каждая кнопка получает только показанный `SetId`, не суммарную сумму всей очереди.
- Смена даты при открытом окне: закреплённый SetId/сумма остаются предъявленной наградой. Повторная проверка при Claim; уже полученное событие закрывается/обновляется без выплаты другому набору.
- Ошибка сохранения: сумма не отмечается полученной, кнопка «Повторить». Двойное нажатие блокируется до ответа. Холодный вход восстанавливает доступность из квестового состояния.

Предлагаемый узкий контракт: read-only snapshot текущей общей награды `(profile,generation,setId,rewardType,amount,originDate)` и Claim по ожидаемому `setId`. Сейчас метод Claim без аргумента забирает голову очереди; её смена между показом и нажатием — конкретный риск. Это задачаP2-03, UI подключаетP2-11. Сохранённый Claim защищает награду; временный флаг посещения защищает только автопоказ.

Порядок с Level Up/уроком — [10](10_level_up_ui.md). Третий Claim сначала получает свои 5 XP; Level Up обслуживается перед ещё не открытым Daily. Уже открытое Daily завершается первым. У общей награды 0 XP; позднее weekly во время её показа может создать pending Level Up, который обслужится после закрытия.

## Приёмка

- 0/3,2/3 Claim; 3 цели выполнены безClaim; третийClaim; LateClaim; Later/возврат; две старые награды; смешанный набор после ротации; полночь при открытом окне.
- По каждой награде: показанныйSetId=полученныйSetId, одна выплата 30,0 XP; свежий набор суммарно 60 монет/15 XP. Повтор/ошибка/перезапуск сохраняют entitlement либо полученный факт.
- Level Up, Daily, щит, weekly показываются по одному; выбранный переход продолжается один раз.1000 мс — текущий debounce, а не право обойти занятую очередь.
- Проверить длинную дату/RU/EN, landscape-safe area и оба CTA. Кандидат качественного прохода:4 из 5 игроков различают «выполнено» и «получено» и находят отложенные 30 монет.

Остаток: принять рекомендованный видA с Later и экранный эталон. Выплаты и момент доступности утверждены 09.
