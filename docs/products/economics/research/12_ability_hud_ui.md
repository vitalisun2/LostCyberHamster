Прямо подтверждённый пример формы — сегментная полоса Subway. Сравнение кольца/числа ниже — проектирование LCH, а не утверждение, что все три аналога используют кольца.

## Число, полоса, кольцо

| Вариант | Польза | Цена для landscape LCH |
|---|---|---|
| Только «3 с» | Точный остаток, мало места | Смена целых секунд ступенчата; доля прошедшего времени не видна |
| Горизонтальная полоса | Быстро читается доля; пример Subway | Дополнительная ширина возле кнопок; без числа не различить 3 с и 7 с полного действия |
| Кольцо вокруг кнопки | Использует существующую округлую кнопку, сохраняет связь с активацией | Без подписи путается с зарядкой; близкий к нулю сектор мал |
| **Кольцо+секунды** | Доля периферическим зрением, абсолютное время числом | Нужны контраст, устойчивое место текста и раздельные charge/active состояния |

**Рекомендация: кольцо времени+число секунд; для скейта отдельное число комбинаций.** Основа — существующий `btn_ultra` в `GameScreen.uxml`, `ulta-charge-value`, классы `.game-control--ready` и `.game-control__visual--ultimate`. Внешний диаметр кольца помещается в текущий прямоугольник кнопки; touch-target остаётся прежним. Плашка секунд и маленькая иконка способности — внутри верхней части visual; счётчик скейта — компактный нижний бейдж внутри того же прямоугольника. Статический USS сейчас задаёт hit-area 267×237 и visual 189×189; это размеры layout, не измерение физических пикселей телефона. Кольцо и бейджи должны помещаться в hit-area. Точное размещение проверяется на новом HUD блока 1.

Кольцо заполняется целиком на успешном старте и убывает по часовой стрелке от 12 часов. Зарядка продолжает использовать существующую оболочку и число 0–99; активное кольцо появляется только после успешной активации. «Готово» — отдельная форма/иконка; цвет дополняет форму и текст. Активная кнопка не принимает повторную активацию; счётчики/кольцо пропускают ввод своему родителю и не расширяют touch-zone.

## Данные и состояния

| Состояние | Показ |
|---|---|
| Способность не выбрана/закрыта | Существующее скрытое/недоступное состояние кнопки |
| Заряд 0–99 | Существующее число заряда; секундного кольца нет |
| Готова 100 | Готовая оболочка+иконка; понятное действие нажать |
| Щит активен | Кольцо `remaining/duration`;`ceil(remaining)`+локализованная единица; полное 3/5/7 с |
| Скейт активен | То же для 5/7/10 с; отдельно пиктограмма прыжка и число новых доступных комбинаций 1/2/3 |
| Скейт: последняя комбинация началась | Число уже 0, текущая комбинация завершается; доступность следующей отсутствует |
| Скейт: время истекло в воздухе | Кольцо пустое, вместо секунд «До посадки»/иконка посадки, новых комбинаций 0; режим живёт до безопасного окончания |
| Молния | Короткий отклик успешного запуска; далее обычная зарядка. Её последовательные визуальные разрушения не превращаются в длительный buff |
| Пауза/background | Показ и источник игрового времени заморожены; после возврата перечитать snapshot |
| Завершение/окончательный выход | Очистить active-view и подписки; новая попытка получает своё состояние |

Число новых комбинаций уменьшается при принятом начале полного jump-cycle. Дополнительный ввод усиленного/двойного прыжка внутри него не списывает ещё одну. Пока есть время, но 0 комбинаций и начатый цикл ещё идёт, показать «До посадки»; это состояние завершения, не обещание нового прыжка. При expiry в Ride выйти сразу. Неуспешный ввод не расходует комбинацию.

Runtime — единственный владелец remaining, duration, phase, remainingCombinations, activationId. HUD читает snapshot через `UltaMechanics`/адаптерP2-06. UI не заводит отдельный таймер от клика и не завершает способность. Остаток щита и снятие защиты должны происходить по одному lifecycle, а не расходиться между `Update` и coroutine.

- Кольцо обновляется в штатном gameplay UI-update; текст только при изменении отображаемого значения. Временные цифры моноширинные/с фиксированной шириной контейнера.
- Целые секунды округляются вверх:2,01 показывает 3; 0,01 показывает 1. 0 с означает завершение/посадку, а не активную защиту. Пограничная точность runtime не зависит от UI.
- Snapshot при bind/scene resume предотвращает кадр старой способности. Profile/root/attempt/activation проверяются; Dispose снимает подписки. Во время revive состояние берётся у владельца попытки, визуальная шкала сама ничего не продлевает.
- RU/EN, разряды 10/9, строка «До посадки», низкий контраст фона, aspect16:9/19.5:9/20:9/4:3 входят в макетную проверку. Верхний quest/record toast остаётся в своём слоте. Фокус урока щита охватывает кнопку вместе с индикатором.

## Приёмка и неизвестные

- Реальный щит I/II/III: на HUD3/5/7 с, пауза 3 с wall-clock остаток не меняет; защита прекращается вместе с lifecycle. UI не показывает ещё 1 с после снятия защиты.
- Скейт: полный простой/усиленный/двойной цикл списывает 1; поздний старт до expiry завершается посадкой; следующий отклоняется. Проверить expiry вRide/Jump/Landing, нулевойbudget, пауза, revive, finish/dispose.
- Молния показывает успешное исполнение без обратного отсчёта; неуспешная активация сохраняет ready/charge по runtime.
- При одновременно открытом tutorial/toast touch-кнопки доступны в разрешённом контексте, бейдж не закрывает прыжок/покупку. Макетную читаемость подтвердить живым кадром после передачи HUD блока 1.
- Кандидат проверки:4 из 5 новичков после короткого взгляда различают заряд, готовность и остаток, а у скейта объясняют 0 комбинаций при завершающемся прыжке. Это ещё не выполненный тест.

Остаток: экранный эталон и визуальная приёмка кольца в реальном HUD. Параметры длительности/комбинаций утверждены 09; от формы индикатора не зависят.
