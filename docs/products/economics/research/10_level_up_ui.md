# 10 — Level Up: представление и продолжение

2026-09-09. Статус: UX-рекомендация для будущей реализации. Экономика утверждена в [09](09_progression_abilities.md); задачи — [план блока 2](../progression_plan.md). Источники прочитаны в эту дату. Игровой прогон LCH в исследование не входил.

## Общий набор аналогов для research 10–12

Три игры: Subway Surfers, Temple Run 2, Jetpack Joyride. Первые две близки по циклу раннера; Jetpack Joyride даёт landscape-пример. Официальная справка подтверждает механики. Статический игровой кадр подтверждает только видимое состояние; момент открытия окна, длительность анимации и поведение после перезапуска из него не выводятся. Версия при отсутствии номера отмечена как неизвестная. Это точечные примеры, а не доказательство роста retention.

Точное модальное Level Up с двумя CTA у этих трёх игр данными источниками не подтверждено. Предлагаемая ниже композиция — собственное решение LCH по утверждённому 09, а не копия якобы найденного экрана.

## Предпочтительный вариант

Одно торжественное landscape-окно на накопленный диапазон повышений. Показ вне забега после результата/Claim. Существующие `LevelUpModal` и `GameResultModalPresentation` сохраняют роль; меняются содержимое и вид. Все повышения получают окно, включая последующие: это уточнение 09 относительно ранней идеи level-toast блока 1.

- Слева крупный новый уровень на существующей наградной плашке; для диапазона — «Уровень 4», ниже «С уровня 2 до 4».
- Справа главный результат «+2 очка развития»; ниже «Свободно сейчас: 3». Earned delta и текущий баланс различаются.
- Ниже до трёх компактных вариантов из реального каталога: иконка, имя, действие, цена 1 DP, краткая выгода. Заголовок «Теперь можешь открыть / улучшить». Это возможности траты, фактического открытия ещё нет.
- Порядок: подходящий шаг щита блока 1; затем следующий рекомендованный элемент чередующейся ветки 09; затем другие доступные варианты. Показывать только доступное при текущих предпосылках. Остальное — на экране развития.
- Основной CTA «К развитию». В первом подходящем состоянии — «Открыть щит»: вход в настоящий урок, расход только через production-покупку. Второй CTA «Продолжить» выполняет выбранное Домой/Дальше/Restart/Leaderboard; на Quests остаётся в квестах.
- Скин: «Открыть за 1 очко · затем купить за 20/25/20 кристаллов». Карточка не обещает бесплатную покупку. При 0 DP: «Очки уже потрачены», переход «Посмотреть развитие». При полном каталоге — уровень/очки и продолжение, без вымышленного товара.
- Появление панели до 0,2 с, короткий акцент уровня до 0,6 с; финальные числа сразу читаемы. Нажатие на анимацию раскрывает финальный кадр, отдельное нажатие CTA выполняет действие. Звук подчиняется Settings; подложка/текст неподвижны. Числа времени — UX-кандидат для проверки.

## Порядок и состояния

1. Win сохраняет результат и показывает звёзды/score/полученный XP. «Домой»/«Дальше» закрывает результат; Level Up; при выборе урок щита; затем сохранённое продолжение. Leaderboard и Restart проходят тот же coordinator.
2. Claim сохраняет награду/XP/claimed, обновляет карточку и квитанцию. Pending Level Up показывается сразу на безопасном Quests-контексте. Дополнительная победа не требуется.
3. Если Daily-окно уже открыто, завершить его текущее действие. Если третий Claim одновременно создал Level Up и доступный Daily-бонус: сначала Level Up, затем предложение урока щита. При уходе в урок Daily остаётся сохранённым и показывается при возврате в Quests. При обычном продолжении Level Up в Quests следующий — Daily. Не вытеснять открытый пользовательский диалог.
4. Weekly фиксирует подтверждение/XP независимо от UI. В меню pending Level Up доставляется после текущей модалки; в другом забеге ждёт его окончания. Record acknowledgment после Level Up. Lose+revive сохраняет ожидание; окончательный выход допускает накопленное повышение из внешнего источника.
5. Несколько повышений до показа объединяются. Пока окно открыто, `toLevel` фиксирован. При новом XP ack только показанного диапазона; новый диапазон остаётся pending и обслуживается тем же безопасным циклом.

Доставка блока 1: `PlayerLevelPresentation.HasPendingLevel`, `ShowAsync`, `LastAcknowledgedPlayerLevel`, `UIManager.HasPriorityPresentation`. Финальные контракты сверены 09.09 с кодом и [отчётом владельца](../first_session_implementation.md); игровая проверка не проводилась. Ack — сохранённое принятие показанного диапазона, отдельное от награды. После прерывания до ack окно может повториться, DP/XP остаются одной выдачей. `ShowAsync` принимает `Func<bool, Action> prepareContinuation`: маршрут готовится внутри ack-транзакции, возвращённый Action только выполняет навигацию. `FirstSessionReturnFromLevelUp` отличает восстановленный маршрут Level Up от tutorial. Явный выбор урока сохраняют `FirstSessionReturnToShield` и optional `startShieldLesson` в `Continue`; `PrepareShield` снимает флаг. Ошибка загрузки Level Up восстанавливает исходный Result для Retry. Callback продолжения одноразовый; scene/profile/generation проверяются. При входе в развитие coordinator хранит исходный маршрут до возврата либо явного нового выбора игрока. После холодного старта маршрут безопасно восстанавливается в меню; сам pending выводится из профиля.

Состояния view: pending; blocked другим modal/tutorial; showing fixed range; animation completed/skipped; acknowledgment saving; accepted; continuation; profile/root invalidated. Ошибка записи оставляет Retry без навигации и без второй награды. Ошибка загрузки UI сохраняет pending и доступный исходный маршрут.

## Приёмка будущей задачи

- Отдельные профили:239 XP+Daily5; 230 XP+первая победа 27; 2 повышения одной выдачей; DP потрачен до показа; новый XP во время окна; late weekly в меню/забеге; смена профиля; повторный вход до/после ack.
- Проверить обе кнопки результата и Leaderboard/Restart; CTA развития с возвращением; первый щит уже открыт/надет; Forest-first; третий Claim вместе с Daily.
- В каждом сценарии: earned DP, свободный баланс, доступные карточки и единственный переход совпадают с сохранённым состоянием. Показ награды сам по себе не начисляет её.
- Макет RU/EN:16:9,19.5:9,20:9 и 4:3 как проверочные размеры; реальную поддерживаемую матрицу подтвердить P2-00. Общий modal host с одним владельцем clipping. Читаемость и touch проверить в запрошенном игровом проходе.
- Качественный кандидат:4 из 5 новых игроков объясняют новое очко и находят развитие; это проверка понятности, а не измеренный D1.

Остаток: утвердить UX-кандидат и экранный эталон перед Unity-интеграцией; параметры экономики закрыты 09.
