# 02. Восстановление прогресса существующего аккаунта

## Что и зачем

При явном входе в существующий аккаунт игра загружает его облачный снимок и полностью заменяет им текущий гостевой прогресс. Пользователь получает состояние выбранного аккаунта без неоднозначного смешивания двух экономик.

## Зависимости

- Успешный явный вход в существующий аккаунт.
- Для его UGS `PlayerId` существует целостный облачный снимок.

## Продуктовый алгоритм

1. Пользователь явно выбирает вход в существующий аккаунт.
2. Игра завершает вход и получает UGS `PlayerId` этого аккаунта.
3. Игра загружает целый облачный снимок данного `PlayerId`.
4. После успешной проверки снимок полностью заменяет текущий гостевой прогресс в игре.
5. Игра продолжает работу с восстановленным состоянием аккаунта.

## Критерии приёмки

- Для явного входа в существующий аккаунт облачный снимок всегда имеет приоритет над текущим гостевым состоянием.
- Замена применяется ко всей игре атомарно, без выбора отдельных полей.
- Гостевой прогресс не сохраняется, не загружается в новый аккаунт и не объединяется с облаком.
- Снимок другого UGS `PlayerId` не применяется.
- После восстановления runtime-состояние соответствует загруженному снимку, а не прежнему гостевому состоянию.

## Граничные случаи

- Облачного снимка нет: игра не выдаёт пустое состояние за успешное восстановление и сообщает об ошибке входа/восстановления.
- Снимок повреждён или неполон: гостевое runtime-состояние не заменяется частично.
- Связь прервалась до завершения загрузки: восстановление можно повторить; частичный результат не применяется.

## Вне рамок

- Сохранение копии гостевого прогресса перед входом.
- Выбор пользователем между гостевым и облачным состоянием.
- Полевое объединение валют, предметов, скинов или прогресса.
- Обычное разрешение конфликтов между устройствами после входа.
