# 05. Безопасный выбор снимка при игре на нескольких устройствах

## Что и зачем

Когда один аккаунт изменён на нескольких устройствах, игра выбирает один целый снимок по детерминированному порядку. Это не допускает потери целостности экономики из-за полевого смешивания разных состояний.

## Зависимости

- [02. Восстановление прогресса существующего аккаунта](02-restore-existing-account-progress.md).
- [04. Офлайн-изменения и синхронизация после подключения](04-offline-pending-reconnect.md).

## Продуктовый алгоритм

1. Для обычной синхронизации одного UGS `PlayerId` игра сравнивает локальный и облачный целые снимки.
2. Побеждает снимок с более высоким рангом игрового прогресса.
3. При равном ранге побеждает снимок с большей ревизией.
4. При равных ранге и ревизии побеждает снимок с более поздним серверным временем.
5. Выбранный снимок целиком становится актуальным состоянием и при необходимости целиком записывается на отстающую сторону.
6. Для явного входа в существующий аккаунт сравнение не применяется: облачный снимок всегда полностью заменяет гостевой прогресс.

## Критерии приёмки

- Одинаковая пара снимков всегда даёт одного и того же победителя по порядку: ранг прогресса, ревизия, серверное время.
- Применяется только один целый снимок.
- Валюта, покупки, предметы и другие части экономики никогда не объединяются по полям.
- Конфликт разрешается только между снимками одного UGS `PlayerId`.
- Явный вход в существующий аккаунт сохраняет безусловный приоритет облака.

## Граничные случаи

- Более позднее серверное время не побеждает более высокий ранг прогресса или ревизию.
- Все три значения равны: снимки считаются эквивалентными для выбора; дополнительное объединение не выполняется.
- Один снимок повреждён или неполон: он не применяется частично и не участвует как источник отдельных полей.
- Офлайн-устройство возвращается с устаревшим снимком: выбор выполняется по тем же правилам, а не только по времени клиента.

## Вне рамок

- Ручной выбор версии пользователем.
- История версий и откат к произвольному снимку.
- Полевое или аддитивное объединение экономики.
- Синхронизация разных аккаунтов или разных UGS `PlayerId`.
