# 03. Автоматическая синхронизация контрольных точек

## Что и зачем

После значимых игровых изменений игра сразу сохраняет целый снимок локально и неблокирующе синхронизирует его с облаком. Игрок не ждёт сеть, а облачное состояние следует за подтверждённым локальным прогрессом.

## Зависимости

- Для текущего UGS `PlayerId` разрешено облачное сохранение.
- Реализован первый облачный снимок для привязанного гостевого аккаунта.
- Определены существующие игровые контрольные точки сохранения.

## Продуктовый алгоритм

1. Игра достигает контрольной точки сохранения.
2. Игра немедленно и атомарно сохраняет локальный снимок всей игры.
3. Игровой процесс продолжается без ожидания облака.
4. Игра неблокирующе отправляет в облако целый актуальный снимок для текущего UGS `PlayerId`.
5. Успех подтверждает синхронизацию; ошибка не отменяет локальное сохранение.

## Критерии приёмки

- Каждая поддерживаемая контрольная точка сначала завершает локальное сохранение.
- Облачная операция не блокирует управление, переходы или дальнейшие локальные сохранения.
- В облако отправляется один целый снимок, а не изменение отдельного поля.
- Снимок записывается только для `PlayerId`, активного для этой синхронизации.
- Ошибка облака не откатывает успешно сохранённый локальный прогресс.

## Граничные случаи

- Несколько контрольных точек возникают подряд: облако в итоге получает самый новый целый снимок, без возврата к более старому.
- `PlayerId` изменился до отправки: снимок старого пользователя не записывается в облако нового пользователя.
- Игра закрылась после локального сохранения, но до ответа облака: локальный снимок остаётся сохранённым.
- Нет сети: локальное сохранение завершается; дальнейшая доставка относится к офлайн-функции.

## Вне рамок

- Перечень новых игровых событий, которых сейчас нет среди контрольных точек.
- Фоновая синхронизация при закрытом приложении.
- Офлайн-очередь и повтор после восстановления сети.
- Разрешение конфликтов нескольких устройств.
