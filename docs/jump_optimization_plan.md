# План оптимизации прыжка

1. **Очень высокий приоритет: Сократить список препятствий**
  1.1 ✅ Распределить `ObstacleSpawner.SpawnedObstacles` на два списка по линиям и хранить индекс ближайшего необработанного препятствия.
  1.2 ✅ В `JumpMechanics.CalculateJumpState` просматривать только 8–10 элементов вперёд, вызвать `EnsureCapacity` для буфера при инициализации.
  1.3 Эффект: обход из O(N) становится квазиконстантным, убираем realloc и спайки GC.

2. **Очень высокий приоритет: Упростить обработчики препятствий**
  2.1 ✅ Заменить словарь делегатов и LINQ в `JumpMechanics` на прямой `switch` по `ObstacleTypeEnum`, подготавливая ссылки на компоненты до цикла.
  2.2 Эффект: нулевые аллокации, минус ~0.5–1 мс CPU на сложных сценах.

3. **Высокий приоритет: Убрать вложенные циклы при поиске bigNotAlive**
  3.1 ✅ Построить сопоставление `smallNotAlive -> bigNotAlive` один раз перед циклом прыжка и использовать в `CollisionUtils.TryFindBigNotAliveUnderSmallNotAlive` и `IsHitSmallNotAliveOnRoof`.
  3.2 Эффект: линейная сложность вместо квадратичной, стабильная производительность на плотных паттернах.

4. **Высокий приоритет: Кэшировать коллайдеры**
  4.1 ✅ В `Obstacle.InitializeMechanics` сохранить ссылки на `BoxCollider2D` и их размеры; `CollisionUtils` принимает уже готовые значения.
  4.2 Эффект: меньше `GetComponent` при каждом сравнении, экономия CPU.

5. **Средний приоритет (↑): Избавиться от повторного поиска границ хомяка**
  5.1 ✅ В `JumpMechanics` хранить `LeftX/RightX` и обновлять при изменении ширины вместо вызова `GetComponent<Hamster>()` в `CollisionUtils.GetHamsterXBounds`.
  5.2 Эффект: двигаем быстродействие и убираем потенциальные GC.

6. **Средний приоритет (↑): Фильтровать прыжки по энергии**
  6.1 Ввести сервис `TrySpendEnergyForJump()` (и аналоги для roof/super) и вызывать его до `AtomicEvent.Invoke()`.
  6.2 Добавить флаг результата в `JumpMechanics`/`SuperJumpMechanics`, чтобы `EnergyMechanics` списывала стоимость только при успешном старте прыжка.
  6.3 Эффект: не просыпаются подписчики при «пустом» нажатии, энергия расходуется строго по факту, UI всегда синхронизирован.

7. **Средний приоритет: Ограничить обновление UI**
  7.1 В `UiGameScreenMechanics` использовать `StringBuilder` и обновлять лейбл по таймеру 0.1 с либо при изменении данных.
  7.2 Эффект: убираем каждокадровые аллокации и лишние layout/repaint.

8. **Средний приоритет: Централизовать обработку ввода**
  8.1 Вынести `DoubleJumpDetector`, проверку состояний и выбор `Jump/SuperJump/Roof` в единый сервис ввода, который используют и `KeyboardMechanics`, и `GameScreenController`.
  8.2 Перевести пробел/тап на `InputAction` с коллбэком `performed`, чтобы UI-кнопка и клавиатура шли через один код.
  8.3 Эффект: нет дублирования правил, меньше поллинга, единая точка входа для прыжка.

9. **Низкий приоритет (↑): Оптимизировать данные событий**
  9.1 В `SendJumpEventIfNeeded` передавать `ObstacleId`, логировать только под `UNITY_EDITOR`/`DEVELOPMENT_BUILD`.
  9.2 Эффект: меньше строковых конкатенаций и логов в продакшене.

10. **Низкий приоритет (↑): Использовать хэши Animator**
  10.1 В `TransformAnimatorController` и `SpriteAnimatorController` заменить строковые триггеры на `Animator.StringToHash`.
  10.2 Эффект: убираем повторные вычисления хэшей и микролаги.

11. **Низкий приоритет: Сузить диапазон квестов**
  11.1 В `QuestManager` сгруппировать задания по `ActionTypeEnum` и обновлять только списки прыжковых квестов.
  11.2 Эффект: сниженная косвенная нагрузка от событий прыжка на мету.
