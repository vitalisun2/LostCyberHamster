# Руководство по ручной проверке гостевого аккаунта

> **Статус:** Не выполнен пользователем / Pending.
>
> Проверку выполняет пользователь. Агент этот сценарий не запускал.

## Preconditions

- Используется Development Build или Unity Editor, где доступно меню `DEV`.
- Открыты Console/логи с фильтром `[Account]`.
- Для первой проверки на устройстве уже сохранён локальный session token гостя.
- `com.unity.services.authentication` `3.4.1` подключён прямой зависимостью проекта; сценарий не требует ручной работы с token.

## Шаги

1. Запустить игру и не ждать завершения авторизации на стартовом экране.
2. Проверить в логах ветку восстановления существующего гостя.
3. Открыть `DEV` → `Account` и нажать `RESET ACCOUNT TEST STATE` один раз.
4. Убедиться, что кнопка сменилась на `CONFIRM RESET`, но сброс ещё не выполнен.
5. Нажать `CONFIRM RESET`.
6. Перезапустить игру.
7. Проверить в логах ветку создания нового гостя.
8. Ещё раз перезапустить игру и проверить, что созданный гость теперь восстанавливается.

## Ожидаемый результат и логи

- Игра продолжает запуск без ожидания завершения гостевой авторизации.
- При первом запуске: `[Account] State: Resolving`, затем `[Account] Scenario selected: RestoreGuest.` и `[Account] Guest restored.`
- После первого нажатия reset credentials не очищаются; требуется отдельное подтверждение.
- После подтверждения: сообщение об успешном сбросе и `[Account] Test state reset. Local credentials cleared.`
- При следующем запуске: `[Account] State: Resolving`, затем `[Account] Scenario selected: CreateGuest.` и `[Account] Guest created.`
- При повторном запуске новый локальный session token выбирает `RestoreGuest`.
- При успешном Create/Restore итоговое состояние аккаунта — `Guest`.

## Cleanup / Reset

- После проверки оставить новый локальный session token, чтобы следующий запуск восстанавливал созданного гостя.
- Не подтверждать reset повторно без необходимости: он очищает только локальные UGS Authentication credentials и может лишить доступа к прежнему непривязанному гостю.
- Не удалять server account, игровой прогресс, Cloud Save и все `PlayerPrefs`: это не входит в cleanup этого сценария.

## Scope / Not covered

- Проверяются только выбор `RestoreGuest`/`CreateGuest`, восстановление, создание и двухшаговый локальный reset.
- Не проверяются удаление server account, привязка аккаунта, восстановление доступа, offline/error/retry, прогресс и Cloud Save.
