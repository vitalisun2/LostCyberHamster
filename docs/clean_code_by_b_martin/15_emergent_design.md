# Формирование архитектуры

## Концепция

Хорошая архитектура формируется через работающий код, устранение дублирования, выразительность и минимальный набор сущностей. Не нужно заранее строить сложную схему, если простая структура уже ясно выражает поведение и выдерживает изменения.

## Когда читать

- Рефакторинг архитектуры.
- Устранение дублирования.
- Выбор между простой правкой и новой абстракцией.
- Подготовка изменения в алгоритме.

## Правила

- Сначала код должен работать и проверяться.
- Затем устраняй дублирование.
- Затем улучшай выразительность имен, структуры и порядка.
- Не добавляй класс/метод, если он не уменьшает реальную сложность.
- Минимум сущностей не важнее ясности: слишком плотный код тоже грязный.

## Пример

Плохо: абстракция появилась раньше повторяющейся проблемы.

```csharp
public interface IUniversalMovementDecisionProviderFactoryResolver
{
    IMovementDecisionProvider Resolve(MovementContext context);
}
```

Лучше: начать с явного простого решения и выделять абстракцию после появления реального варианта.

```csharp
public sealed class MovementDecisionProvider
{
    public MovementDecision Decide(MovementContext context)
    {
        if (context.IsOnRoof)
            return DecideRoofMovement(context);

        return DecideGroundMovement(context);
    }
}
```

## Правило для агента

Добавляй абстракцию только после ответа на вопрос: какую конкретную сложность она убирает сейчас? Если ответ расплывчатый, оставь решение проще.
