# Чистый код: профессиональная позиция

## Концепция

Чистый код - это код, который можно уверенно читать, менять и проверять. Главная идея для агента: не просто заставить изменение работать, а оставить затронутую область понятнее, чем она была до правки.

При этом чистота не означает бесконтрольный рефакторинг. Агент работает в рамках задачи: улучшает то, что связано с текущим изменением, и не переписывает соседние системы без причины.

## Когда читать

- Перед любой существенной правкой.
- Когда есть соблазн сделать только быстрый патч.
- Когда рефакторинг может расползтись за пределы задачи.

## Правила

- Сначала понять текущее поведение, затем менять код.
- Не оставлять в затронутом коде очевидный мусор: мертвые ветки, временные имена, бессмысленные комментарии.
- Не чинить весь проект заодно. Улучшать только код, который реально нужен для задачи.
- Если чистка меняет поведение, она уже не косметика: ее нужно планировать, проверять и объяснять.
- Если область слишком рискованная, зафиксировать проблему и сделать минимальное безопасное изменение.

## Пример

Плохо: быстрый патч добавляет еще один флаг в уже мутный метод.

```csharp
private void UpdateBot(bool force, bool fromRoof, bool skipCheck)
{
    if (!skipCheck && _state == null) return;
    if (force || fromRoof) _speed *= 1.2f;
    // ...
}
```

Лучше: в рамках задачи выделен явный сценарий, но соседняя система не переписана целиком.

```csharp
private void UpdateBot()
{
    if (!CanUpdateBot())
        return;

    ApplyMovementSpeed();
}

private bool CanUpdateBot()
{
    return _state != null;
}

private void ApplyMovementSpeed()
{
    if (_movementMode == MovementMode.RoofRun)
        _speed *= RoofRunSpeedMultiplier;
}
```

## Правило для агента

Перед финальным ответом проверь: не оставил ли ты в измененных файлах новый долг, который появился именно из-за твоей правки. Старый долг не трогай без необходимости, но новый не добавляй.
