# Дублирование и DRY

## Концепция

Дублирование опасно не только лишними строками. Оно создает несколько мест, где одно и то же знание может разойтись. Но устранять нужно именно повтор знания, а не любое визуальное сходство.

## Когда читать

- Один и тот же алгоритм повторяется.
- Появляется копипаста с небольшими отличиями.
- Нужно решить, выделять ли общий метод/класс.

## Правила

- Устраняй повтор бизнес-правила, формулы, граничного условия, ключа, константы.
- Не объединяй случайно похожий код с разными причинами изменения.
- Общее имя должно описывать реальную концепцию, а не технический компромисс.
- После устранения дублирования вызывающий код должен стать понятнее.
- Если общий метод получает много флагов, абстракция выбрана неверно.

## Пример

Плохо: одно правило безопасной дистанции размножено по коду.

```csharp
if (roofGap.Width < 2.5f)
    return false;

if (exitGap.Width < 2.5f)
    MarkBlocked(exitGap);
```

Лучше: правило получает имя и один источник изменения.

```csharp
private const float MinimumSafeExitGapWidth = 2.5f;

private bool IsExitGapSafe(Gap gap)
{
    return gap.Width >= MinimumSafeExitGapWidth;
}
```

Осторожно: похожие строки не всегда дублирование.

```csharp
private const float MinimumSafeExitGapWidth = 2.5f;
private const float MinimumCameraPadding = 2.5f;
```

Здесь одинаковое число может иметь разные причины изменения, поэтому объединять его нельзя без доменного основания.

## Правило для агента

Перед выделением общего кода сформулируй, какое знание дублируется. Если общего знания нет, не создавай искусственную абстракцию.
