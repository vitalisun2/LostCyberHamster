# Существующие системы

## Сначала понять систему

**Ситуация.** Задача затрагивает готовую систему, сервис, компонент или workflow.

**Действия.**

1. Найти владельца поведения, точку входа, состояние, контракт и потребителей.
2. Проследить путь данных до эффекта. Проверить документацию, тесты и runtime-факты.
3. Если механизм уже есть, использовать его в месте задачи. Если контракт не покрывает требование, менять систему у владельца и проверить потребителей.

**Результат.** До кода понятны путь выполнения, уровень изменения и проверка. Локальный костыль не создаёт параллельное правило.

## Решение держать у владельца инварианта

**Ситуация.** Правка добавляет guard, filter, fallback, shortcut или новое ветвление.

**Действия.**

1. Назвать инвариант и слой с полным контекстом для решения.
2. Проверить, не дублирует ли правка ответственность другого слоя.
3. Оставить одно место решения; нижним слоям передавать готовый результат или явный контракт.
4. Проверить все call sites и граничные сценарии владельца.

**Результат.** Один владелец правила, нет расходящихся guards и symptom patch.

## Готовность первого UI-кадра

**Ситуация.** Новый UI Toolkit экран меняет размер центральной композиции сразу после открытия.

**Действия.** Сопоставить момент добавления дерева в panel, асинхронные ожидания, подключение `GeometryChangedEvent` и первый расчёт scale/frame. Измерить геометрию до и после этого расчёта. Проверить повторный вход: новое дерево теряет inline-стили прежнего. Готовность первого показа закреплять в lifecycle экрана: отдельно подготовить скрытое дерево, применить геометрию, синхронно связать элементы и показать. Загрузку каталога, иконок и сетевых данных вынести в отдельный этап. Подготовка нового дерева должна сохранять состояние ещё видимого контроллера, включая повторный вход в тот же экран.

**Результат.** Поздний расчёт геометрии отделён от загрузки спрайтов; итоговый неподвижный скриншот дополнен проверкой начального состояния.

## Проверять покрытие редизайна UI

**Ситуация.** Нужно найти экраны, оставшиеся после массового обновления интерфейса.

**Действия.** Сопоставить реестр экранов, места показа модалок, UI из runtime-кода и активные компоненты сцен. Для каждого проверить UXML/USS, переопределения общего host, используемые ассеты и историю представления. Готовность макета, импорт PNG и подключение к живому UI фиксировать отдельно. Переименованное переиспользование уточнять по ссылкам и при необходимости SHA256.

**Результат.** Список содержит действующие визуальные хвосты. Общие ассеты, обновления одной логики и оставшиеся шаблоны классифицированы по реальному использованию.
