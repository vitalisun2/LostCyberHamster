# Диагностика ошибок

## Доказать root cause до фикса

**Ситуация.** Поведение расходится с ожиданием, причина не доказана.

**Действия.**

1. Зафиксировать affected input, expected, actual и источник expected.
2. Получить минимальное воспроизведение. Проследить execution path до первой точки расхождения.
3. Подтвердить значения и выбранные ветки фактами выполнения. Отдельно исключить альтернативы.
4. Исправлять слой-владелец причины после доказательства, не симптом.

**Результат.** Есть code location, фактические значения, причина actual и исключённые альтернативы.

## Проверить наблюдаемость

**Ситуация.** Тест или automation сообщает об отсутствии события, действия или маркера.

**Действия.**

1. Проверить, включён ли источник сигнала, исполняется ли запись, доходит ли transport и тот ли формат читает проверка.
2. Сопоставить семантический сигнал с независимым итогом: result, state, damage, completion.
3. Отделить дефект наблюдаемости от дефекта поведения.

**Результат.** Отсутствие сигнала считается фактом поведения только после проверки всего канала наблюдаемости.

## Логировать под гипотезу

**Ситуация.** Кода недостаточно для выбора между конкретными причинами.

**Действия.**

1. Сформулировать вопрос диагностического прохода.
2. Логировать только вход, состояние, ключевые ветки и результат; связать путь correlation id.
3. Использовать штатную Diagnostic Log инфраструктуру и нужный канал.
4. После анализа кода разрешать один узкий дополнительный проход для недостающего факта.

**Результат.** Каждый лог отвечает на гипотезу; объём достаточен для доказательства, без постоянного шумного трассирования.

## Отделить анализ от фикса

**Ситуация.** Пользователь запросил root cause или анализ без реализации.

**Действия.** Доказать причину, дать архитектурную рекомендацию и остановиться. Фикс, cleanup и дополнительные проверки запускать отдельным запросом.

**Результат.** Анализ не меняет исследуемое состояние и не расширяет scope.

## Учесть стоимость диагностики

**Ситуация.** Измеряется производительность, а диагностика пишет синхронные или подробные логи.

**Действия.** Отделить метрики приложения от стоимости логирования. Подробный trace включать на короткий проход; итог подтвердить с обычным diagnostic profile.

**Результат.** Диагностика не принимается за измеряемый performance-дефект.
