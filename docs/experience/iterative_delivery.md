# Итерации и проверки

## Завершать смысловой шаг проверкой

**Ситуация.** Реализация или рефакторинг состоит из зависимых этапов.

**Действия.**

1. Разбить работу на минимальные смысловые изменения.
2. После каждого шага проверить ближайший контракт или сценарий.
3. Зафиксировать артефакт: diff, результат команды, документ анализа или краткий итог проверки.
4. Переходить дальше после подтверждения текущего шага.

**Результат.** Ошибка локализуется в последнем шаге; следующий этап опирается на проверенное состояние.

## Проверять пропорционально риску

**Ситуация.** Изменение готово, нужно выбрать финальную проверку.

**Действия.**

1. Найти обязательный gate для типа задачи.
2. Проверять изменённые файлы и затронутый execution path, не весь проект без причины.
3. При сбое отделить ошибку своего diff от внешнего blocker.
4. После успешного обязательного gate не повторять проверки без нового вопроса или явного запроса.

**Результат.** Риск закрыт минимальным достаточным набором проверок; время не тратится на дубли.
