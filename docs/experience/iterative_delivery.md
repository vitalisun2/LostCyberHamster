# Итерации и проверки

## Планировать зависимые этапы до выполнения

**Ситуация.** Исследование, реализация и проверка состоят из зависимых этапов.

**Действия.**

1. Изучить задачу, систему и доступные средства проверки. Отделить подтверждённые факты от открытых вопросов.
2. Построить порядок этапов по зависимостям. Для каждого назвать входные условия, ожидаемый результат и критерий завершения.
3. Заранее спроектировать минимальный проверочный сценарий: исходное состояние, действия, наблюдаемый эффект и способ его фиксации.
4. Выполнять текущий этап до подтверждения его результата. При найденном блокирующем расхождении исследовать его причину; зависимые этапы ждать готовности входных условий.
5. Зафиксировать артефакт: diff, результат команды, документ анализа или краткий итог проверки. Переходить дальше по принятому плану.
6. При новых фактах или уточнении пользователя сначала обновить план и критерии, затем продолжить действия.

**Результат.** Каждое действие закрывает определённый вопрос; следующий этап опирается на проверенное состояние.

## Проверять пропорционально риску

**Ситуация.** Изменение готово, нужно выбрать финальную проверку.

**Действия.**

1. Найти обязательный gate для типа задачи.
2. Проверять изменённые файлы и затронутый execution path, не весь проект без причины.
3. При сбое отделить ошибку своего diff от внешнего blocker.
4. После успешного обязательного gate не повторять проверки без нового вопроса или явного запроса.

**Результат.** Риск закрыт минимальным достаточным набором проверок; время не тратится на дубли.

Для нескольких родственных UI собирать RU/EN и размеры в один preview-прогон после review композиции. Дорогой runtime-прогон закрывает сохранение, навигацию и награды. Подтверждённое ручное прохождение учитывать как отдельное доказательство. Новый дефект повторно проверять по затронутому пути, затем сразу выполнять финальный gate. При общем Unity Editor заранее учитывать ручные действия пользователя в интерпретации результатов.
