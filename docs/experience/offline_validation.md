# Проверка работы без сети

## Разделять потерю сети и холодный запуск

**Ситуация.** Игра сохраняет pending после потери сети в уже авторизованной сессии.

**Действия.** Отдельно проверить cold-start до авторизации, локальный checkpoint, owner/dirty/pending, закрытие и следующий online-запуск. Сравнить прежнюю и изменённую cloud revision; учесть pending старой сессии.

**Результат.** Подтверждена сохранность последнего локального прогресса во всех стадиях account lifecycle.

## Связывать сетевой код с реальным запуском

**Ситуация.** Код содержит удалённые URL, SDK init или проверку подключения.

**Действия.** Найти callers и активные scene/prefab GUID. Проверить Addressables profile и схемы. Прочитать initializer и transport установленной версии SDK: источник конфигурации, timeout, retry, expiry.

**Результат.** Активная сетевая зависимость отделена от legacy-кода и локальной инициализации SDK.

## Отделять имитацию от проверки устройства

**Ситуация.** Проверка проходит в Editor или через fake сервиса.

**Действия.** Прочитать реализацию SDK для целевой платформы. Записать, что реально проверено: production-ветка, callback-контракт, физическое отключение сети, native cache, kill/relaunch. Для изолированных вызовов восстановить static events, временные объекты и состояние Editor.

**Результат.** Editor placeholder подтверждает свой контракт; Android offline-поведение подтверждается отдельным прогоном конкретного APK.

Источник: [аудит 2026-09-05](../Planning/offline_audit_2026-09-05.md).

## Отделять рабочий прогресс от durable snapshot

**Ситуация.** Во время забега облако подтверждает старую ревизию или сервис записывает технический журнал.

**Действия.** Техническую запись сериализовать с последним сохранённым gameplay. Рабочие монеты и квесты оставлять в памяти. При ошибке обычного checkpoint сохранять их для повтора, откатывая только revision и дату попытки. При ошибке экономической транзакции откатывать её изменение.

**Результат.** ACK сохраняет прежнюю игровую ревизию; ошибка записи сохраняет возможность повторить checkpoint с заработанным прогрессом.

## Сохранять credentials переключаемых аккаунтов

**Ситуация.** После `SignOut(false)` другой вход использует тот же Authentication SDK profile.

**Действия.** Использовать public SDK profiles. Сохранить подтверждённое соответствие PlayerId → SDK profile перед переключением; candidate mapping записать до принятия облачного профиля. После crash выбирать credentials по владельцу durable envelope.

**Результат.** Вход другого аккаунта сохраняет возможность восстановить исходную identity.

## Отменять браузерный вход на двух уровнях

**Ситуация.** Браузер закрыт без callback; следующий вход получает поздний ответ старого flow.

**Действия.** Ограничить gateway ожиданием активного приложения. При отмене освобождать listener и transition. В SDK проверять generation после await и OAuth state до применения callback.

**Результат.** Истёкший запрос освобождает игру; старый ответ сохраняет принадлежность исходной операции.

## Проверять первый bind и потерянный callback отдельно

**Ситуация.** Подтверждённая рекламная награда сохранена у локального профиля без owner; при следующем запуске раньше recovery проходит первый вход.

**Действия.** Допускать перенос null owner к подтверждённому владельцу только для того же ProfileId и перенесённого журнала. До Show сохранять intent; completion и начисление фиксировать отдельно, receipt — вместе с балансом. При soft timeout сохранять обработчик до результата SDK.

**Результат.** Первый bind сохраняет подтверждённую награду; поздний callback завершает исходную операцию.

## Разделять версии ответов рейтинга

**Ситуация.** Ответы получения сезона, результатов таблицы и запроса ушедшего экрана приходят в другом порядке.

**Действия.** Проверять отдельные sequence для сезона и кэша одной версии; UI проверяет собственный lifecycle. Перед terminal compare повторно сверять серверный период. Результат без известной недели сначала сохранять как LocalOnly.

**Результат.** Поздний ответ сохраняет правильный период, экран и состояние локального результата.

Источник новых записей: [реализация 2026-09-05](../Planning/offline_implementation_2026-09-05.md).
