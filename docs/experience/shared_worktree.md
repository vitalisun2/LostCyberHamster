# Общее рабочее дерево

## Перечитать файл перед патчем

**Ситуация.** Общий файл мог измениться после первого чтения.

**Действия.**

1. Перед правкой снова прочитать целевой участок, `git status` и diff файла.
2. Отделить существующие изменения от своего scope.
3. Применить узкий патч по текущему контексту.
4. Повторно проверить файл и свой diff.

**Результат.** Патч применён к текущей версии; чужие изменения сохранены.

## Отделить свой scope

**Ситуация.** Рабочее дерево уже dirty или проверка упала при параллельной работе.

**Действия.**

1. До правки записать свои файлы-владения и исходный status.
2. Менять, проверять и stage только свой scope.
3. Ошибку сначала связать со своим diff. Внешнюю причину оформить отдельным blocker.
4. Перед commit повторить status и проверить staged diff.

**Результат.** Commit содержит только целевые изменения; чужая работа не изменена и не присвоена.

## Не мешать общему Unity Editor

**Ситуация.** Другой агент или пользователь одновременно работает в общем Unity Editor по тому же runtime-пути.

**Действия.**

1. Перед runtime-проверкой уточнить владельца общего пути и текущую фазу его работы.
2. Если другой владелец меняет те же связанные C# / UXML / USS или уже держит тот же runtime-route, не запускать свою automation поверх него.
3. В такой ситуации продолжать только read-only диагностику или работу вне Unity; runtime-проверку пометить как внешний blocker.
4. После освобождения Unity повторить compile gate и только потом запускать Play Mode.

**Результат.** Проверка не ломает чужую сессию и её результат можно уверенно привязать к своему изменению.
