# Существующие тесты

## Концепция

Этот файл читать только при явной работе с уже существующими тестами или при прямом запросе пользователя на тесты.

Проектное правило: не добавлять и не расширять тесты по инициативе агента. Редакторские/EditMode/editor-only тесты на проекте не пишутся.

## Когда читать

- Пользователь прямо просит работать с тестами.
- Нужно отрефакторить существующие тесты.

## Правила

- Не предлагать тесты как обязательный артефакт задачи.
- Один тест - одна концепция.
- Тест должен быть быстрым, независимым, повторяемым, самопроверяющимся и своевременным.
- Arrange/Act/Assert должны быть читаемы без расшифровки магических чисел.
- Дублирование в тестах допустимо меньше, чем в production, но шумовые setup-блоки нужно прятать за helper/DSL.
- Не тестируй внутреннюю реализацию, если важен внешний контракт.

## Пример

Плохо: смысл проверки теряется в числах и setup.

```csharp
[Test]
public void Test1()
{
    var planner = new JumpPlanner();
    var result = planner.Plan(new Vector2(10, 5), new Vector2(16, 5), 4);
    Assert.AreEqual(true, result.CanJump);
}
```

Лучше: тест называет поведение.

```csharp
[Test]
public void Plan_ReturnsReachableJump_WhenTargetIsInsideMaxDistance()
{
    JumpPlanner planner = CreateJumpPlanner(maxDistance: 8f);

    JumpPlan plan = planner.Plan(
        start: new Vector2(10f, 5f),
        target: new Vector2(16f, 5f));

    Assert.That(plan.CanJump, Is.True);
}
```

## Правило для агента

Если пользователь прямо попросил работать с тестами, тест должен объяснять проверяемое поведение лучше, чем production-код. В остальных задачах тесты не создавать.
