# Побочные эффекты и разделение команд/запросов

## Концепция

Функция должна либо отвечать на вопрос, либо изменять состояние. Когда метод одновременно возвращает ответ и меняет систему, вызывающий код становится двусмысленным: чтение выглядит безопасным, но на самом деле двигает состояние.

## Когда читать

- Метод с именем `Is...`, `Can...`, `Get...`, `Find...` меняет состояние.
- Метод возвращает `bool`, но также выполняет команду.
- Проверка в `if` неожиданно запускает игровое действие.

## Правила

- Запросы не меняют состояние.
- Команды меняют состояние и имеют имена действия: `Start`, `Apply`, `Save`, `Register`.
- Метод `Try...` допустим, если по имени очевидно, что он пытается выполнить команду.
- Не прятать инициализацию, запись, кеширование или изменение state machine внутри проверки.
- Побочный эффект либо вынести отдельно, либо сделать частью честно названной команды.

## Пример

Плохо: метод выглядит как проверка, но меняет состояние.

```csharp
private bool CanStartRoofRun()
{
    if (!_roofSensor.HasRoofAhead)
        return false;

    _state = BotState.RoofRun;
    _lastRoofRunStartTime = Time.time;
    return true;
}

if (CanStartRoofRun())
{
    PlayRoofRunAnimation();
}
```

Лучше: запрос и команда разделены.

```csharp
private bool CanStartRoofRun()
{
    return _roofSensor.HasRoofAhead;
}

private void StartRoofRun()
{
    _state = BotState.RoofRun;
    _lastRoofRunStartTime = Time.time;
    PlayRoofRunAnimation();
}

if (CanStartRoofRun())
{
    StartRoofRun();
}
```

## Правило для агента

Если метод используется в условии, он должен быть безопасен для чтения. Если он меняет состояние, его имя и место вызова должны выглядеть как команда.
