# Запахи и эвристики: быстрый диагностический список

## Концепция

Запах кода - не автоматический приговор, а сигнал для проверки. Этот файл нужен как стартовая точка code review: найти признаки проблемы и перейти к профильной теме.

## Когда читать

- Перед ревью чужой или своей правки.
- Когда код "не нравится", но причина не сформулирована.
- Когда нужно выбрать релевантные файлы этого справочника.

## Диагностика

- Комментарий объясняет плохое имя или запутанный метод -> `07_comments.md`, `02_meaningful_names.md`.
- Метод принимает много аргументов -> `04_function_arguments.md`.
- Boolean-флаг выбирает сценарий -> `04_function_arguments.md`.
- Повторяется одинаковый блок -> `19_duplication_dry.md`.
- Код находится на неверном уровне абстракции -> `03_functions_one_operation.md`.
- Базовый класс знает о наследниках -> `06_switches_and_polymorphism.md`, `13_classes_srp_cohesion.md`.
- Есть мертвый код или мертвая функция -> удалить, если доказано, что не используется.
- Непоследовательные имена для одной концепции -> `02_meaningful_names.md`.
- Метод завидует данным другого объекта -> `09_objects_and_data_structures.md`.
- Магические числа без имени -> вынести в именованную константу на правильном уровне.
- Отрицательные условия усложняют чтение -> инвертировать имя или ветвление.
- Длинная цепочка доступа `a.B.C.D` -> `09_objects_and_data_structures.md`.
- Тест отсутствует рядом с рискованной логикой -> `12_unit_tests.md` и проектные правила по тестам.

## Вопросы для агента

- Что является главным намерением этого кода?
- На каком уровне абстракции должен жить текущий фрагмент?
- Какая причина изменения у этого класса или метода?
- Можно ли изменить это поведение в одном месте?
- Есть ли скрытый побочный эффект?
- Есть ли граничное условие, которое не выражено явно?

## Правило для агента

Не исправляй запах механически. Сначала назови риск, затем выбери минимальную правку, которая делает код понятнее или безопаснее в рамках текущей задачи.
