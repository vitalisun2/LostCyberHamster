# Clean Code: справочник для агентов

Краткие прикладные правила по мотивам книги Роберта Мартина «Чистый код». Это не пересказ книги и не замена правилам проекта, а вспомогательный навигационный слой: агент выбирает только релевантные темы перед подготовкой плана и конкретным изменением кода.

## Как использовать

1. Сначала понять задачу и определить, какие файлы, классы и сценарии будут затронуты.
2. Если задача готовит план реализации, рефакторинга или code review по коду, выбрать 2-5 релевантных тем из таблицы ниже до составления плана.
3. Прочитать выбранные MD-файлы до подготовки плана.
4. Перед первой содержательной правкой кода убедиться, что выбранный набор тем все еще покрывает текущий scope; если scope изменился, добрать или заменить релевантные темы и дочитать их.
5. После реализации быстро пройтись по тем же файлам как по чеклисту ревью.
6. Если задача не требует изменения кода, читать только темы, которые нужны для ответа.

Не читать весь справочник каждый раз. Если сомневаешься, начни с `18_smells_and_heuristics.md`, затем перейди по релевантным темам.

## Приоритет правил

1. Явный запрос пользователя.
2. Проектные правила из `docs/rules/AGENTS.md`, `code_conventions.md` и соседних файлов.
3. Релевантные файлы из этого справочника.
4. Общие предпочтения агента.

Подходы из этого справочника никогда не переопределяют уже принятые правила проекта. Этот каталог помогает выбрать более чистый способ внутри проектных ограничений, а не заменить эти ограничения.

Если расхождение между проектным правилом и релевантной рекомендацией Clean Code существенное и влияет на план, реализацию или ревью, агент должен кратко сообщить пользователю об этом расхождении: что требует проект, какую альтернативу предлагает Clean Code и почему в задаче приоритет остаётся у проектного правила.

Если правило из книги конфликтует с проектным правилом, выполнять проектное правило.

## Каталог тем

- `01_clean_code_attitude.md` - профессиональная позиция, правило бойскаута, ограниченный скоуп.
- `02_meaningful_names.md` - имена, намерение, контекст, отсутствие шумовых различий.
- `03_functions_one_operation.md` - маленькие функции, одна операция, один уровень абстракции.
- `04_function_arguments.md` - количество аргументов, флаги, выходные аргументы, parameter object.
- `05_side_effects_command_query.md` - скрытые побочные эффекты и разделение команд/запросов.
- `06_switches_and_polymorphism.md` - замена повторяющихся `switch/if` полиморфизмом или стратегиями.
- `07_comments.md` - когда комментарии помогают, а когда маскируют плохой код.
- `08_formatting.md` - вертикальная структура, близость связанных строк, порядок чтения.
- `09_objects_and_data_structures.md` - объекты, структуры данных, DTO, закон Деметры.
- `10_error_handling.md` - исключения, контекст ошибки, отказ от `null`.
- `11_boundaries_and_third_party_code.md` - границы со сторонним и платформенным кодом.
- `12_unit_tests.md` - чистые тесты, F.I.R.S.T., один смысл на тест.
- `13_classes_srp_cohesion.md` - компактные классы, SRP, связность.
- `14_system_construction_and_dependencies.md` - отделение создания системы от использования.
- `15_emergent_design.md` - простая архитектура через тесты, DRY и выразительность.
- `16_concurrency.md` - изоляция многопоточного кода и shared state.
- `17_progressive_cleanup.md` - постепенная очистка работающего кода.
- `18_smells_and_heuristics.md` - диагностический список запахов.
- `19_duplication_dry.md` - дублирование и безопасное устранение повторов.
