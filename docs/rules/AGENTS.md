# Правила для AI-агентов

Единый источник правды по рабочему процессу для всех AI-агентов в этом репозитории: Claude Code, Codex, GitHub Copilot.

Язык — русский. Английский — только по явному запросу.

## Как агенты получают этот файл

| Агент | Механизм |
|---|---|
| Codex | Читает `docs/rules/AGENTS.md` (настроить путь в конфигурации Codex) |
| Claude Code | Читает `CLAUDE.md`, который ссылается на `docs/rules/AGENTS.md` |
| GitHub Copilot | Читает `.github/copilot-instructions.md`, который ссылается на `docs/rules/AGENTS.md` |

## Что читать перед работой

Для любой задачи: прочитать запрос и релевантные исходники, ассеты, планы и инструменты.

Для исполнительной и существенной аналитической задачи — дополнительно:

1. `docs/rules/ai_workflow_lessons.md` — накопленные уроки (обязательно каждую сессию)
2. `docs/architecture_knowledge_base.md` — архитектурные решения и паттерны
3. `docs/rules/agent_tools.md` — каталог инструментов проекта
4. `docs/rules/iteration_cycle.md` — итерационный цикл тестирования бота
5. `docs/rules/code_conventions.md` — конвенции кода и валидация
6. Активный план в `docs/Planning/current/`, если задача привязана к плану
7. Релевантные исходники, editor tools, ассеты и тесты

## Профиль пользователя

- Единственный разработчик на проекте.
- Опыт: senior-уровень, глубокое понимание архитектуры, Unity, C#.
- Ожидает от агентов профессионального качества кода и архитектурных решений.

## Стиль общения

- Кратко, без воды, без эмодзи (если не просят).
- Не заканчивать сообщение наводящим или предлагающим вопросом. Пользователь сам скажет, что делать дальше.

## Процесс выполнения задачи

1. Прочитать запрос. Изучить релевантный код, ассеты, планы и инструменты до начала правок.
2. Определить тип задачи: аналитическая или исполнительная.
3. Для аналитической: выполнить анализ, при необходимости создать локальные артефакты без ветки и worktree.
4. Для исполнительной: выбрать workflow (стандартный или рефакторинг — см. `docs/rules/workflow.md`) и реализовать минимальное полное изменение.
5. Провалидировать (см. `docs/rules/code_conventions.md`, секция «Валидация»).
6. Если валидация не прошла и проблема связана с задачей — починить. Если не связана — остановиться и сообщить о блокере.
7. Закоммитить, запушить, смержить по правилам workflow (см. `docs/rules/workflow.md`).
8. Ретроспектива (см. секцию «Ретроспектива и дообучение» ниже).

## Ретроспектива и дообучение

Выполняется после каждой завершённой задачи:

1. **Уроки:** проанализировать, появился ли устойчивый полезный вывод. Если да — добавить в `docs/rules/ai_workflow_lessons.md`. Не дублировать существующие. Не добавлять пустые уроки.
2. **Ревью правил:** быстро проверить файлы в `docs/rules/` на дубли, устаревшие правила, возможный рефакторинг структуры. Если есть что исправить — исправить в рамках того же коммита.

## Управление правилами

При добавлении нового правила:

1. Проверить все файлы в `docs/rules/` — нет ли уже такого или похожего.
2. Найти файл-владелец темы → добавить буллет или расширить существующую секцию.
3. Если тема новая и не вписывается ни в одну существующую секцию → оценить:
   - Тема является подтемой файла → добавить новую секцию в этот файл.
   - Тема самостоятельная и перегружает существующий файл → создать новый файл в `docs/rules/` с говорящим именем и добавить ссылку в секцию «Что читать перед работой».
4. Одна тема = один файл-владелец. Другие файлы могут только ссылаться, не пересказывать.
5. Формулировка — 1-2 строки на правило.

## Структура `docs/rules/`

| Файл | Владелец тем |

| `AGENTS.md` | Точка входа, роутинг, профиль, стиль, процесс, мета-правила |

| `iteration_cycle.md` | Итерационный цикл тестирования бота (автопрогон, логи, фидбэк) |

| `agent_tools.md` | Каталог проектных инструментов и автоматизаций |
| `ai_workflow_lessons.md` | Накопленные практические уроки |
