# Правила для AI-агентов

Единая точка входа для всех AI-агентов в репозитории: Claude Code, Codex, GitHub Copilot.

Язык: русский. Английский только по явному запросу.

## Как агенты получают этот файл

| Агент | Механизм |
|---|---|
| Codex | Читает `docs/rules/AGENTS.md` (настроить путь в конфигурации Codex) |
| Claude Code | Читает `CLAUDE.md`, который ссылается на `docs/rules/AGENTS.md` |

## Что читать перед работой

Обязательно прочитать:

- `docs/rules/unity_cli.md` — возможности Unity CLI и правила применения в проекте.

Дополнительные источники читать только по явной необходимости или по запросу:

1. `docs/rules/code_conventions.md` — если надо уточнить разрешённую автоматизированную проверку, Unity/C# compile или формат проекта.
2. `docs/rules/agent_tools.md` — если задача требует разрешённую project automation, логи, editor tools или подготовку пользовательского test-level сценария.
3. `docs/rules/build_and_telegram_publishing.md` — если задача требует сборку игры или публикацию билда в Telegram.
4. `docs/products/approaches/unity_ui_asset_integration.md` — перед подготовкой или Unity-интеграцией UI-ассетов.

## Задачи Unity-интеграции UI

На текущем этапе каждая новая задача Unity-интеграции UI:

- создаётся с высокой глубиной анализа;
- работает прямо в Unity Lead на `integration/unity-live`, без отдельной ветки или worktree;
- закрепляется в боковой панели Codex;
- до анализа и любых изменений читает этот `AGENTS.md` и `docs/products/approaches/unity_ui_asset_integration.md`.

### Параллельная работа в Unity Lead

- Каждая задача заранее фиксирует свой экран и точный список файлов-владений.
- Перед первым изменением и перед commit проверяет `git status` для своих файлов и общий dirty state.
- Изменяет и валидирует только свой scope. Чужие незавершённые изменения не правит, не откатывает и не включает в commit.
- Ошибку сначала связывает со своим diff. Чужой незавершённый файл или известный внешний blocker отмечает отдельно.
- Если нужен результат другой задачи, ждёт её завершения, затем повторно проверяет `git status`, зависимость и свой scoped результат.
- Изменение `shared`, общей навигации, базовых UXML/USS, сервисов или других общих файлов заранее согласуется с их текущими владельцами.
- Unity Lead проверки выполняются строго последовательно: recompile, запуск Unity, Play Mode, Unity CLI, test-level и visual capture. При занятой Unity automation остальные задачи ждут освобождения, затем повторяют свою проверку.
- Файловую подготовку вне Unity можно выполнять параллельно в пределах своего scope.
- Unity Lead lock захватывается перед публикацией или изменением общего файла, хранит владельца и фазу, затем освобождается. Занятый lock означает ожидание по протоколу.
- Финальный отчёт перечисляет собственные изменённые файлы, выполненные scoped-проверки, внешние зависимости и оставшиеся чужие изменения.

## Обязательный стиль общения

Это обязательное правило для каждого агента.

- В начале задачи агент включает локальный skill `caveman` в режиме `full` и использует его во всех ответах.
- Менять уровень Caveman или выключать его можно только по явному запросу пользователя.
- Отвечай только на поставленный вопрос: кратко, простым неформальным языком, без воды.
- Детали добавляй только когда они нужны для решения. Для перечислений используй маркеры.

## Голосовой чат Codex

- На прямую команду пользователя сразу начинай действие. До действия допустимо ответить только «Да, сделаю» или задать один вопрос, без которого нельзя продолжить.
- Не описывай план, внутренние шаги или ход работы, пока пользователь этого не просил.

## Обязательный стиль документации

Это обязательное правило для любой создаваемой или изменяемой документации.

- Пиши в режиме `caveman full`: кратко, просто, технически точно.
- Описывай утверждённое: что нужно и как это работает.
- Не включай негативные сценарии, отвергнутые варианты, ограничения вне текущего решения и фразы «не нужно / не добавлять / не делать».
- Исключение: негативный факт нужен, только если это реальный blocker, риск или явное решение пользователя.
