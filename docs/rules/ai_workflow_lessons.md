# AI Workflow Lessons

Короткие правила по эффективности рабочего процесса. Это не архитектура игры и не спецификация фич, а накопленные уроки по тому, как быстрее и точнее выполнять задачи в этом репозитории.

## Как использовать

- Читать перед существенной задачей, особенно если она связана с ботом, логами, тестовыми уровнями или Unity Editor workflow.
- После завершения задачи добавлять только устойчивые выводы, которые повышают качество следующих задач.
- Не превращать файл в дневник. Добавлять краткие правила, а не историю всех действий.

## Уроки

- Для реального прогона через `Tools/Test Level/Launch` фактический исполняемый уровень — `Assets/Content/locations/01_New_York/levels/Morning/test_level/test_level.json`.
- Stage-specific bot-паттерны удобно хранить в `PatternsCollection.json`, а `test_level.json` пересобирать из них под текущий этап вместо переключения launcher на отдельные level-файлы.
- При анализе логики бота сначала отделять проблему поведения от проблемы логирования: шум в `diagnostic_log.txt` легко маскирует корректное поведение.
- Для бота слово `safe` нужно формулировать как безопасность самого шага в окне исполнения; будущие угрозы после безопасного шага относятся к следующему пересчёту или к chain stages.
- Для автоматизации уже открытого Unity внешняя CLI-команда недостаточна: нужен in-editor bridge, который сам вызывает `EditorApplication.ExecuteMenuItem(...)` или общую launch-логику по файловому/IPC-сигналу.
- После изменений в editor/runtime-скриптах в уже открытом Unity нужно закладывать паузу на script reload перед автопрогоном, иначе тест может пройти на старой доменной сборке и дать ложную картину.
- Для автопрогона в уже открытом Unity лучше сначала принудительно запросить script compilation из Editor API, а затем запускать test level; фокус окна можно использовать как вспомогательную меру, но не как единственный механизм.
- Для `SwitchLane` правильнее считать окно исполнения по прогнозу освобождения target-линии (динамический `execAt`), а не отбрасывать действие только потому, что линия unsafe в текущем кадре.
