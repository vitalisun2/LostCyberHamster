# Итерационный цикл тестирования бота

Процесс итеративной разработки и отладки бота через цикл: гипотеза → правка → автопрогон → визуальный фидбэк → логи → вывод.

## Когда применять

Задачи, затрагивающие gameplay, бота, прогрессию или тестовые уровни. Для чисто структурных изменений (рефакторинг, editor tools, документация) этот цикл не нужен.

## Выбор целевого шага из плана

1. Определить в текущем плане (`docs/Planning/current/`) следующий невыполненный шаг.
2. Сформулировать цель текущей итерации в 1-2 предложениях.
3. Не переключаться на следующий шаг, пока текущий не закрыт.
4. Если шаг неясен — задать уточняющие вопросы.

## Жёсткие правила

- Сначала понять проблему, потом менять код.
- Не делать больше 2 слепых попыток фикса без нового визуального фидбэка или логов.
- После каждого автопрогона ждать визуальный отчёт пользователя.
- Только после визуального отчёта читать диагностику и делать выводы.
- Не использовать хрупкие хаки под один тип препятствия вместо общей механики.
- Не ломать архитектурные ограничения этапа.

## Тестовая инфраструктура

Подробности по инструментам, форматам и командам — в `docs/rules/agent_tools.md`.

Ключевые правила:
- Прогонять **все** тестовые уровни из таблицы в `workflow.md` (секция «Тестовые уровни бота»). Между паттернами — `relief`.
- Перед запуском рекомендуется `recompile_scripts`, если менялись .cs файлы.
- Логирование — `EditorLogs/diagnostic_log.txt` с тегами каналов: `[CH=STAB]`, `[CH=BOT]`, `[CH=ECO]`.
- Для чтения логов — `read_log_channel.ps1` (см. `agent_tools.md`).

## Цикл

1. Сформулировать гипотезу причины бага.
2. Сделать минимальную правку.
3. Проверить компиляцию.
4. Пересобрать `test_level.json` из актуальных паттернов, если менялись.
5. Запустить автопрогон.
6. Остановиться и запросить визуальный фидбэк.
7. После фидбэка прочитать логи:
   - `./read_log_channel.ps1 -Channel STAB -Tail 120`
   - `./read_log_channel.ps1 -Channel BOT -Tail 200`
   - `./read_log_channel.ps1 -Channel ECO -Tail 200`
8. Сопоставить визуал и логи, оценить экономику:
   - **Безопасность** — 100% (любое столкновение = баг).
   - **Энергия** — % оптимальности расхода.
   - **Ресурсы** — % собранных монет/кристаллов.
9. Повторить до стабильного результата или явного блокера.

## Стабильный результат

- Нет регрессий.
- Проблемный кейс воспроизводимо исправлен.
- Логи и визуал не противоречат друг другу.
- Изменения в рамках архитектурных ограничений этапа.
- Экономика не деградировала.

## Формат отчёта итерации

- Что изменено.
- Почему это должно помочь.
- Что показал автопрогон.
- Что подтвердил/не подтвердил визуальный фидбэк.
- Что видно в логах (STAB / BOT / ECO).
- Экономика: безопасность / энергия / ресурсы.
- Следующий шаг.

## При неясности

- 2-3 конкретных уточняющих вопроса до правок.
- Незнакомый API — проверить документацию.
- Визуальная проблема — попросить скриншот.
