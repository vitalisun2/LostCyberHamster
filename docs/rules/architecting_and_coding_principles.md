# Architecting and Coding Principles

## Принципы

- Если метод уже сделал guard-проверку перед вызовом нижележащего метода, не дублировать ту же самую проверку в вызываемом методе без явной причины. Инвариант должен жить на одном уровне ответственности, иначе код начинает расходиться, шуметь и маскировать реальную точку принятия решения.
- Чем меньше кода в методе, тем лучше. Логику метода нужно регулярно разбирать по частям и проверять каждую часть на избыточность: повтор, лишнюю ветку, промежуточное действие без собственной ценности или блок, который можно безопасно вынести либо удалить.
- Значимые развилки поведения должны быть выражены явно на том уровне, где принимается решение. Не прятать разные сценарии за неочевидными результатами внутренних вызовов: сначала показать основное ветвление, например `roof` и `ground`, и только потом выполнять детали соответствующей ветки.
