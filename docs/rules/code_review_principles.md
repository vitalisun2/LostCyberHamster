# Принципы code review

Короткие принципы self-review после доработки. Читать только для review/self-review задач.

## 1. Решение должно оставаться на правильном уровне

Проверять каждый новый фильтр, fallback, shortcut или "полезную оптимизацию": не переносит ли он решение из слоя с полным контекстом в слой с частичным контекстом.

Локальная польза не оправдывает код, который дублирует, обходит или подменяет ответственность другого слоя без доказанного invariant.

Хорошая архитектура это когда каждый элемент занимается своим делом. Важно не размазывать ответственность между слоями. Прежде чем добавлять логику надо проверять 
где более подходящее место для логики и не решает ли уже другой элемент архитектуры задачу этой логики.
