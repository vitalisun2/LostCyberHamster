# Разбор Android-плейтеста

Источник: `C:\Dropbox\exchange\crystal_wave\LostCyberHamster_Playtests\android`. На другом ноутбуке использовать его синхронизированную Dropbox-папку. Журнал появляется в development APK с `economyTelemetryEnabled: true`; версия баланса задаётся `balanceVersion` в `Assets/Resources/Diagnostics/device_log_settings.json`.

## Команда агента

Из корня репозитория, Python 3.10+ со стандартной библиотекой:

```powershell
python tools/economy/summarize.py C:/Dropbox/exchange/crystal_wave/LostCyberHamster_Playtests/android --output .temp/economy/summary.json
```

`available` перечисляет профили, версии баланса и группы. Обычная игра из тестового Android — `playtest`. Для конкретного профиля и дня по Москве:

```powershell
python tools/economy/summarize.py C:/Dropbox/exchange/crystal_wave/LostCyberHamster_Playtests/android --profile PROFILE_ID --from 2026-09-10T00:00:00+03:00 --to 2026-09-11T00:00:00+03:00 --balance 2026-09-10-economy-1 --output .temp/economy/summary.json
```

Интервал: начало включено, конец исключён. `--cohort editor|dev|all` предназначен для диагностики. Профили и версии баланса представлены отдельными группами. После DEV-выдачи профиль помечается `dev`; для обычного прогона использовать чистый профиль. Сессия — запуск процесса, возвраты из background дополнительно есть в `session_activity`.

## Как ответить пользователю

1. Прочитать `input_issues`, `quality`, свежесть последнего события и загрузки. Указать неполный/устаревший период. Отсутствие событий означает отсутствие данных.
2. Взять из `operations` начисления с причиной и ссылкой `file`/`line`/`event_id`. Снимки и рекламные события служат контролем; в суммы входят подтверждённые `economy_transaction`.
3. Сообщить 3–5 показателей: XP по источникам; активные минуты/попытки до повышения; доходы, расходы и остатки; возвраты/квесты/показы при достаточных данных.
4. Сверить с текущим кодом и [экономикой](../../docs/products/economics/README.md) только затронутые правила. Отделить нарушение начисления от нежелательного темпа. Одноразовые награды обучения и первых побед рассматривать отдельно от повторных уровней.
5. Предложить одну конкретную настройку с основанием. Целевой темп уточнить у пользователя, если он ещё не задан. После изменения баланса обновить `balanceVersion`, собрать APK и сравнить сопоставимые прогоны.

`xp_per_active_minute` включает начисления вне забега, но знаменатель — активное время забегов в выбранном периоде. Для прерванной попытки время является нижней оценкой: промежуточная запись раз в 15 секунд. `milestones` отсчитываются от начала выбранного периода. Локальные часы дают время событий; обратный ход отмечается. Один профиль показывает личную траекторию, общие D1/D7 и выручка требуют данных игроков/платформ.

ChatGPT/Work без доступа к папке получает `summary.json` вложением; нужные исходные JSONL прикладываются для детализации. `feature_configuration` сообщает флаги IAP/interstitial и режим рекламного SDK, а не подтверждение готовности магазина или фактической выручки.

## Контракт и хранение

- В приложении: `<persistentDataPath>/economy/economy_events.jsonl`, `*.packet.jsonl`, `state.json`.
- Схема событий: `EconomyEvent` в `Assets/Scripts/Diagnostics/EconomySnapshot.cs`. `profile_id` и `save_generation` равны устойчивому ID профиля; штатный сброс создаёт новый ID. Runtime `GameDataManager.Generation` для группировки между запусками не используется.
- Награды/покупки: снимки до/после сохранённой операции. `operation_id` содержит профиль, revision, причину и суффикс ambient для накопленной добычи. Источник квеста/weekly/return/rewarded/IAP уточняется в `detail` по сохранённым квитанциям. Purchase ID хешируется.
- Добыча: `pickup`, `obstacle_jump`, `obstacle_bonus`, суммирование между checkpoint. Валютные расходы и внешние выплаты проходят отдельно. `run_finished`/`run_progress` служат состоянием и временем; окончательный баланс сверять с подтверждёнными операциями.
- Пакет до 128 КиБ целых строк, очередь до 16 МиБ с резервом одного пакета. При переполнении растёт `lost_packets`; неполная история видна в отчёте. Слишком большая запись заменяется `data_gap`.
- Collector подтверждает SHA-256 пакета после записи JSONL и metadata в архив. Повтор одного пакета сохраняет один файл. Изменение endpoint оставляет старую очередь привязанной к прежнему адресу; восстановление адреса требуется для отправки.
- Архив автоматически сохраняется вне 72-часовой очистки диагностических логов. Его срок хранения управляется отдельно владельцем. Передача требует работающего receiver, сети и синхронизации Dropbox.
